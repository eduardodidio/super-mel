## Decisions Needed

### D1 — Gamepad deadzone threshold
**Options:**
- (A) Fixed 0.2 deadzone on all axes (standard for most games)
- (B) Configurable deadzone in Assist Mode settings
**Recommendation:** A — fixed 0.2 is industry standard; over-engineering configuration adds complexity for near-zero user benefit.

### D2 — Physics freeze strategy for pause
**Options:**
- (A) Set Rapier Physics `paused` prop on the `<Physics>` component (supported by @react-three/rapier)
- (B) Set `world.timestep = 0` via `useRapier()` — requires manual restore
- (C) Guard every `useFrame` callback with `if (paused) return`
**Recommendation:** A — the `<Physics paused={true}>` prop is the cleanest API; combined with guarding `useFrame` in Mel.tsx / ProjectileManager / etc. it freezes everything without touching internal Rapier state.

### D3 — Assist Mode persistence key
**Options:**
- (A) Single localStorage key `supermel_assist_mode` with JSON object
- (B) Multiple keys: `supermel_assist_invincible`, `supermel_assist_unlimited_fly`, etc.
**Recommendation:** A — single key is atomic (read/write one JSON blob), simpler to manage, easier to clear.

### D4 — Game speed implementation
**Options:**
- (A) Scale `delta` in every `useFrame` callback via a global multiplier
- (B) Scale the Rapier physics `timeStep` and let rendering follow naturally
- (C) Wrap `useFrame` in a custom hook `useGameFrame` that applies the speed multiplier
**Recommendation:** C — a custom `useGameFrame` hook centralizes the multiplier, is testable, and avoids touching Rapier internals. All gameplay `useFrame` calls become `useGameFrame`.

### D5 — Input type detection for HUD hint switching
**Options:**
- (A) Global zustand field `lastInputType: 'keyboard' | 'touch' | 'gamepad'` updated on every input event
- (B) Ref-based in useControls, exposed via a getter
**Recommendation:** A — zustand lets HUD react to changes without prop drilling; the update frequency is low (only on input type switch, not every frame).
