# Task F53-T02 -- AnimationStateMachine: Add double_jump State

**Feature:** F53
**Wave:** 0
**Type:** frontend (animation)
**Depends on:** None (can run in parallel with T01; both modify independent files)
**Status:** planned

## User Story

As a player, I want to see a distinct animation cue when Mel performs a double jump, so that I get clear visual feedback that my second jump was registered.

## Objective

Add `"double_jump"` to the `AnimState` union and `AnimInput` interface. Wire it into the state machine so that when `input.doubleJumping` is true and Mel is airborne, the animation transitions to `"double_jump"`. Map `"double_jump"` to the existing `"jump"` sprite animation (reuse frames). The `"fly"` state remains in the union but will never be entered because `AnimInput.flying` is now always `false` (set by T01).

### 3. Update `ANIM_NAME_MAP`

Map `"double_jump"` to the existing `"jump"` animation name:

const ANIM_NAME_MAP: Record<AnimState, string> = {
  // ... existing entries ...
  fly: "fly",
  double_jump: "jump",  // <-- NEW: reuses jump sprite frames
  // ... rest ...

### 4. Update the `update()` method -- Priority 4 (airborne states)

In the `// --- Priority 4: Jump states (airborne) ---` section, add a check for `doubleJumping` BEFORE the fly check:

```typescript
// --- Priority 4: Jump states (airborne) ---
if (!input.grounded) {
  // Double jump: show a brief rise animation
  if (input.doubleJumping && input.velY > 0) {
    this.transitionIfDifferent("double_jump");
    return this.state;
  }
  // If flying and airborne, stay in fly state (currently never true)
  if (input.flying) {
    this.transitionIfDifferent("fly");
    return this.state;
  }
  if (input.velY > 1) {
    this.transitionIfDifferent("jump_rise");
  } else if (input.velY < -1) {
    this.transitionIfDifferent("jump_fall");
  } else {
    this.transitionIfDifferent("jump_air");
  }
  return this.state;
}
```

The `double_jump` state is entered when `doubleJumping` is true (meaning the player has used their double jump and is still airborne) AND `velY > 0` (rising from the second jump). Once `velY` drops below 0, the normal `jump_fall` takes over. This gives a brief visual distinction during the upward arc of the double jump.

### 5. Update `isJumpState()` helper

Add `"double_jump"` to the jump state check:
```typescript
private isJumpState(): boolean {
  return (
    this.state === "jump_rise" ||
    this.state === "jump_air" ||
    this.state === "jump_fall" ||
    this.state === "double_jump"  // <-- NEW
  );
}
```

This ensures that landing from a double_jump state triggers the `jump_land` animation.

### Gotchas

- The `"fly"` state and its sprite mapping remain intact. Since `AnimInput.flying` is always `false` (set by T01), the `"fly"` state will never be entered. This preserves the ability to re-enable fly in a future feature.
- `"double_jump"` maps to `"jump"` in `ANIM_NAME_MAP`, meaning it reuses the same sprite frames as `jump_rise`. This is intentional -- no new sprites are needed. If custom double-jump sprites are added later, only `ANIM_NAME_MAP` needs to change.
- The `double_jump` state is NOT a one-shot (no entry in `ONE_SHOT_DURATIONS`). It's a continuous state driven by the `doubleJumping` and `velY` conditions, similar to `jump_rise`.
