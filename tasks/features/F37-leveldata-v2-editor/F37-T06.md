## User Story

As a developer, I want the test level and the chunk rendering pipeline to use the same `levelToSceneObjects` converter so that there is a single source of truth for interpreting level data, and user-created levels render identically to the test level.

## Objective

Update `ChunkRenderer.tsx` to accept converted scene data for editor preview and user-created levels. ## Dev Notes

### 1. Refactor `packages/frontend/src/game/systems/TestLevelData.ts`

The current `generateTestLevel()` returns `Chunk[]` (an array of 5 hand-crafted chunks). Two options:

**Option A (minimal change):** Keep `generateTestLevel()` as-is for now and add a new `generateTestLevelV2(): LevelDataV2` function that produces equivalent data in v2 format. This preserves the existing test level while proving the v2 pipeline.

**Option B (full migration):** Rewrite `generateTestLevel()` to return `LevelDataV2` and use `levelToSceneObjects` + `sceneObjectsToChunks` at the call site to convert.

**Recommendation: Option A** -- less risk, validates the pipeline without breaking the existing test level.

```typescript
import type { LevelDataV2, EntityData, BlockCell, BlockType } from "@super-mel/shared";

/**
 * Generate the test level as a LevelDataV2.
 * This is the v2-format equivalent of generateTestLevel().
 * Can be used with levelToSceneObjects() for unified rendering.
 */
export function generateTestLevelV2(): LevelDataV2 {
  const width = 80; // 5 chunks x 16 blocks
  const height = 20;

  // Build grid as 2D array
  const grid: BlockCell[][] = [];
  for (let y = 0; y < height; y++) {
    const row: BlockCell[] = [];
    for (let x = 0; x < width; x++) {
      row.push({ type: "empty" as BlockType, x, y });
    }
    grid.push(row);
  }

  // Helper to set a block in the grid
  const setBlock = (type: Exclude<BlockType, "empty">, x: number, y: number) => {
    // Map world Y to grid row (grid[0] = bottom row or top row depending on convention)
    // The grid is indexed as grid[row][col] where row = y offset from bottom
    // Adjust based on how the grid is interpreted -- use y directly as row index
    // with an offset to handle negative Y values
    const gridY = y + 5; // offset so y=-2 maps to row 3, y=0 maps to row 5
    const gridX = x;
    if (gridY >= 0 && gridY < height && gridX >= 0 && gridX < width) {
      grid[gridY][gridX] = { type, x, y };
    }
  };

  const entities: EntityData[] = [];

  // --- Spawn ---
  entities.push({ type: "spawn", x: 2, y: 1 });

  // --- Chunk 0 (x: 0-15): Spawn & Basics ---
  // Ground
  for (let x = 0; x <= 15; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  // Wood stack at x=1
  setBlock("wood", 1, 1);
  setBlock("wood", 1, 2);
  // Item block
  setBlock("item_block", 10, 3);
  // Coins
  entities.push({ type: "coin", x: 4, y: 2 });
  entities.push({ type: "coin", x: 6, y: 2 });
  entities.push({ type: "coin", x: 8, y: 2 });
  // Heart
  entities.push({ type: "heart", x: 12, y: 2 });

  // --- Chunk 1 (x: 16-31): Platforms & Gaps ---
  for (let x = 16; x <= 19; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  for (let x = 24; x <= 31; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  // Brick platform
  for (let x = 17; x <= 20; x++) setBlock("brick", x, 3);
  // Stone platform
  for (let x = 25; x <= 28; x++) setBlock("stone", x, 6);
  // Item blocks
  setBlock("item_block", 20, 6);
  setBlock("item_block", 22, 6);
  // Coins arc
  entities.push({ type: "coin", x: 19, y: 3 });
  entities.push({ type: "coin", x: 20, y: 4 });
  entities.push({ type: "coin", x: 21, y: 5 });
  entities.push({ type: "coin", x: 22, y: 4 });
  entities.push({ type: "coin", x: 23, y: 3 });
  // Heart on high platform
  entities.push({ type: "heart", x: 26, y: 7 });

  // --- Chunk 2 (x: 32-47): Destructibles & Combat ---
  for (let x = 32; x <= 47; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  // Wood wall
  setBlock("wood", 36, 1);
  setBlock("wood", 36, 2);
  setBlock("wood", 36, 3);
  // Glass wall
  setBlock("glass", 41, 1);
  setBlock("glass", 41, 2);
  // Iron wall
  setBlock("iron", 45, 1);
  setBlock("iron", 45, 2);
  setBlock("iron", 45, 3);
  // Coins behind wood
  entities.push({ type: "coin", x: 37, y: 1 });
  entities.push({ type: "coin", x: 37, y: 2 });
  entities.push({ type: "coin", x: 38, y: 1 });
  // Item block
  setBlock("item_block", 39, 4);

  // --- Chunk 3 (x: 48-63): Advanced Platforming ---
  for (let x = 48; x <= 49; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  for (let x = 53; x <= 56; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  for (let x = 61; x <= 63; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  // Stepping stones
  setBlock("stone", 51, 2);
  setBlock("stone", 53, 4);
  setBlock("stone", 59, 3);
  // Item blocks elevated
  setBlock("item_block", 54, 10);
  setBlock("item_block", 55, 10);
  setBlock("item_block", 56, 10);
  // High platform
  for (let x = 54; x <= 56; x++) setBlock("stone", x, 8);
  // Coins
  entities.push({ type: "coin", x: 50, y: 3 });
  entities.push({ type: "coin", x: 51, y: 4 });
  entities.push({ type: "coin", x: 52, y: 3 });
  entities.push({ type: "coin", x: 58, y: 4 });
  entities.push({ type: "coin", x: 59, y: 5 });
  entities.push({ type: "coin", x: 60, y: 4 });
  // Lava
  for (let x = 57; x <= 60; x++) setBlock("lava", x, -4);

  // --- Chunk 4 (x: 64-79): Victory Run ---
  for (let x = 64; x <= 79; x++) {
    setBlock("dirt", x, 0);
    setBlock("stone", x, -1);
    setBlock("stone", x, -2);
  }
  // 10 coins
  for (let x = 65; x <= 74; x++) {
    entities.push({ type: "coin", x, y: 2 });
  }
  // Hearts
  entities.push({ type: "heart", x: 68, y: 2 });
  entities.push({ type: "heart", x: 72, y: 2 });
  // Finish item blocks
  setBlock("item_block", 76, 1);
  setBlock("item_block", 76, 2);
  setBlock("item_block", 76, 3);
  // Goal
  entities.push({ type: "goal", x: 78, y: 1 });

  return {
    version: 2,
    grid,
    width,
    height,
    entities,
  };
}
```

**Note:** The grid offset logic (`y + 5`) is a simplification. The developer should verify the actual grid-to-world coordinate mapping by checking how the existing `generateTestLevel()` chunks map blocks to world coordinates. The key insight is that the v2 grid stores `BlockCell` objects with explicit `x, y` fields, so the grid array indices are less important than the cell's own coordinates.

A simpler approach may be to use a flat grid where `grid[row][col]` maps to `y=row, x=col` and then the `BlockCell.x/y` values match. The developer should choose the approach that aligns with how the editor stores blocks.

### 3. ChunkRenderer integration for user-created levels

When a user loads a saved level (from backend GET), the frontend receives `LevelDataV2`. The rendering path is:

```
Backend GET /levels/:id
  -> response.data (LevelDataV2, auto-migrated by T03)
  -> migrateLevelData(response.data)  // defensive, already v2
  -> levelToSceneObjects(levelData)
  -> sceneObjectsToChunks(sceneObjects)
  -> <ChunkRenderer testChunks={chunks} />
```

The developer should find the component that loads user levels (likely a "play level" or "test level" scene) and wire this pipeline. This may involve:

1. Fetching the level data from the API
2. Calling `migrateLevelData()` (defensive)
3. Calling `levelToSceneObjects()`
4. Calling `sceneObjectsToChunks()`
5. Passing chunks to `<ChunkRenderer testChunks={chunks} />`

If no "play user level" scene exists yet, the developer should at minimum wire it for the editor's TESTAR (test) button.

### 4. Editor preview integration

The editor's test mode already likely builds `Chunk[]` from the editor's block array. Update it to:

1. Build a `LevelDataV2` from the editor's current state (blocks + entities)
2. Call `levelToSceneObjects()` to get the scene
3. Call `sceneObjectsToChunks()` to get chunks for ChunkRenderer

This ensures the test play shows entities (coins, hearts) from the editor.

### 5. Background blocks

The current `TestLevelData.ts` places background decoration blocks at `z=-3`. The v2 grid is 2D (no z dimension for background layers). Background blocks are a rendering concern, not a LevelData concern.

**Decision:** For now, `generateTestLevelV2()` does NOT include background decorations. The existing `generateTestLevel()` continues to serve as the definitive test level with full background. The v2 pipeline will gain background support in a future feature (F20/F21 scope).

Alternatively, background blocks could be represented as entities with `props.z` and `props.isBackground`, but this adds complexity without clear benefit now.

### 6. Preserve existing `generateTestLevel()`

Do NOT modify or remove the existing `generateTestLevel()` function. It continues to work as before. The new `generateTestLevelV2()` is an additive function.
