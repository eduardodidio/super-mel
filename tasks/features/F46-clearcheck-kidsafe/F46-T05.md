# Task F46-T05 -- Level Select UI Overhaul (Stats, Sorting, Reactions, Report)

**Feature:** F46
**Wave:** 2
**Type:** frontend
**Depends on:** F46-T02 (stats + attempt endpoints), F46-T03 (reaction + report endpoints)
**Status:** planned

## User Story

As a player, I want to see how popular and difficult each community level is, react with fun stamps, and report inappropriate levels, so I can find great levels and help keep the community safe.

## Objective

Overhaul `LevelSelectScene3D.tsx` to display play/clear statistics, difficulty badges, stamp reactions, a report button, and sort tabs (Novas / Populares). Also add attempt tracking: POST an attempt when starting a level, and update it as cleared when the level is completed.

## Dev Notes

### 1. Updated `LevelEntry` interface

```typescript
interface LevelEntry {
  id: string;
  name: string;
  creatorName: string;
  background: string;
  createdAt: string;
  code: string | null;
  plays: number;
  clears: number;
  clearRate: number;
  difficulty: string | null; // "Facil" | "Normal" | "Dificil" | "Extremo" | null
}
```

### 2. Sort tabs

Add two tab buttons above the level list:

```
[NOVAS] [POPULARES]
```

- NOVAS: `GET /api/levels?sort=new` (default)
- POPULARES: `GET /api/levels?sort=popular`

Fetch levels when the selected sort changes.

### 3. Level card redesign

Each level card now shows:

```
+----------------------------------------------+
| [Nome da Fase]                    [Dificil]   |
| por CreatorName                               |
| 42 jogadas | 12 clears | forest              |
|                                               |
| [paw 3] [heart 5] [bone 1] [star 2]  [!]    |
|                                    [JOGAR]    |
+----------------------------------------------+
```

- **Difficulty badge:** Colored label:
  - Facil = green (#4a8a4a)
  - Normal = yellow (#ccaa00)
  - Dificil = orange (#cc6600)
  - Extremo = red (#cc2222)
  - null (< 5 plays) = gray, "Novo"
- **Stats line:** `{plays} jogadas | {clears} clears`
- **Stamp row:** Four small stamp buttons (paw, heart, bone, star) with counts. The player's current stamp is highlighted. Clicking a stamp toggles their reaction (POST/DELETE).
- **Report button:** Small `[!]` icon. On click, shows a dropdown with reasons (nome_inadequado, conteudo_ofensivo, impossivel, outro). On selection, POSTs the report and shows "Denuncia enviada".

### 4. Stamp interaction

When a player clicks a stamp:
- If it's the same stamp they already selected: DELETE the reaction (un-react)
- If it's a different stamp or no reaction yet: POST the reaction (react/change)
- Update the counts optimistically in the UI

Fetch reactions for visible levels in batch (or lazily on scroll). For simplicity in v1, fetch reactions for each level card when it renders using a `useEffect` with the level ID.

### 5. Attempt tracking

When the player clicks JOGAR:
1. POST `/api/levels/:id/attempt { playerId, cleared: false }`
2. Store the `attemptId` (or just the fact that an attempt was started)
3. After level completion (scene transitions to "levelclear"), POST an update or a new attempt with `{ cleared: true, time }`

The simplest approach: POST attempt with `cleared: false` on start, then POST a second attempt with `cleared: true` on completion. This means `plays` counts both. Alternatively, use a single POST on completion only, and increment plays on start via a separate endpoint.

Recommended: POST on start (increments plays). On clear, POST another call to `/:id/attempt { cleared: true, time }` which only increments clears (the route in T02 handles this).

Actually, simplify: POST attempt only ONCE per play session. Use `cleared: false` on start; if the player clears, PATCH or re-POST with `cleared: true`. For simplicity, since attempt tracking is not critical to get perfectly right in v1, POST on clear only is acceptable. Track plays via a simple `POST /:id/play` that increments plays without creating an attempt record (lean approach).

Final decision: follow the T02 spec -- POST `/:id/attempt` on level start (plays++). On clear, POST `/:id/attempt { cleared: true, time }` (clears++). This double-counts plays if the player clears. T02 should handle this correctly by incrementing plays on every POST.

### Gotchas

- The level list currently fetches once on mount. With sort tabs, it must re-fetch when the sort changes. Use the sort as a dependency in the `useEffect`.
- Stamp counts update optimistically but may need a full refetch to stay in sync. For v1, optimistic updates are fine.
- The report dropdown should be a simple overlay, not a full modal. Keep it lightweight.
- The `playerId` comes from `localStorage.getItem("supermel_player_id")`. It may be a `local-*` guest ID, which is fine for reactions and reports.
- Do not add JWT auth to these frontend calls -- keep consistent with existing patterns (playerId in body).
- The JOGAR button flow must remain functional: click -> fetch level data -> start playing. Add the attempt POST as a fire-and-forget side effect, not a blocker.
