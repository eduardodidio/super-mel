# Task F46-T01 -- Prisma Schema Migration (Level stats + Attempt + Reaction + Report)

**Feature:** F46
**Wave:** 0
**Type:** backend
**Depends on:** None (F42 must already be merged; no intra-feature dependency)

## User Story

As a developer, I need the database schema to support level statistics, attempt tracking, reactions, and reports so that all subsequent tasks can persist and query this data.

## Objective

Create a Prisma migration that adds fields to the `Level` model and creates three new models: `LevelAttempt`, `LevelReaction`, and `LevelReport`. All existing data must be preserved.

## Dev Notes

### 1. Update `Level` model in `packages/backend/prisma/schema.prisma`

Add after `updatedAt`:

```prisma
  code       String?   @unique @db.VarChar(6)
  plays      Int       @default(0)
  clears     Int       @default(0)
  bestTime   Int?      @map("best_time")
  cleared    Boolean   @default(false)
  approved   Boolean   @default(false)

  attempts  LevelAttempt[]
  reactions LevelReaction[]
  reports   LevelReport[]
```

The `code` is nullable because unpublished levels have no code. It gets populated on first publish. The `cleared` flag tracks whether the creator has beaten the level in test mode.

### 2. Create `LevelAttempt` model

```prisma
model LevelAttempt {
  id        String   @id @default(uuid()) @db.Uuid
  levelId   String   @map("level_id") @db.Uuid
  playerId  String   @map("player_id") @db.Uuid
  cleared   Boolean  @default(false)
  time      Int?
  createdAt DateTime @default(now()) @map("created_at")

  level  Level  @relation(fields: [levelId], references: [id], onDelete: Cascade)
  player Player @relation(fields: [playerId], references: [id])

  @@map("level_attempts")
}
```

### 3. Create `LevelReaction` model

```prisma
model LevelReaction {
  id        String   @id @default(uuid()) @db.Uuid
  levelId   String   @map("level_id") @db.Uuid
  playerId  String   @map("player_id") @db.Uuid
  stamp     String   @db.VarChar(10)
  createdAt DateTime @default(now()) @map("created_at")

  level  Level  @relation(fields: [levelId], references: [id], onDelete: Cascade)
  player Player @relation(fields: [playerId], references: [id])

  @@unique([levelId, playerId])
  @@map("level_reactions")
}
```

Stamps are constrained to: `"paw"`, `"heart"`, `"bone"`, `"star"`. Validation is done at the route layer, not the DB layer, to keep the migration simple.

### 4. Create `LevelReport` model

```prisma
model LevelReport {
  id        String   @id @default(uuid()) @db.Uuid
  levelId   String   @map("level_id") @db.Uuid
  playerId  String   @map("player_id") @db.Uuid
  reason    String   @db.VarChar(50)
  createdAt DateTime @default(now()) @map("created_at")

  level  Level  @relation(fields: [levelId], references: [id], onDelete: Cascade)
  player Player @relation(fields: [playerId], references: [id])

  @@unique([levelId, playerId])
  @@map("level_reports")
}
```

### 5. Update `Player` model

Add relation fields (no DB columns, just Prisma relation pointers):

```prisma
  attempts  LevelAttempt[]
  reactions LevelReaction[]
  reports   LevelReport[]
```

### 6. Run migration

```bash
cd packages/backend
npx prisma migrate dev --name add_level_stats_community
npx prisma generate
```

### Gotchas

- Existing levels will get `plays=0`, `clears=0`, `cleared=false`, `approved=false`, `code=null`, `bestTime=null` by default. This is correct -- they were published before clear check existed.
- The `code` column has a `@unique` constraint. Since all existing levels start with `code=null`, and PostgreSQL allows multiple NULLs in a unique column, no conflict arises.
- `onDelete: Cascade` on LevelAttempt/LevelReaction/LevelReport ensures that deleting a level removes its associated data.
- Do NOT change any existing columns or their defaults. This is purely additive.
- After migration, run `npx prisma generate` to update the Prisma Client types.
