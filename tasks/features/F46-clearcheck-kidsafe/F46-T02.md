# Task F46-T02 -- Clear Check Gate + Attempt Tracking + Code Generation (Backend Routes)

**Feature:** F46
**Wave:** 1
**Type:** backend
**Depends on:** F46-T01 (Prisma migration must exist)
**Status:** planned

## User Story

As a level creator, I want the system to prevent me from publishing a level I haven't beaten, assign my level a shareable code, and track when people play and clear it, so the community only has beatable levels with stats.

## Objective

Modify `routes/levels.ts` to add the clear check gate on publish, unique code generation, attempt tracking endpoints, and enhanced listing with stats and sorting.

## Dev Notes

### 1. Code generation utility

Create a utility function in `routes/levels.ts` (or a separate `utils/codeGen.ts`):

```typescript
const CODE_CHARS = "ABCDEFGHJKMNPQRSTUVWXYZ23456789"; // 30 chars, no 0/O/1/I/L

function generateCode(): string {
  let code = "";
  for (let i = 0; i < 6; i++) {
    code += CODE_CHARS[Math.floor(Math.random() * CODE_CHARS.length)];
  }
  return code;
}
```

When generating, attempt to create with the code. If unique constraint violation (P2002), retry with a new code (max 5 retries).

### 2. Modify `PUT /:id` -- Clear check gate

When `request.body.published === true`:
- Query the level to check `level.cleared === true`
- If not cleared, return `400 { error: "Voce precisa zerar a fase antes de publicar" }`
- If cleared and `level.code === null`, generate and assign a unique 6-char code
- Proceed with the update (set `published: true`)

When `request.body.cleared === true`:
- This is called by the editor after the creator reaches the goal in test mode
- Allow the update (set `cleared: true`)
- Do NOT auto-publish -- the creator must explicitly publish after clearing

### 3. Modify `GET /` -- Enhanced listing

Accept query parameters:
- `sort`: `"new"` (default, by `createdAt desc`) or `"popular"` (by `plays desc`)
- `familyMode`: `"true"` or `"false"` (default `"true"`)
- When `familyMode === "true"`, add `where: { approved: true }` to the filter (on top of `published: true`)

Return additional fields per level:
```typescript
{
  id, name, creatorName, background, createdAt,
  code,          // String | null
  plays,         // Int
  clears,        // Int
  clearRate,     // Number (clears / plays, or 0 if plays === 0)
  difficulty,    // "Facil" | "Normal" | "Dificil" | "Extremo" | null
}
```

Difficulty calculation (pure function, not stored):
```typescript
function getDifficulty(plays: number, clears: number): string | null {
  if (plays < 5) return null;
  if (clears === 0) return "Extremo";
  const rate = clears / plays;
  if (rate >= 0.5) return "Facil";
  if (rate >= 0.2) return "Normal";
  if (rate >= 0.05) return "Dificil";
  return "Extremo";
}
```

### 4. New route `GET /code/:code`

Look up a level by its 6-char code (case-insensitive: convert to uppercase before query).

```typescript
app.get<{ Params: { code: string } }>("/code/:code", async (request, reply) => {
  const code = request.params.code.toUpperCase();
  const level = await prisma.level.findUnique({ where: { code } });
  if (!level) return reply.status(404).send({ error: "Codigo nao encontrado" });
  // Return full level data (same as GET /:id, with migration)
  // ...
});
```

This endpoint does NOT check `approved` or Family Mode -- any level with a valid code is accessible. This is the "parent shared the code" trust model.

### 5. New route `POST /:id/attempt`

Record a play attempt:

```typescript
app.post<{
  Params: { id: string };
  Body: { playerId: string; cleared?: boolean; time?: number };
}>("/:id/attempt", async (request, reply) => {
  const { id } = request.params;
  const { playerId, cleared, time } = request.body;

  // Create attempt
  const attempt = await prisma.levelAttempt.create({
    data: { levelId: id, playerId, cleared: cleared ?? false, time },
  });

  // Update level stats
  await prisma.level.update({
    where: { id },
    data: {
      plays: { increment: 1 },
      ...(cleared ? {
        clears: { increment: 1 },
        ...(time && { bestTime: /* update if better */ }),
      } : {}),
    },
  });

  return attempt;
});
```

For `bestTime`: use a raw SQL update or a conditional update -- only set if current `bestTime` is null or the new `time` is lower:

```typescript
if (cleared && time) {
  const level = await prisma.level.findUnique({ where: { id }, select: { bestTime: true } });
  const newBest = level?.bestTime === null || time < level.bestTime;
  if (newBest) {
    await prisma.level.update({ where: { id }, data: { bestTime: time } });
  }
}
```

### Gotchas

- The `cleared` field on Level tracks if the CREATOR has cleared it. The `cleared` field on LevelAttempt tracks if a PLAYER cleared the attempt. Different semantics, same name. Use context to disambiguate.
- The code generation retry loop must have a hard limit (5 retries) to prevent infinite loops.
- When `familyMode` is `"true"`, the `approved` filter must be combined with `published: true` using AND (both required).
- Do not change the existing `POST /` (create level) or `DELETE /:id` routes. Only modify `GET /`, `PUT /:id`, and add new endpoints.
- Keep the existing data migration (`migrateLevelData`) and validation (`validateLevelDataV2`) calls intact in existing routes.
