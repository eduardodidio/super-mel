# Task F46-T06 -- Family Mode + Word Filter

**Feature:** F46
**Wave:** 3
**Type:** fullstack
**Depends on:** F46-T02 (familyMode query param), F46-T04 (editor name input), F46-T05 (level select)
**Status:** done

## User Story

As a parent, I want the game to default to a safe mode where my child only sees levels from approved creators, and I want level names to be filtered for bad words, so I can trust the game is safe.

## Objective

Implement Family Mode (default ON for guests) which filters the level listing to approved creators only, and add a client-side word filter for level names in the editor.

### 3. Code bypass for Family Mode

When a player enters a code in "Buscar por codigo" (T07), the code lookup endpoint (`GET /api/levels/code/:code`) does NOT check `approved`. This means:
- Family Mode ON: browsing shows only approved levels
- Entering a code: shows ANY level, regardless of approval status

This is the "parent shared the code" trust model described in the README.

### 4. Word filter for level names

Create a new utility file `packages/frontend/src/utils/wordFilter.ts`:

```typescript
const BLOCKED_WORDS: string[] = [
  // ~200 Portuguese profanities and slurs
  // Keep this list in a separate constant, not inline
  // Source: common Brazilian Portuguese filter lists
  "merda", "porra", "caralho", "foda", "puta",
  "bosta", "cuzao", "viado", "arrombado", "buceta",
  // ... (developer fills in a comprehensive list)
  // Also include common leetspeak substitutions:
  // "m3rda", "p0rra", etc.
];

/**
 * Check if a string contains any blocked words.
 * Case-insensitive, diacritic-insensitive.
 * Returns the first matched word or null.
 */
export function findBlockedWord(text: string): string | null {
  const normalized = text
    .toLowerCase()
    .normalize("NFD")
    .replace(/[\u0300-\u036f]/g, ""); // remove diacritics

  for (const word of BLOCKED_WORDS) {
    const normalizedWord = word
      .toLowerCase()
      .normalize("NFD")
      .replace(/[\u0300-\u036f]/g, "");

    if (normalized.includes(normalizedWord)) {
      return word;
    }
  }
  return null;
}

/**
 * Validate a level name.
 * Returns { valid: true } or { valid: false, reason: string }.
 */
export function validateLevelName(name: string): { valid: boolean; reason?: string } {
  if (!name.trim()) {
    return { valid: false, reason: "Nome nao pode ser vazio" };
  }
  if (name.length > 30) {
    return { valid: false, reason: "Nome muito longo (max 30 caracteres)" };
  }
  const blocked = findBlockedWord(name);
  if (blocked) {
    return { valid: false, reason: "Nome contem palavra inadequada" };
  }
  return { valid: true };
}
```

### Gotchas

- The word filter runs client-side only. A determined user could bypass it via API calls. For a kid game, client-side is sufficient as a first barrier. The report system (T03/T05) handles the rest.
- The blocked words list should be comprehensive but NOT overzealous. Common non-profane words that contain profane substrings (e.g., "assume" containing "ass" in English) should be handled. In Portuguese, this is less of an issue, but test with common names.
- Family Mode defaults to ON. This means new visitors see an empty level list until some levels are approved. This is intentional -- it's safer to show nothing than to show unmoderated content.
- The Family Mode toggle should be clearly labeled and NOT hidden. Parents should be able to find it easily, and kids should understand what it does.
- Do NOT add the word filter to the backend validation in `levelValidation.ts`. Keep it client-side in this feature. Backend validation can be added later as a guardrail.
