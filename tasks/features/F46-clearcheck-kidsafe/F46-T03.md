# Task F46-T03 -- Reactions + Reports Backend Routes

**Feature:** F46
**Wave:** 1
**Type:** backend
**Depends on:** F46-T01 (Prisma migration must exist)
**Status:** planned

## User Story

As a player, I want to react to community levels with fun stamps and report inappropriate levels so that the community stays positive and safe for kids.

## Objective

Add backend endpoints for stamp reactions (paw, heart, bone, star) and level reports. Reactions are upsert (one stamp per player per level, changeable). Reports are one-per-player-per-level.

## Dev Notes

### 1. Reaction routes in `routes/levels.ts`

#### `POST /:id/reaction`

Upsert a reaction: if the player already reacted to this level, update the stamp. If not, create a new reaction.

```typescript
app.post<{
  Params: { id: string };
  Body: { playerId: string; stamp: string };
}>("/:id/reaction", async (request, reply) => {
  const { id } = request.params;
  const { playerId, stamp } = request.body;

  // Validate stamp
  const VALID_STAMPS = ["paw", "heart", "bone", "star"];
  if (!VALID_STAMPS.includes(stamp)) {
    return reply.status(400).send({ error: "Carimbo invalido" });
  }

  // Upsert: one reaction per player per level
  const reaction = await prisma.levelReaction.upsert({
    where: {
      levelId_playerId: { levelId: id, playerId },
    },
    update: { stamp },
    create: { levelId: id, playerId, stamp },
  });

  return reaction;
});
```

#### `DELETE /:id/reaction`

Remove a player's reaction from a level:

```typescript
app.delete<{
  Params: { id: string };
  Body: { playerId: string };
}>("/:id/reaction", async (request, reply) => {
  const { id } = request.params;
  const { playerId } = request.body;

  try {
    await prisma.levelReaction.delete({
      where: {
        levelId_playerId: { levelId: id, playerId },
      },
    });
    return { ok: true };
  } catch {
    return { ok: true }; // Idempotent: no reaction to delete is fine
  }
});
```

#### `GET /:id/reactions`

Return aggregated reaction counts for a level, plus the current player's reaction (if any):

```typescript
app.get<{
  Params: { id: string };
  Querystring: { playerId?: string };
}>("/:id/reactions", async (request, reply) => {
  const { id } = request.params;
  const { playerId } = request.query;

  // Count per stamp
  const counts = await prisma.levelReaction.groupBy({
    by: ["stamp"],
    where: { levelId: id },
    _count: { stamp: true },
  });

  const stampCounts: Record<string, number> = {
    paw: 0, heart: 0, bone: 0, star: 0,
  };
  for (const c of counts) {
    stampCounts[c.stamp] = c._count.stamp;
  }

  // Current player's reaction
  let playerStamp: string | null = null;
  if (playerId) {
    const reaction = await prisma.levelReaction.findUnique({
      where: {
        levelId_playerId: { levelId: id, playerId },
      },
    });
    playerStamp = reaction?.stamp ?? null;
  }

  return { stamps: stampCounts, playerStamp };
});
```

### 2. Report route in `routes/levels.ts`

#### `POST /:id/report`

```typescript
app.post<{
  Params: { id: string };
  Body: { playerId: string; reason: string };
}>("/:id/report", async (request, reply) => {
  const { id } = request.params;
  const { playerId, reason } = request.body;

  // Validate reason
  const VALID_REASONS = [
    "nome_inadequado",
    "conteudo_ofensivo",
    "impossivel",
    "outro",
  ];
  if (!VALID_REASONS.includes(reason)) {
    return reply.status(400).send({ error: "Motivo invalido" });
  }

  try {
    await prisma.levelReport.create({
      data: { levelId: id, playerId, reason },
    });
    return { ok: true };
  } catch {
    // Unique constraint: player already reported this level
    return reply.status(409).send({ error: "Voce ja denunciou esta fase" });
  }
});
```

### Gotchas

- The `@@unique([levelId, playerId])` on LevelReaction and LevelReport provides the compound unique constraint. Prisma generates the accessor name `levelId_playerId` for it. If the field names in the schema use `@map`, the generated Prisma accessor might differ -- double-check with `npx prisma generate`.
- Reactions are upsert, not create-only. This lets the player change their stamp without deleting first.
- Reports are create-only (no update/delete by user). One report per player per level -- subsequent attempts return 409.
- Stamp validation is at the route layer. The DB stores it as a varchar, so any string would technically fit. The route must reject invalid stamps.
- Report reasons are a fixed enum: `nome_inadequado`, `conteudo_ofensivo`, `impossivel`, `outro`. This keeps it kid-safe (no freeform text from users).
- These endpoints do NOT require JWT auth -- they use `playerId` from the body (same pattern as existing `POST /api/scores`). This is consistent with the project's current auth model.

## Acceptance Criteria

- [ ] `POST /:id/reaction { playerId, stamp }` creates or updates a reaction
- [ ] Only stamps `paw`, `heart`, `bone`, `star` are accepted; others return 400
- [ ] One reaction per player per level (upsert semantics)
- [ ] `DELETE /:id/reaction { playerId }` removes the player's reaction (idempotent)
- [ ] `GET /:id/reactions?playerId=X` returns stamp counts + player's current stamp
- [ ] `POST /:id/report { playerId, reason }` creates a report
- [ ] Only reasons `nome_inadequado`, `conteudo_ofensivo`, `impossivel`, `outro` are accepted
- [ ] Duplicate reports from same player return 409
- [ ] All endpoints handle missing level/player gracefully (no 500s)
- [ ] TypeScript compiles with no errors
