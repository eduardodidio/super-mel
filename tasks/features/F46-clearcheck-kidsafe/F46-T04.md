# Task F46-T04 -- Editor Clear-Check UI + Publish Gate

**Feature:** F46
**Wave:** 2
**Type:** frontend
**Depends on:** F46-T02 (backend clear check + code generation routes)
**Status:** done

## User Story

As a level creator, I want the editor to guide me through the clear check process: I build my level, test it by reaching the goal, and only then can I publish it. After publishing, I see a shareable code to give to friends.

## Objective

Modify the editor UI (`EditorUI.tsx` and `EditorWrapper.tsx`) to implement the clear check flow: track whether the creator has cleared their level in test mode, gate the PUBLICAR button on that state, and display the level code after publishing.

### 2. Update `handleTest` flow

After the creator reaches the goal in test mode (detected when `useGameState.scene` transitions back from `"levelclear"` to editor), set `levelCleared = true`.

The flow is:
1. Creator clicks TESTAR -- `handleTest()` calls `startLevel(id, data)`
2. Creator plays and reaches the goal -- `scene` goes to `"levelclear"`
3. Creator clicks "Menu" or "Repetir" on LevelClearOverlay -- scene returns
4. When returning to editor, the wrapper detects the level was completed and sets `levelCleared = true`

Implementation: use a `useEffect` watching `scene`. When `scene` returns to `"editor"` and `gameMode` was `"level"` and `levelCompleting` was triggered, set `levelCleared = true`.

Alternative (simpler): After test mode, if the level was completed (scene went through "levelclear"), the wrapper intercepts the return and marks cleared. This can be detected by adding a callback or by checking a flag on `useGameState`.

Suggested approach: add a `levelTestCleared` ref that gets set to `true` when the LevelClearOverlay "Voltar ao Editor" action fires. The EditorWrapper listens for scene changes back to "editor" and reads this flag.

### 3. Update `handleSave` flow

Split into two separate flows:

**SALVAR (save draft):**
- Saves the level to backend without publishing (`published: false`)
- Stores the returned `level.id` in `savedLevelId`
- Available at any time (no clear check needed for saving a draft)

**PUBLICAR (publish):**
- Only enabled when `levelCleared === true` AND `savedLevelId` is not null
- Calls `PUT /api/levels/:id { published: true }`
- On success, receives the level `code` in the response
- Stores `code` in `levelCode` state
- Shows a modal/toast with the code

If the level hasn't been cleared yet, the PUBLICAR button is disabled with a tooltip: "Zere sua fase primeiro (TESTAR)"

### Gotchas

- The clear check state (`levelCleared`) is per-edit-session, not persisted. If the creator refreshes the page, they must clear the level again. This is intentional -- same as Mario Maker.
- The `savedLevelId` must be set before PUBLICAR can work, because publish is a `PUT` (update), not a `POST` (create). The creator must save first, then publish.
- When updating an existing saved level's data (editing after save), `levelCleared` should reset to `false` because the level data changed. Only clearing the CURRENT version of the level should enable publish.
- The EditorUI already has an `onSave` prop. Split it into `onSave` (draft) and `onPublish` (publish). Do NOT break the existing `onBack` or `onTest` callbacks.
- The level code display should be copiable (add a copy-to-clipboard button or select-on-click behavior).

## Test Scenarios

- **Happy path:** Build level with goal -> Save draft -> Test -> Reach goal -> Return to editor -> PUBLICAR enabled -> Publish -> See code
- **Block path:** Build level -> Try to publish without testing -> PUBLICAR disabled
- **Edit-after-clear:** Clear the level -> Edit a block -> PUBLICAR disabled again (must re-clear)
- **No goal:** Build level without goal entity -> Test uses infinite mode -> Cannot publish (PUBLICAR stays disabled)
