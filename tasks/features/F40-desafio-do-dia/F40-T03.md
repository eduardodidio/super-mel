# F40-T03 — Backend Routes: daily check, score with mode/seed, daily leaderboard

**Wave:** 1
**Type:** backend
**Depends on:** F40-T01 (Prisma migration for mode/seed fields)
**Status:** planned

## User Story

As a player, I want the server to check if I already played today's daily challenge and to show a daily leaderboard, so that the 1-attempt-per-day rule is enforced and I can see how I compare to others.

## Objective

Criar arquivo de rotas `daily.ts` com endpoints para verificar elegibilidade e leaderboard diario. Atualizar `scores.ts` para aceitar campos mode e seed no POST. Registrar novas rotas no server.ts.

### 1. Atualizar POST /api/scores (scores.ts)

- Arquivo: `packages/backend/src/routes/scores.ts`

  ```ts
  app.post<{ Body: { playerId: string; distance: number; levelId?: string; mode?: string; seed?: number } }>(
    "/",
    async (request) => {
      const { playerId, distance, levelId, mode, seed } = request.body;
      const score = await prisma.score.create({
        data: {
          playerId,
          distance,
          levelId: levelId || null,
          mode: mode || "infinite",
          seed: seed ?? null,
        },
      });
      return score;
    },
  );
  ```

### 2. Criar rotas diarias (daily.ts)

- Novo arquivo: `packages/backend/src/routes/daily.ts`
- Implementar funcao `dailySeed` identica ao frontend (mesma logica de hash):
  ```ts
  function dailySeed(dateStr: string): number {
    let hash = 0;
    for (let i = 0; i < dateStr.length; i++) {
      hash = (hash * 31 + dateStr.charCodeAt(i)) & 0x7fffffff;
    }
    return hash;
  }

  function todayDateStr(): string {
    const d = new Date();
    return `${d.getFullYear()}${String(d.getMonth() + 1).padStart(2, '0')}${String(d.getDate()).padStart(2, '0')}`;
  }
  ```

- **GET /api/daily/can-play?playerId=UUID**
  - Calcular seed do dia: `dailySeed(todayDateStr())`
  - Checar se existe Score com `mode="daily"` AND `seed=todaySeed` AND `playerId=X`
  - Retornar: `{ canPlay: boolean, todaySeed: number, todayDate: string }`
  - Se nao tem playerId, retornar canPlay=true (guest sem controle)

- **GET /api/daily/leaderboard?date=YYYY-MM-DD** (date opcional, default hoje)
  - Converter date param para dateStr YYYYMMDD
  - Calcular seed: `dailySeed(dateStr)`
  - Buscar scores: `mode="daily" AND seed=<calculatedSeed>`, orderBy distance desc, take 20
  - Include player.name
  - Retornar array de `{ id, playerName, distance, createdAt }`

- **GET /api/daily/my-result?playerId=UUID**
  - Calcular seed do dia
  - Buscar score do jogador para o desafio de hoje: `mode="daily" AND seed=todaySeed AND playerId=X`
  - Se existir, calcular ranking (count scores com distance > playerScore + 1)
  - Retornar: `{ played: boolean, distance?: number, rank?: number, totalPlayers?: number }`

## Test Scenarios

- **Happy path:** jogador checa can-play (true), joga, submete score, checa can-play (false), ve leaderboard com seu score
- **Edge case:** jogador sem playerId — can-play retorna true (sem enforcement para guests)
- **Edge case:** leaderboard com date param de ontem — retorna scores de ontem
- **Boundary:** leaderboard vazio (ninguem jogou) — retorna array vazio
- **Error:** banco offline — endpoints retornam fallback sem crash
