## User Story

As a player, I want to press Esc (or Start on gamepad) to open a pause menu so I can take a break, adjust volume, restart, or return to the main menu without losing my progress.

## Objective

Create the `PauseOverlay.tsx` component — a full-screen overlay with menu buttons, volume controls, and navigation to sub-screens (Como Jogar, Opcoes/Assist Mode). This task builds the UI only; wiring pause logic to freeze physics is T04.

### 2. AudioManager3D volume control

Add to `packages/frontend/src/game/systems/AudioManager3D.ts`:

```typescript
let volume = 0.4; // default

export function setVolume(v: number): void {
  volume = Math.max(0, Math.min(1, v));
  if (currentAudio) {
    currentAudio.volume = volume;
  }
}

export function getVolume(): number {
  return volume;
}
```

### 3. Volume slider wiring in PauseOverlay

```tsx
const [vol, setVol] = useState(() => Math.round(getVolume() * 100));
const [muted, setMuted] = useState(isMuted());

const handleVolumeChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  const v = parseInt(e.target.value, 10);
  setVol(v);
  setVolume(v / 100);
};

const handleMuteToggle = () => {
  setMuted(toggleMute());
};
```

### Design decisions

- **Callback props instead of zustand actions:** The overlay receives action callbacks from the parent (Game3D.tsx). This keeps the component pure and testable. Game3D already has `resetGame`, `setScene`, `setPaused`.
- **Sub-screen navigation via callbacks:** `onComoJogar` and `onOpcoes` will be wired to show/hide sub-screen components. The parent (Game3D or PauseOverlay itself) manages which sub-screen is visible.
- **Volume state local:** Volume slider state is local to the overlay. The AudioManager3D module holds the truth.
