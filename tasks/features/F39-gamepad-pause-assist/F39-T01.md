# Task F39-T01 — Gamepad polling + hot-plug in useControls

**Feature:** F39
**Wave:** 0
**Type:** frontend (hook)
**Depends on:** (none)
**Status:** planned

## User Story

As a player with a gamepad controller, I want the game to recognize my controller inputs so that I can play Super Mel with a gamepad instead of a keyboard.

## Objective

Extend `useControls.ts` to poll the Gamepad API every frame and merge gamepad inputs with keyboard inputs. Add hot-plug detection via browser events. Track `lastInputType` and `gamepadConnected` in zustand.

**B) Polling function** (called from a `requestAnimationFrame` loop or integrated into a returned poll function):

Since `useControls` currently returns a `ref` and does not use `useFrame` (it is called outside the R3F Canvas), we need a `pollGamepad()` function that can be called from within `useFrame` in game components.

Add a new export: `pollGamepad(controlsRef)` function:

```typescript
const DEADZONE = 0.2;

export function pollGamepad(controls: Controls): void {
  const gamepads = navigator.getGamepads();
  const gp = gamepads[0]; // Use first connected gamepad
  if (!gp) return;

  // Left stick or D-pad
  const axisX = gp.axes[0] ?? 0;
  const axisY = gp.axes[1] ?? 0;

  // D-pad buttons (standard mapping): up=12, down=13, left=14, right=15
  const dpadUp = gp.buttons[12]?.pressed ?? false;
  const dpadDown = gp.buttons[13]?.pressed ?? false;
  const dpadLeft = gp.buttons[14]?.pressed ?? false;
  const dpadRight = gp.buttons[15]?.pressed ?? false;

  // Merge: gamepad overrides only if gamepad has input
  const gpLeft = axisX < -DEADZONE || dpadLeft;
  const gpRight = axisX > DEADZONE || dpadRight;
  const gpUp = axisY < -DEADZONE || dpadUp;
  const gpDown = axisY > DEADZONE || dpadDown;

  // A/Cross = button 0 = jump
  const gpJump = gp.buttons[0]?.pressed ?? false;
  // X/Square = button 2 = shoot
  const gpShoot = gp.buttons[2]?.pressed ?? false;

  // OR-merge with keyboard (keyboard sets via events, gamepad sets here)
  // Gamepad state is additive — if keyboard key is held, it stays true
  if (gpLeft) controls.left = true;
  if (gpRight) controls.right = true;
  if (gpUp) controls.up = true;
  if (gpDown) controls.down = true;
  if (gpJump) controls.jump = true;
  if (gpShoot) controls.shoot = true;

  // When gamepad has NO input on an axis, we must NOT override keyboard
  // The keyboard events handle their own false-setting via keyup
  // So gamepad only needs to set to false if it was the one that set it to true
  // Strategy: track "gamepad was active" for each axis to know when to clear

  // Simplified approach: gamepad polling clears its own bits when not pressed
  // This is safe because keyboard keyup also clears the same bits
  if (!gpLeft && !controls.left) controls.left = false; // no-op, but explicit
  if (!gpRight && !controls.right) controls.right = false;
  if (!gpJump && !controls.jump) controls.jump = false;
  if (!gpShoot && !controls.shoot) controls.shoot = false;

  // Track last input type
  const hasGamepadInput = gpLeft || gpRight || gpUp || gpDown || gpJump || gpShoot;
  if (hasGamepadInput) {
    const state = useGameState.getState();
    if (state.lastInputType !== 'gamepad') {
      state.setLastInputType('gamepad');
    }
  }
}
```

**IMPORTANT design note:** The keyboard keydown/keyup events already handle setting `controls.current.left = false` etc. when keys are released. The gamepad polling only needs to set bits ON when pressed. The tricky part is ensuring gamepad release clears the bit even if no keyboard is active. Solution: after gamepad polling, explicitly set bits to false for gamepad-specific axes when gamepad is NOT pressing them, but ONLY if keyboard is also not pressing them.

Better approach — use a secondary ref for "gamepad state" and merge both:

```typescript
const kbControls = useRef<Controls>({ ... }); // keyboard state
const gpState = useRef<Controls>({ ... });     // gamepad state
const merged = useRef<Controls>({ ... });      // what callers read

// In pollGamepad: update gpState
// In merge: merged = kb OR gp for each field
```

This avoids the conflict. The `useControls` hook returns the `merged` ref. Callers read merged. Keyboard events write to `kbControls`. `pollGamepad` writes to `gpState`. A merge function combines them.


Expose this as a separate return or call `setPaused` from the polling function. Better: return a `startJustPressed` flag that the caller (Game3D or GameScene3D) can use to toggle pause. Use edge detection (track previous Start state in a ref).

### Gotchas

- `navigator.getGamepads()` returns a snapshot; must be called every frame
- Standard Mapping (`gp.mapping === 'standard'`) gives predictable button indices; non-standard gamepads may have different layouts — we only support standard mapping for now
- Gamepad API only works in secure contexts (HTTPS or localhost)
- The `gamepadconnected` event fires when a gamepad button is first pressed, not when physically plugged in (browser quirk)
