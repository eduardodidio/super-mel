# Task F39-T04 — Pause logic: freeze physics, freeze animations, wire Esc/Start

**Feature:** F39
**Wave:** 1
**Type:** frontend (integration)
**Depends on:** F39-T01 (gamepad Start button detection), F39-T03 (PauseOverlay component)
**Status:** planned

## User Story

As a player, I want the game to completely freeze when I pause — no physics, no animations, no movement — so that pausing is safe and fair.

## Objective

Wire the Esc key and gamepad Start button to toggle `paused` in zustand. Pass `paused` to the `<Physics>` component. Guard all `useFrame` callbacks. Mount the PauseOverlay when paused. Implement resume, restart, and menu navigation.

### 1. Physics freeze (Game3D.tsx)

The `<Physics>` component from `@react-three/rapier` accepts a `paused` prop:

```tsx
const paused = useGameState((s) => s.paused);

<Physics gravity={[0, -15, 0]} paused={paused}>
  <SceneContent />
</Physics>
```

This stops the Rapier physics simulation from stepping. Bodies freeze in place.

### 2. Esc key handler (Game3D.tsx)

Add a `useEffect` for Esc key:

```typescript
useEffect(() => {
  const handleKeyDown = (e: KeyboardEvent) => {
    if (e.code === 'Escape' && scene === 'playing') {
      e.preventDefault();
      const state = useGameState.getState();
      state.setPaused(!state.paused);
    }
  };
  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, [scene]);
```

### 3. Gamepad Start button (Game3D.tsx or GameScene3D.tsx)

The `pollGamepad` function from T01 exposes Start button state. Add edge detection:

```typescript
const prevStartRef = useRef(false);

// In a useFrame or useEffect polling loop:
const gamepads = navigator.getGamepads();
const gp = gamepads[0];
if (gp) {
  const startPressed = gp.buttons[9]?.pressed ?? false;
  if (startPressed && !prevStartRef.current && scene === 'playing') {
    const state = useGameState.getState();
    state.setPaused(!state.paused);
  }
  prevStartRef.current = startPressed;
}
```

Since Game3D.tsx is outside the Canvas (not in R3F), use a `requestAnimationFrame` loop or a `setInterval` for gamepad Start polling. Alternatively, create a small component inside the Canvas that uses `useFrame` to check Start.

Recommended: Add a `useEffect` with `requestAnimationFrame` loop in Game3D.tsx that only polls the Start button (lightweight, ~10 lines).

### 4. Guard useFrame callbacks

In every component that uses `useFrame` for gameplay logic, add a pause guard:

**Mel.tsx:**
```typescript
const paused = useGameState((s) => s.paused);

useFrame((_, delta) => {
  if (paused) return; // <-- ADD THIS
  // ... existing logic
});
```

Note: Read `paused` outside useFrame via zustand selector (not `getState()` inside useFrame) so the component re-renders when paused changes. But actually, since `useFrame` runs every RAF, we can use `useGameState.getState().paused` inside the callback to avoid re-renders:

```typescript
useFrame((_, delta) => {
  if (useGameState.getState().paused) return;
  // ...
});
```

This is more performant (no re-render on pause toggle for R3F components).

Apply the same guard to:
- `ProjectileManager.tsx` (useFrame for projectile movement)
- `CameraRig.tsx` (useFrame for camera follow — freeze camera too)
- `ChunkRenderer.tsx` (useFrame for chunk loading — can continue or freeze, prefer freeze for consistency)
- Any other component with gameplay useFrame

### 5. Mount PauseOverlay (Game3D.tsx)

```tsx
const paused = useGameState((s) => s.paused);
const setPaused = useGameState((s) => s.setPaused);

// State for sub-screens
const [pauseSubScreen, setPauseSubScreen] = useState<'main' | 'comojogar' | 'opcoes'>('main');

const handleResume = () => {
  setPaused(false);
  setPauseSubScreen('main');
};

const handleRestart = () => {
  setPaused(false);
  setPauseSubScreen('main');
  resetGame();
};

const handleMainMenu = () => {
  setPaused(false);
  setPauseSubScreen('main');
  setScene('menu');
};

// In JSX, after overlays:
{paused && scene === 'playing' && (
  <PauseOverlay
    onResume={handleResume}
    onRestart={handleRestart}
    onMainMenu={handleMainMenu}
    onComoJogar={() => setPauseSubScreen('comojogar')}
    onOpcoes={() => setPauseSubScreen('opcoes')}
  />
)}
```

### 6. Ensure pause resets on game over / menu transition

In `loseLife` (when lives reach 0 and scene goes to 'gameover'), ensure `paused` is set to false:

```typescript
loseLife: () => set((s) => {
  const lives = s.lives - 1;
  if (lives <= 0) {
    return { lives, scene: "gameover", testMode: false, paused: false };
  }
  return { lives };
}),
```

Also in `resetGame` and `startTestMode` (already have `paused: false`).

### Design decisions

- **`<Physics paused>` is the primary freeze mechanism.** It stops Rapier from stepping, which means RigidBodies freeze. Combined with guarding `useFrame`, nothing moves.
- **`useGameState.getState().paused` inside useFrame** avoids re-rendering R3F components on pause toggle. The components keep running RAF but exit immediately.
- **Sub-screen state lives in Game3D** (local React state) rather than zustand, since it is purely UI navigation within the pause overlay.
- **Start button polling via RAF loop** in Game3D.tsx (outside Canvas). This avoids creating a hidden R3F component just for one button check.
