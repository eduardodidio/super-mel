# F41-T03 -- Merge Logic: Guest localStorage para Backend na Criacao de Conta

**Wave:** 2
**Type:** backend + frontend
**Depends on:** F41-T02, F41-T04
**Status:** planned

## User Story

As a guest player who decides to create an account, I want my locally stored progress (coins, etc.) to be automatically saved to my new account so that I don't lose anything I've earned.

## Objective

Na criacao de conta (register), apos receber o token JWT, o frontend le o progresso do localStorage e envia para PUT /api/progress, migrando o progresso do guest para a conta permanente. O backend deve criar um Progress vazio automaticamente no /api/auth/register.

## Dev Notes

### Backend: auto-criar Progress no register

- Arquivo a modificar: `packages/backend/src/routes/auth.ts`
- Apos criar o Player no `/register`, criar tambem o Progress:
  ```typescript
  await prisma.progress.create({
    data: { playerId: player.id, totalCoins: 0, data: {} }
  });
  ```
- Wrap em try/catch para nao falhar o register se progress creation falhar

### Frontend: enviar localStorage apos register

- Arquivo a modificar: `packages/frontend/src/components/AuthScreen.tsx`
- Apos register bem-sucedido (token recebido), fazer:
  1. Ler `supermel_total_coins` do localStorage
  2. Se > 0, chamar PUT /api/progress com `{ totalCoins, data: {} }`
  3. Nao bloquear a UI -- fire-and-forget com catch silencioso

### Arquivos a modificar

- `packages/backend/src/routes/auth.ts`
- `packages/frontend/src/components/AuthScreen.tsx`

## Implementation Details

### auth.ts -- /register endpoint changes

Apos a linha `const player = await prisma.player.create(...)`:

```typescript
// Auto-create empty progress for new registered player
try {
  await prisma.progress.create({
    data: { playerId: player.id, totalCoins: 0, data: {} },
  });
} catch {
  // Non-critical: progress will be created on first GET /api/progress
}
```

### AuthScreen.tsx -- post-register merge

Dentro do `handleSubmit`, apos `localStorage.setItem("supermel_token", data.token)`:

```typescript
// Migrate guest localStorage progress to backend
if (mode === "register") {
  const localCoins = parseInt(localStorage.getItem("supermel_total_coins") || "0", 10);
  if (localCoins > 0) {
    fetch("/api/progress", {
      method: "PUT",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${data.token}`,
      },
      body: JSON.stringify({ totalCoins: localCoins, data: {} }),
    }).catch(() => {});
  }
}
```

### Fluxo completo

1. Guest joga, acumula 50 moedas no localStorage
2. Guest clica "Registrar", cria conta com nome/senha
3. Backend cria Player + Progress (totalCoins: 0)
4. Frontend recebe token, detecta mode === "register"
5. Frontend le localStorage totalCoins (50), chama PUT /api/progress { totalCoins: 50 }
6. Backend atualiza Progress.totalCoins para 50
7. Frontend navega para o jogo; useProgressSync carrega do backend (50 moedas)

## Acceptance Criteria

- [ ] /api/auth/register cria Progress vazio junto com o Player
- [ ] Apos register no frontend, localStorage totalCoins e enviado para PUT /api/progress
- [ ] Se localStorage totalCoins e 0, nenhuma chamada PUT e feita (otimizacao)
- [ ] Falha na migracao nao impede o fluxo de registro (silenciosa)
- [ ] Apos migracao, GET /api/progress retorna o totalCoins correto
- [ ] Fluxo de login (nao register) nao dispara merge -- apenas le o progresso existente

## Testing

Validacao manual:
1. Jogar como guest, coletar moedas
2. Ir para AuthScreen, clicar "Registrar"
3. Criar conta
4. Verificar no backend (curl GET /api/progress) que totalCoins reflete o localStorage

## Test Scenarios

- Happy path: guest com 50 moedas -> register -> backend tem 50 moedas
- Zero coins: guest sem moedas -> register -> no PUT call, backend tem 0
- Network error: PUT falha -> registro funciona, moedas ficam no localStorage
- Re-register (nome duplicado): 409 -> nenhum merge tentado
- Login (nao register): nenhum merge, apenas leitura do backend
