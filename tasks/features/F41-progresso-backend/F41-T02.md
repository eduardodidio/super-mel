## Implementation Details

### Auth preHandler

```typescript
import jwt from "jsonwebtoken";

const JWT_SECRET = process.env.JWT_SECRET || "super-mel-dev-secret";

// Inline preHandler for JWT auth
async function authPreHandler(request: FastifyRequest, reply: FastifyReply) {
  const auth = request.headers.authorization;
  if (!auth || !auth.startsWith("Bearer ")) {
    return reply.status(401).send({ error: "Token ausente" });
  }
  try {
    const payload = jwt.verify(auth.slice(7), JWT_SECRET) as { id: string };
    (request as any).playerId = payload.id;
  } catch {
    return reply.status(401).send({ error: "Token invalido" });
  }
}
```

### GET /api/progress

1. Extrair `playerId` do request (set by preHandler)
2. `prisma.progress.findUnique({ where: { playerId } })`
3. Se nao existir, criar com defaults: `prisma.progress.create({ data: { playerId, totalCoins: 0, data: {} } })`
4. Retornar `{ totalCoins, data, updatedAt }`

### PUT /api/progress

1. Extrair `playerId` do request
2. Body: `{ totalCoins?: number, data?: Record<string, unknown> }`
3. Ler progress atual: `prisma.progress.findUnique({ where: { playerId } })`
4. Se nao existir, criar com os valores recebidos
5. Se existir, deep-merge `data`:
   ```typescript
   const mergedData = { ...(existing.data as object), ...(body.data || {}) };
   // Para arrays dentro de data (levelsCleared, achievements), usar union:
   // Se body.data.levelsCleared existe, unir com existing
   ```
6. `prisma.progress.update({ where: { playerId }, data: { totalCoins: body.totalCoins ?? existing.totalCoins, data: mergedData } })`
7. Retornar progress atualizado

### Deep Merge Logic

```typescript
function mergeProgressData(
  existing: Record<string, unknown>,
  incoming: Record<string, unknown>
): Record<string, unknown> {
  const merged = { ...existing };
  for (const [key, value] of Object.entries(incoming)) {
    if (Array.isArray(value) && Array.isArray(existing[key])) {
      // Union for arrays (deduplicate)
      merged[key] = [...new Set([...(existing[key] as unknown[]), ...value])];
    } else if (value !== null && value !== undefined) {
      merged[key] = value;
    }
  }
  return merged;
}
```

## Acceptance Criteria

- [ ] GET /api/progress retorna progresso do jogador autenticado
- [ ] GET /api/progress sem token retorna 401
- [ ] GET /api/progress cria Progress vazio se nao existir (upsert)
- [ ] PUT /api/progress atualiza totalCoins
- [ ] PUT /api/progress faz deep merge no campo `data` (objetos: overwrite; arrays: union)
- [ ] PUT /api/progress sem token retorna 401
- [ ] PUT /api/progress com body parcial (so totalCoins, ou so data) funciona
- [ ] progressRoutes registrado em server.ts no prefix `/api/progress`
- [ ] Dev bypass users (id starts with "dev-" or "local-") devem ser tratados gracefully (skip DB, return empty progress ou in-memory)

## Test Scenarios

- Happy path: login -> GET (empty) -> PUT (coins + data) -> GET (updated)
- Partial update: PUT only totalCoins, data untouched
- Array merge: PUT levelsCleared ["a"] -> PUT levelsCleared ["b"] -> GET returns ["a","b"]
- No token: GET/PUT return 401
- Invalid token: GET/PUT return 401
- Dev bypass user (id "dev-rafa"): return empty progress without DB error
