# Task F54-T05 -- useGameState Cutscene Scene + Flow Changes

**Feature:** F54
**Wave:** 1
**Type:** frontend / state
**Depends on:** None (independent state changes, parallelizable with T04)
**Status:** planned

## User Story

As a developer, I want the game state to support a "cutscene" scene type so that the game can transition from gameplay to the cutscene and from the cutscene to the result screen seamlessly.

## Objective

Extend `useGameState` with cutscene-related state and modify the existing level completion flow so that reaching the goal transitions to the cutscene scene instead of directly to the result screen.

## Dev Notes

### 1. Extend GameScene Union Type

In `packages/frontend/src/game/hooks/useGameState.ts`, add `"cutscene"` to the `GameScene` type:

```typescript
export type GameScene = "menu" | "playing" | "gameover" | "editor" | "levelselect" | "leaderboard" | "levelclear" | "worldmap" | "cutscene";
```

### 2. Add Cutscene State Fields

Add to the `GameState` interface:

```typescript
// Cutscene fields
cutsceneType: "end_level" | null;  // which cutscene is active
cutsceneSkipped: boolean;           // whether the player skipped the cutscene
```

Add defaults in the initial state:

```typescript
cutsceneType: null,
cutsceneSkipped: false,
```

### 3. Add Cutscene Actions

Add to the `GameState` interface:

```typescript
startCutscene: (type: "end_level") => void;
endCutscene: () => void;
skipCutscene: () => void;
```

Implementations:

```typescript
startCutscene: (type) => set({
  scene: "cutscene",
  cutsceneType: type,
  cutsceneSkipped: false,
  levelCompleting: false,  // clear the completing flag since cutscene now handles it
}),

endCutscene: () => set({
  scene: "levelclear",
  cutsceneType: null,
}),

skipCutscene: () => set({
  scene: "levelclear",
  cutsceneType: null,
  cutsceneSkipped: true,
}),
```

### 4. Modify completeLevel Action

The existing `completeLevel` action currently does:
```typescript
completeLevel: () => set({ scene: "levelclear", levelCompleting: false }),
```

Change it to route through the cutscene instead:
```typescript
completeLevel: () => set({
  scene: "cutscene",
  cutsceneType: "end_level",
  cutsceneSkipped: false,
  levelCompleting: false,
}),
```

This means `completeLevel()` now triggers the cutscene, and the cutscene's completion triggers the `endCutscene()` action which transitions to `levelclear`.

### 5. Reset Cutscene State

Ensure `cutsceneType` and `cutsceneSkipped` are reset in `resetGame()`, `startLevel()`, `startCampaignLevel()`, `startTestMode()`, and `startDailyMode()`:

```typescript
cutsceneType: null,
cutsceneSkipped: false,
```

### 6. Modify handleGoalReached in GameScene3D

The existing `handleGoalReached` in `GameScene3D.tsx` does:
```typescript
setLevelCompleting(true);
// ... emit event ...
setTimeout(() => {
  completeLevel();  // now this will trigger cutscene
}, 1500);
```

**Keep the 1.5s delay** -- this still serves as the in-gameplay celebration moment (Mel reaches the owner, jump_on_owner sprite shows). After 1.5s, `completeLevel()` fires which now transitions to `scene: "cutscene"` instead of `scene: "levelclear"`.

No changes to `GameScene3D.tsx` in this task -- the existing `completeLevel()` call will automatically route to the cutscene because we changed the action's implementation.

### Relevant Files

- `packages/frontend/src/game/hooks/useGameState.ts` -- primary file to modify
- `packages/frontend/src/game/scenes/GameScene3D.tsx` -- reference only (no changes in this task; the existing `completeLevel()` call now routes to cutscene automatically)

### Gotchas

- The `GameScene` type is used in `HUD3D.tsx`, `Game3D.tsx`, `TouchControls3D.tsx`, and other places that check for specific scene values. The HUD should NOT show during cutscenes -- verify that `scene === "playing"` checks in HUD/controls still work correctly (they will, since "cutscene" is a separate value).
- The `cutsceneType` field allows future expansion (e.g., "world_intro", "boss_intro") without changing the flow.
- `endCutscene()` vs `skipCutscene()`: both go to `levelclear`, but `skipCutscene` sets the `cutsceneSkipped` flag. This flag is not used now but enables future analytics or achievements.
- Touch controls should NOT render during the cutscene scene. The existing check `scene === "playing"` in `TouchControls3D` handles this correctly.
