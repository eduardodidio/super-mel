# Task F54-T01 -- CutsceneEngine (Generic Timeline System)

**Feature:** F54
**Wave:** 0
**Type:** frontend / systems
**Depends on:** None (standalone utility)

## User Story

As a developer, I want a reusable timeline-based cutscene engine so that I can define scripted sequences of events with precise timing, callbacks, and skip support -- enabling the end-of-level ceremony and future cutscenes.

## Objective

Create a pure TypeScript class `CutsceneEngine` that drives a linear sequence of timed steps. Each step has a duration, optional callbacks (`onStart`, `onUpdate`, `onEnd`), and the engine tracks overall progress, supports skipping, and emits completion.

## Dev Notes

### 1. Create `packages/frontend/src/game/systems/CutsceneEngine.ts`

This is a **pure TypeScript class** with no React dependencies. It can be instantiated inside a React component and driven via `useFrame`.

### 2. Types

```typescript
export interface CutsceneStep {
  id: string;                              // unique identifier (e.g. "walk_to_bush")
  duration: number;                        // seconds
  onStart?: () => void;                    // called once when step begins
  onUpdate?: (progress: number, delta: number) => void;  // called each frame, progress = 0..1
  onEnd?: () => void;                      // called once when step ends
}

export type CutsceneStatus = "idle" | "playing" | "completed" | "skipped";

export interface CutsceneState {
  status: CutsceneStatus;
  currentStepIndex: number;
  currentStepId: string;
  stepProgress: number;      // 0..1 within current step
  totalProgress: number;     // 0..1 across entire cutscene
  totalDuration: number;     // sum of all step durations
  elapsed: number;           // total elapsed seconds
}
```

### 3. Class API

```typescript
export class CutsceneEngine {
  constructor(steps: CutsceneStep[]);

  /** Call once per frame with delta in seconds */
  update(delta: number): void;

  /** Start playback from the beginning */
  start(): void;

  /** Skip to the end -- calls all remaining onEnd callbacks */
  skip(): void;

  /** Get current state (readonly snapshot) */
  getState(): CutsceneState;

  /** Register a callback for when the entire cutscene completes */
  onComplete(callback: () => void): void;
}
```

### 4. Implementation Details

- `update(delta)`: advances `elapsed` by `delta`. If the current step's accumulated time exceeds its `duration`, call its `onEnd()`, advance `currentStepIndex`, call the next step's `onStart()`. Call current step's `onUpdate(progress, delta)` each frame.
- `skip()`: immediately calls `onEnd()` for the current step and all remaining steps (in order), sets status to `"skipped"`, fires the completion callback.
- `start()`: resets all state, sets status to `"playing"`, calls the first step's `onStart()`.
- When the last step's time is exceeded: call its `onEnd()`, set status to `"completed"`, fire the completion callback.
- Guard against double-starts and updates after completion.
- `totalProgress = elapsed / totalDuration` (clamped to 0..1).

### Gotchas

- Keep the engine **pure** -- no React, no THREE, no side effects. All visual changes happen in the callbacks provided by the consumer.
- `onUpdate` receives `progress` (0..1 normalized within the step) -- useful for lerping positions, opacity, etc.
- Be careful with floating-point accumulation -- use `>=` not `===` for step completion checks.
- The `skip()` method must call `onEnd` for every remaining step in order -- some steps use `onEnd` to set critical state.

## Test Scenarios

- **Happy path:** 3-step cutscene plays to completion, all callbacks fire in order
- **Skip mid-play:** skip() during step 2 of 5 -- steps 2-5 onEnd fire, completion fires
- **Skip before start:** skip() when idle -- all onEnd callbacks fire, status = skipped
- **Zero-duration step:** step with `duration: 0` should fire onStart + onEnd immediately
- **Update after completion:** no callbacks fire, no state changes
