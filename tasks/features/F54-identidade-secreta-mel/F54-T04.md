# Task F54-T04 -- Mel Nocape Sprites + Cape Visual Prop

**Feature:** F54
**Wave:** 1
**Type:** frontend / assets + systems
**Depends on:** None (independent of Wave 0 tasks, but parallelizable with T05)
**Status:** planned

## User Story

As a player, I want to see Mel without her cape after she hides it behind the bush, so that the "secret identity" reveal feels authentic -- she transitions from superhero to normal pet.

## Objective

Create the "Mel without cape" sprite variant and a cape visual prop (a colored plane) that can be shown/hidden during the cutscene. Also add cutscene-specific animation definitions to the SpriteAnimator.

## Dev Notes

### 1. Nocape Mel Sprite

The existing Mel sprites all show her with a cape (the flowing fabric behind her). For the cutscene, we need a variant without the cape.

**Approach -- Programmatic reuse, not new art:**

Since creating entirely new sprite art is not feasible without an artist, use the following approach:

- Create `packages/frontend/public/sprites/mel/mel_nocape.png` by using the existing `idle_right.png` as a base. The "cape" in the sprite is the colored fabric trailing behind Mel. For the cutscene, we will render Mel using existing sprites but with a visual cape overlay that gets removed.

- **Alternative (simpler and recommended):** Instead of creating new sprite PNGs, use the existing sprites and add a cape as a **separate THREE.Mesh** (a colored plane) attached to Mel's sprite position during the cutscene. When Mel walks behind the bush, the cape mesh is hidden. When Mel emerges, she uses the same existing sprites but the cape mesh is no longer attached. The visual difference is subtle but effective.

### 2. Cape Visual Prop

Create a cape as a simple THREE mesh that floats near Mel's sprite during the cutscene:

```typescript
// In the cutscene component:
function CapeOverlay({
  position,
  visible,
  facingRight
}: {
  position: [number, number, number];
  visible: boolean;
  facingRight: boolean;
}) {
  if (!visible) return null;
  return (
    <mesh position={position}>
      <planeGeometry args={[0.4, 0.8]} />
      <meshStandardMaterial
        color="#DC143C"
        side={THREE.DoubleSide}
        transparent
        opacity={0.9}
      />
    </mesh>
  );
}
```

The cape is:
- A red/crimson plane (`#DC143C`) attached behind Mel's sprite position
- Offset slightly in -X (behind her) and slightly in -Z
- Has a subtle flutter animation (small rotation oscillation on Z axis, 0.05 rad at 3Hz)
- During the cutscene: visible while Mel walks to the bush, hidden after she goes behind it

### 3. Add Cutscene Animation Definitions to SpriteAnimator

Add these new animation definitions to the `ANIMATIONS` record in `SpriteAnimator.ts`:

```typescript
// Cutscene-specific animations
walk_slow: {
  name: "walk_slow",
  frames: ["walk_right", "walk_right_b"],
  fps: 6,  // slower than normal walk (10fps) for a casual stroll
  loop: true,
},
peek: {
  name: "peek",
  frames: ["idle_right", "idle_left"],  // alternates looking left/right
  fps: 2,  // slow toggle for "looking around suspiciously"
  loop: true,
},
```

These reuse existing sprites but with different timing to convey the cutscene mood.

### 4. Sprite Manifest Update

No manifest.json changes needed -- the new animations reuse existing sprite names. The manifest already contains all referenced sprites.

### Gotchas

- The cape is NOT part of the sprite -- it is a separate THREE.Mesh positioned relative to Mel's sprite. This avoids needing new art assets.
- The "sneaky looking around" effect uses existing `idle_right` and `idle_left` sprites alternated at low fps.
- The `walk_slow` animation uses existing walk frames at lower fps -- this gives a casual, relaxed walk feel.
- Do NOT modify existing animation definitions -- only add new ones.
- The cape flutter animation should be gentle -- 0.05 radians max, not a dramatic flap.
