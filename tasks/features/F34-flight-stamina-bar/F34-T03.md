# Task F34-T03 — Wire fly state from Mel to zustand in GameScene3D

**Feature:** F34
**Wave:** 1
**Type:** frontend (scene)
**Depends on:** F34-T01, F34-T02
**Status:** planned

## User Story

As the game system, I need GameScene3D to receive Mel's fly state callback and pipe it into the zustand store so the HUD can reactively display the stamina bar.

## Objective

Create a `handleFlyStateUpdate` callback in GameScene3D that calls `setFlyState` from the zustand store, and pass it to the `<Mel>` component as the `onFlyStateUpdate` prop.

## Dev Notes

- File: `packages/frontend/src/game/scenes/GameScene3D.tsx`

### 1. Import setFlyState from zustand (near line ~33)

Add `setFlyState` to the existing `useGameState` selectors:

```typescript
const setFlyState = useGameState((s) => s.setFlyState);
```

### 2. Create the callback (after handleDamage, ~line 70)

```typescript
const handleFlyStateUpdate = useCallback((isFlying: boolean, timeRemaining: number) => {
  setFlyState(isFlying, timeRemaining);
}, [setFlyState]);
```

### 3. Pass to Mel component (line ~132)

Add the prop to the existing `<Mel>` JSX:

```tsx
<Mel
  controlsRef={controlsRef}
  onPositionUpdate={handlePositionUpdate}
  onCollisionDamage={handleDamage}
  invincible={invincibleRef.current}
  dead={lives <= 0}
  onLookUp={setIsLookingUp}
  onFlyStateUpdate={handleFlyStateUpdate}   // NEW
/>
```

### Design decisions

- **useCallback wrapping:** Same pattern as `handleDamage`, `handlePositionUpdate`, etc. Prevents Mel re-renders from callback identity changes.
- **Direct passthrough:** No filtering or debouncing here. The zustand `set()` call is cheap (shallow merge), and the HUD uses selectors that only re-render when values actually change.
- **No onAttackFrame concern:** Note that `onAttackFrame` is NOT currently passed to Mel in GameScene3D (it is wired through ProjectileManager). The new prop follows the existing callback pattern.

### Performance note

`setFlyState` is called every frame (~60/s). This is fine because:
1. Zustand's `set()` is a shallow merge, very cheap
2. HUD3D will use zustand selectors: `useGameState(s => s.isFlying)` and `useGameState(s => s.flyTimeRemaining)` only trigger re-renders when values change
3. During non-flying frames, `isFlying=false` and `flyTimeRemaining=5` are constant, so zustand will not trigger re-renders (referential equality on primitives)
