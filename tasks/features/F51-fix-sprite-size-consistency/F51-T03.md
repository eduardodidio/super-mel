# F51-T03 — Manifest: mapear sprites faltantes e validar ancoras

**Wave:** 0 (paralelo com T01)
**File:** `packages/frontend/public/sprites/mel/manifest.json`
**Depends on:** nenhum
**Status:** done

## User Story

Como desenvolvedor, quero que todos os sprites referenciados pelo
SpriteAnimator existam no manifest com dados corretos, para que o
sistema de escala normalizada funcione sem fallbacks silenciosos.

## Dev Notes

### Contexto

O `SpriteAnimator.ts` define animacoes que referenciam sprites que NAO
existem como arquivos PNG no diretorio `sprites/mel/`:

| Frame referenciado | Animacao que usa | Arquivo existe? |
|-------------------|-----------------|-----------------|
| `crouch`          | crouch, dig     | NAO             |
| `fly_1`           | fly             | NAO             |
| `fly_2`           | fly             | NAO             |
| `look_up`         | look_up         | NAO             |

Esses sprites fazem fallback silencioso para `idle_right`, o que:
1. Mostra a Mel parada em vez de numa pose apropriada
2. Causa inconsistencia no sistema de escala normalizada (T01)

### O que fazer

1. **Atualizar `manifest.json`** para adicionar entradas de sprites "alias"
   que mapeiam para arquivos existentes com dados de escala corretos:

   ```json
   "crouch": {
     "file": "sit.png",
     "group": "special",
     "sourceSize": [97, 115],
     "anchor": [52, 114],
     "note": "Alias: crouch uses sit pose until dedicated sprite is drawn"
   },
   "fly_1": {
     "file": "jump_air.png",
     "group": "jump",
     "direction": "right",
     "sourceSize": [139, 118],
     "anchor": [70, 117],
     "note": "Alias: fly_1 uses jump_air until dedicated sprite is drawn"
   },
   "fly_2": {
     "file": "jump_rise.png",
     "group": "jump",
     "direction": "right",
     "sourceSize": [134, 125],
     "anchor": [68, 124],
     "note": "Alias: fly_2 uses jump_rise until dedicated sprite is drawn"
   },
   "look_up": {
     "file": "idle_right.png",
     "group": "idle",
     "direction": "right",
     "sourceSize": [101, 138],
     "anchor": [51, 137],
     "note": "Alias: look_up uses idle_right until dedicated sprite is drawn"
   }
   ```

2. **Validar anchor consistency**: Para cada sprite, o anchor Y deve estar
   proximo de `sourceSize[1] - 1` (pe no fundo da imagem). Verificar que
   todos os sprites gameplay seguem essa convencao:

   ```
   Esperado: anchor[1] ~= sourceSize[1] - 1
   ```

   Revisar e corrigir qualquer sprite com anchor inconsistente.

3. **Criar symlinks ou copias para sprites alias** (OPCIONAL):
   Se o SpriteAnimator carrega pelo nome do arquivo (`fly_1.png`), criar
   symlinks ou copias dos PNGs:
   - `crouch.png` -> copia de `sit.png`
   - `fly_1.png` -> copia de `jump_air.png`
   - `fly_2.png` -> copia de `jump_rise.png`
   - `look_up.png` -> copia de `idle_right.png`

   NOTA: O SpriteAnimator carrega via `${SPRITE_BASE_PATH}${spriteName}.png`
   e o nome vem dos `frames[]` na definicao de animacao. Entao os arquivos
   DEVEM existir com o nome referenciado, ou a animacao em T01 deve ser
   atualizada para usar nomes de arquivos existentes.

   **Decisao recomendada**: Atualizar os frames em T01 para apontar para
   arquivos existentes (`sit`, `jump_air`, `jump_rise`, `idle_right`) E
   adicionar as entradas no manifest. Isso evita duplicacao de arquivos.
