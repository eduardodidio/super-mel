# F58-T05: LevelSceneConverter -- Extract Spring, MovingPlatform, Spikes

**Feature:** F58
**Wave:** 1
**Type:** frontend
**Depends on:** F58-T01
**Status:** planned

## User Story

As a level designer, I want the level data pipeline to correctly extract
spring, moving platform, and spikes entities from level data, so that they
are available for rendering in GameScene3D and the editor.

## Objective

Update `LevelSceneConverter.ts` to add new cases in the entity switch for
"spring", "moving_platform", and "spikes", and add corresponding typed
arrays to the `SceneObjects` interface.

## Dev Notes

### File to modify

`packages/frontend/src/game/systems/LevelSceneConverter.ts`

### 1. New data types in SceneObjects interface

Add 3 new arrays to the `SceneObjects` interface (after `signs`, before `otherEntities`):

```typescript
export interface SceneSpringData {
  x: number;
  y: number;
  bounceForce: number;
}

export interface SceneMovingPlatformData {
  x: number;
  y: number;
  direction: "horizontal" | "vertical";
  speed: number;
  range: number;
}

export interface SceneSpikesData {
  x: number;
  y: number;
  facing: "up" | "down" | "left" | "right";
}
```

Add to `SceneObjects`:

```typescript
export interface SceneObjects {
  // ... existing fields ...

  /** Springs extracted from entities */
  springs: SceneSpringData[];
  /** Moving platforms extracted from entities */
  movingPlatforms: SceneMovingPlatformData[];
  /** Spikes extracted from entities */
  spikes: SceneSpikesData[];

  // ... remaining fields (otherEntities, customBlockAssets, customAssets) ...
}
```

### 2. Initialize arrays in levelToSceneObjects

Add after `const signs` (line 64):

```typescript
const springs: SceneSpringData[] = [];
const movingPlatforms: SceneMovingPlatformData[] = [];
const spikes: SceneSpikesData[] = [];
```

### 3. Add cases to the entity switch

Add before the `default` case (line 144):

```typescript
case "spring":
  springs.push({
    x: entity.x,
    y: entity.y,
    bounceForce: (entity.props?.bounceForce as number) ?? 18,
  });
  break;

case "moving_platform":
  movingPlatforms.push({
    x: entity.x,
    y: entity.y,
    direction: (entity.props?.direction as "horizontal" | "vertical") ?? "horizontal",
    speed: (entity.props?.speed as number) ?? 3,
    range: (entity.props?.range as number) ?? 4,
  });
  break;

case "spikes":
  spikes.push({
    x: entity.x,
    y: entity.y,
    facing: (entity.props?.facing as "up" | "down" | "left" | "right") ?? "up",
  });
  break;
```

### 4. Include in return object

Add to the return statement (around line 152):

```typescript
return {
  // ... existing fields ...
  springs,
  movingPlatforms,
  spikes,
  // ... remaining fields ...
};
```

### Props default values

These match the brief:
- Spring `bounceForce` default: 18
- MovingPlatform `direction` default: "horizontal"
- MovingPlatform `speed` default: 3
- MovingPlatform `range` default: 4
- Spikes `facing` default: "up"

### Existing patterns to follow

- `case "enemy"` (lines 108-116): demonstrates props extraction with casting and default values
- `case "sign"` (lines 126-137): demonstrates conditional props handling
- Each case follows the pattern: extract from `entity.props`, cast to expected type, provide fallback default

### Gotchas

- The `sceneObjectsToChunks` helper (line 177) does NOT need changes -- it only converts blocks/hearts/coins/enemies which are passed to ChunkRenderer. The new elements will be rendered directly in GameScene3D.
- Ensure the new arrays are always initialized (empty `[]`) even if no entities of that type exist in the level data.
