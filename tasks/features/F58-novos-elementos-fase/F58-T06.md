# F58-T06: GameScene3D Integration -- Render Spring, MovingPlatform, Spikes

**Feature:** F58
**Wave:** 2
**Type:** frontend
**Depends on:** F58-T02, F58-T03, F58-T04, F58-T05
**Status:** planned

## User Story

As a player, I want springs, moving platforms, and spikes to appear and
function correctly when I play a level that contains them, so that I can
interact with these new elements during gameplay.

## Objective

Wire the 3 new entity components into GameScene3D so they are rendered from
level data and connected to the appropriate game callbacks (bounce for springs,
damage for spikes).

## Dev Notes

### File to modify

`packages/frontend/src/game/scenes/GameScene3D.tsx`

### 1. Imports

Add imports at the top of the file (after existing entity imports, around line 11):

```typescript
import { Spring } from "../entities/Spring";
import { MovingPlatform } from "../entities/MovingPlatform";
import { Spikes } from "../entities/Spikes";
```

### 2. Extract data from sceneObjects

After the existing entity extractions (around line 120, after `signEntities`):

```typescript
const springEntities = sceneObjects?.springs ?? [];
const movingPlatformEntities = sceneObjects?.movingPlatforms ?? [];
const spikesEntities = sceneObjects?.spikes ?? [];
```

### 3. Spring bounce handler

Add a callback near the other handlers (after `handleBoneCollected`, around line 385):

```typescript
const handleSpringBounce = useCallback((force: number) => {
  melRef.current?.springBounce(force);
  shake(0.06, 0.1);
}, [shake]);
```

This uses the `springBounce` method added to MelHandle in T02.

### 4. Render components in JSX

Add after the sign entities render block (around line 651, after the sign `.map`):

```tsx
{/* Spring entities from level data */}
{springEntities.map((s, i) => (
  <Spring
    key={`spring-${s.x}-${s.y}-${i}`}
    position={[s.x, s.y, 0]}
    bounceForce={s.bounceForce}
    onBounce={handleSpringBounce}
  />
))}

{/* Moving platform entities from level data */}
{movingPlatformEntities.map((mp, i) => (
  <MovingPlatform
    key={`platform-${mp.x}-${mp.y}-${i}`}
    position={[mp.x, mp.y, 0]}
    direction={mp.direction}
    speed={mp.speed}
    range={mp.range}
  />
))}

{/* Spikes entities from level data */}
{spikesEntities.map((sp, i) => (
  <Spikes
    key={`spikes-${sp.x}-${sp.y}-${i}`}
    position={[sp.x, sp.y, 0]}
    facing={sp.facing}
    onDamage={handleDamage}
  />
))}
```

### 5. Damage callback reuse

Spikes use the existing `handleDamage` callback (line 411-421) which already:
- Checks invincibility
- Calls `loseLife()`
- Triggers screen shake
- Sets invincibility timer (1500ms)
- Emits `damage_taken` event

No new damage handler needed.

### 6. Callback dependencies

- `handleSpringBounce` depends on `shake` (already in scope via `useScreenShake`)
- `handleDamage` already exists and handles all damage logic
- `melRef` already exists (line 171) for calling `springBounce`

### Existing patterns to follow

- Goal rendering (lines 612-618): `.map` over entities with `key` and position prop
- Checkpoint rendering (lines 621-632): same pattern with additional props
- Bone rendering (lines 635-641): same pattern with callback prop

### Gotchas

- These entities only render in level mode (when `sceneObjects` exists from `levelData`).
  Infinite mode uses chunk generation which does not include these entities yet (future work).
- The arrays default to `[]` when `sceneObjects` is null, so no conditional rendering needed.
- Do NOT render these inside ChunkRenderer -- they are standalone scene entities.
