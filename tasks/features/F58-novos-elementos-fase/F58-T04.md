# F58-T04: Spikes Entity (Espinhos)

**Feature:** F58
**Wave:** 1
**Type:** frontend
**Depends on:** F58-T01
**Status:** planned

## User Story

As a player, I want to see and avoid spike hazards placed on floors, ceilings,
and walls, so that levels have dangerous obstacles that require careful
navigation.

## Objective

Create the `Spikes.tsx` entity component: a fixed rigid body with a sensor
collider that deals 1 heart of damage on Mel contact. The spikes can face
up/down/left/right, rotating the mesh accordingly.

## Dev Notes

### Props interface

```typescript
interface SpikesProps {
  position: [number, number, number];

```

### Physics setup

Follow the `Heart.tsx` pattern (RigidBody fixed + sensor + onIntersectionEnter):

```typescript
<RigidBody
  type="fixed"
  position={position}
  colliders={false}
  sensor
  name="spikes"
>
  <CuboidCollider
    args={[0.4, 0.2, 0.3]}  // slightly smaller than visual
    position={[0, 0.1, 0]}   // shifted toward spike tips
  />
  {/* Visual mesh group, rotated based on facing */}
</RigidBody>
```

Note: The sensor is on the RigidBody level (like Heart.tsx), not on the
CuboidCollider. Use `onIntersectionEnter` on the RigidBody:

```typescript
<RigidBody
  type="fixed"
  position={position}
  colliders="cuboid"
  sensor
  name="spikes"
  onIntersectionEnter={(payload) => {
    if (payload.other.rigidBodyObject?.name === "mel") {
      onDamage();
    }
  }}
>
```

### Facing rotation

Rotate the entire visual group based on the `facing` prop:

```typescript
const FACING_ROTATION: Record<string, [number, number, number]> = {
  up:    [0, 0, 0],
  down:  [0, 0, Math.PI],        // 180 degrees on Z
  left:  [0, 0, Math.PI / 2],    // 90 degrees on Z
  right: [0, 0, -Math.PI / 2],   // -90 degrees on Z
};
```

Apply rotation to the visual `<group>` wrapping all meshes.

### Visual design

Triangular spike geometry on a flat base (voxel style):
- Base: 1 block wide (0.9 x 0.15 x 0.6), dark gray (#444444)
- Spikes: 4-5 elongated pyramids (or thin boxes tapering upward) arranged in a row
  - Each spike: narrow box (0.12 x 0.35 x 0.12), tilted slightly, or use ConeGeometry
  - Color: metallic dark silver (#666666) with slight red emissive (#330000) for danger feel
  - For voxel consistency, can use stacked thin boxes decreasing in size (no cones)
- Alternative voxel approach: 3-4 thin boxes stacked vertically, each smaller than the last
  - Bottom: 0.15 x 0.12 x 0.15
  - Middle: 0.10 x 0.12 x 0.10
  - Top: 0.05 x 0.12 x 0.05

### Damage behavior

- On Mel contact: call `onDamage()` callback immediately
- The `onDamage` callback will be wired to `handleDamage` in GameScene3D (T06),
  which already handles invincibility frames (INVINCIBILITY_MS = 1500)
- This means spikes follow the same damage model as lava: 1 heart, invincibility cooldown
- No knockback (same as lava). Mel just takes damage and gets invincibility frames.

## Test Scenarios

- **Happy path (up):** Mel walks into spikes from above -- takes 1 heart damage
- **Facing down (ceiling):** Spikes on ceiling, Mel jumps into them -- takes damage
- **Facing left/right (wall):** Spikes on wall, Mel walks into them -- takes damage
- **Invincibility:** After taking spike damage, Mel is invincible for 1.5s -- no second hit
- **Visual check:** Spikes visually point in the correct direction for each facing value
- **Adjacent blocks:** Spikes placed next to solid blocks render correctly without z-fighting
- **Edge case - pass through:** Mel with invincibility frames passes through spikes without additional damage
