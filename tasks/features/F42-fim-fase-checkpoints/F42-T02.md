# Task F42-T02 -- Checkpoint Entity Component (Checkpoint.tsx) + Activation Logic

**Feature:** F42
**Wave:** 0
**Type:** frontend
**Depends on:** F37 (EntityType "checkpoint" in LevelDataV2)
**Status:** planned

## User Story

As a player, I want to activate checkpoints throughout a level so that when I die, I respawn at the last one I touched instead of starting over.

## Objective

Create a Checkpoint entity component that renders a small doghouse (casinha) mesh in the 3D scene, detects collision with Mel, and reports activation to a callback. The checkpoint has two visual states: inactive (dim) and active (glowing).

## Dev Notes

### 1. Create `packages/frontend/src/game/entities/Checkpoint.tsx`

Props interface:
```typescript
interface CheckpointProps {
  position: [number, number, number];
  id: string; // unique identifier (e.g., "checkpoint-3-7" from grid coords)
  active: boolean; // controlled by parent -- is THIS the currently active checkpoint?
  onActivate: (id: string, x: number, y: number) => void;
}
```

The `active` prop is controlled by the parent scene (GameScene3D). When Mel touches a checkpoint, the parent updates which checkpoint is active. This allows only the LAST activated checkpoint to glow.

### 2. Visual: Doghouse (Casinha) Mesh

Build a simple voxel-style doghouse from box geometries:
- **Base/floor:** Box 1.2 x 0.1 x 1.0, color `#8B4513` (saddlebrown)
- **Walls:** 4 thin boxes forming a small house shape, 1.0 x 0.8 x 0.8, color `#A0522D` (sienna)
- **Roof:** 2 angled planes forming a triangular roof, color `#D2691E` (chocolate). Can approximate with a flattened box rotated 30deg on each side.
- **Door opening:** A small cutout in the front wall (or just leave the front wall shorter)
- Overall size: ~1.2 x 1.2 x 1.0 units (fits roughly in a 1-block space but slightly larger for visibility)

Alternative simpler approach: A single box with a "flag" on top (a thin vertical box + small plane as flag). The flag changes color on activation.

### 3. Activation Visual States

- **Inactive:** Dim colors, no emissive, no light. Flag (if using flag approach) is down or gray.
- **Active:** Warm glow -- add emissive to the main material (`emissive: "#FFD700"`, `emissiveIntensity: 0.3`). Add a small PointLight (color `#FFD700`, intensity 0.3, distance 3). Flag turns golden.

Transition: When `active` prop changes from false to true, can optionally do a brief scale-up pulse (1.0 -> 1.15 -> 1.0 over 0.3s) using useFrame.

### 4. Collision Detection

Same pattern as Coin.tsx:
- RigidBody type="fixed", sensor, name="checkpoint"
- `onIntersectionEnter`: if `payload.other.rigidBodyObject?.name === "mel"` and NOT already the active checkpoint, call `onActivate(id, position.x, position.y)`
- Unlike coins, checkpoints are NOT consumed -- they remain in the scene. Use the `active` prop (not a local ref) to track state. A checkpoint can be re-activated if Mel backtracks to a previous one (design choice: always use the LAST touched checkpoint).

### Relevant Files

- `packages/frontend/src/game/entities/Heart.tsx` -- pattern for RigidBody sensor entity
- `packages/frontend/src/game/entities/Coin.tsx` -- collision detection pattern
- `packages/frontend/src/game/entities/Block.tsx` -- box geometry reference for voxel style

### Gotchas

- Checkpoints are NOT single-use. They persist in the scene for the entire level.
- The `active` prop is boolean per checkpoint. The parent scene tracks which checkpoint ID is active and passes `active={activeCheckpointId === id}` to each Checkpoint.
- Position is in world-space grid coordinates (same as blocks).
- In infinite mode, checkpoints should not appear (they are only in LevelDataV2 entities for level mode).

## Acceptance Criteria

- [ ] Inactive state: dim appearance, no glow

- [ ] Collision with Mel triggers `onActivate(id, x, y)` callback
- [ ] Checkpoint is reusable -- touching it again after another checkpoint was activated re-activates it

- [ ] TypeScript compiles without errors

## Test Scenarios

- **Happy path:** Mel walks through checkpoint, it activates with glow
- **Sequential:** Mel activates checkpoint A, then B -- only B glows
- **Backtrack:** Mel activates B, walks back to A -- A glows, B dims
- **Edge case:** Mel jumps over checkpoint without touching sensor -- no activation
- **Boundary:** Checkpoint at ground level (y=1) renders correctly (not clipping into floor)
