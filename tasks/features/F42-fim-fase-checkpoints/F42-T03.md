# Task F42-T03 -- Level Mode Respawn System

**Feature:** F42
**Wave:** 1
**Type:** frontend
**Depends on:** F42-T02 (Checkpoint entity exists)
**Status:** planned

## User Story

As a player in level mode, I want to respawn at my last checkpoint when I die so that I can keep trying without seeing game over, while my death count increases for star rating.

## Objective

Modify `useGameState` to support a "level" game mode with checkpoint-based respawn, deaths counter, and no game-over screen. Modify `Mel.tsx` fall-death to respect the new mode.

## Dev Notes

**Modify `loseLife()`:**
```typescript
loseLife: () =>
  set((s) => {
    const lives = s.lives - 1;
    if (s.gameMode === "level") {
      // Level mode: respawn with full hearts, increment deaths
      // Actual teleport happens in Mel.tsx; here we just reset lives
      return { lives: 3, deaths: s.deaths + 1 };
    }
    // Infinite mode: game over at 0 lives
    if (lives <= 0) {
      return { lives, scene: "gameover", testMode: false };
    }
    return { lives };
  }),
```

**Modify `resetGame()`:**
Ensure it resets all new fields back to infinite-mode defaults:
```typescript
resetGame: () => set({
  score: 0, lives: 3, coins: 0, scene: "playing", paused: false,

  gameMode: "infinite", levelId: null, deaths: 0,
  lastCheckpoint: null, levelCompleting: false, levelStartTime: 0, levelCoins: 0,
}),
```

**Update `GameScene` type:**


### 2. Modify `packages/frontend/src/game/entities/Mel.tsx`

Locate the fall-death block (line ~264):
```typescript
if (pos.y < -15) {
  onCollisionDamage?.();
  rb.setTranslation({ x: pos.x, y: 8, z: 0 }, true);
  rb.setLinvel({ x: 0, y: 0, z: 0 }, true);
}
```

Change to respect checkpoints. Mel.tsx needs a new prop for respawn position:
```typescript
interface MelProps {
  // ...existing props...
  respawnPoint?: { x: number; y: number }; // from lastCheckpoint or spawnPoint
}
```

Updated fall-death:
```typescript
if (pos.y < -15) {
  onCollisionDamage?.();
  const rx = respawnPoint?.x ?? pos.x;
  const ry = respawnPoint?.y ?? 8;
  rb.setTranslation({ x: rx, y: ry + 2, z: 0 }, true);
  rb.setLinvel({ x: 0, y: 0, z: 0 }, true);
}
```

The +2 offset on y ensures Mel spawns slightly above the checkpoint, not inside a block.

### Gotchas

- `loseLife()` in level mode must NOT transition to "gameover". It resets lives to 3 and increments deaths.
- The actual teleport (setTranslation) happens in Mel.tsx's useFrame, not in the Zustand action.
- `onCollisionDamage` from GameScene3D calls `loseLife()` -- this path already funnels correctly.
- Lava damage also calls `onCollisionDamage` through the same path.
- The `levelCoins` field is separate from `coins` (session coins) and `totalCoins` (persistent). `levelCoins` tracks coins specifically for this level attempt (for star calculation). The `addCoin()` action should also increment `levelCoins` when in level mode.
- Update `addCoin()` to also increment `levelCoins`:
  ```typescript
  addCoin: () => set((s) => {
    const totalCoins = s.totalCoins + 1;
    try { localStorage.setItem("supermel_total_coins", String(totalCoins)); } catch {}
    return {
      coins: s.coins + 1,
      totalCoins,
      levelCoins: s.gameMode === "level" ? s.levelCoins + 1 : s.levelCoins,
    };
  }),
  ```

## Test Scenarios

- **Happy path (level mode):** Mel falls, respawns at checkpoint with 3 hearts, deaths incremented
- **Happy path (infinite mode):** Mel loses all lives, gameover screen appears (unchanged)
- **Edge case (no checkpoint):** Level mode, no checkpoint activated, Mel falls -- respawns at spawnPoint default
- **Edge case (lava):** Lava damage in level mode -- same loseLife path, lives reset to 3
- **Regression:** Infinite mode gameplay is completely unchanged
