# Task F42-T06 -- Level Mode Game Flow: Load Entities from LevelData v2, Place Goal + Checkpoints in Scene

**Feature:** F42
**Wave:** 2
**Type:** frontend
**Depends on:** F42-T01 (Goal), F42-T02 (Checkpoint), F42-T03 (useGameState level mode), F42-T05 (levelclear wiring)
**Status:** planned

## User Story

As a player starting a user-created level, I want Goal and Checkpoint entities to be loaded from the level data and placed in the 3D scene so that the level has a proper endpoint and respawn points.

## Objective

Wire the complete level-mode game flow: when a level is started (from level select or editor test), parse `LevelDataV2.entities`, instantiate Goal and Checkpoint components at their positions in GameScene3D, manage checkpoint activation state, and pass the goal collision handler. This is the integration task that ties T01-T05 together.

## Dev Notes

### 1. Level Start Entry Point

Currently, levels are started from:
- **Level Select** (`LevelSelectScene3D.tsx`): User picks a published level. Currently calls `startTestMode()` or `resetGame()`. Should call `startLevel(levelId)` from T03 instead.
- **Editor Test** (`EditorWrapper.tsx`): User clicks "TESTAR" in the editor. Currently calls `startTestMode()`. Should call `startLevel(tempLevelId)` with the editor's current data.

Modify both to call `useGameState.getState().startLevel(levelId)` and pass the level data to GameScene3D.

### 2. Passing Level Data to GameScene3D

Currently, GameScene3D accepts `testMode?: boolean` and loads `testChunks` from `generateTestLevel()`.

Extend to also accept level data:
```typescript
interface GameScene3DProps {
  testMode?: boolean;
  levelData?: LevelDataV2; // from F37
}
```

When `levelData` is provided (level mode), extract entities:
```typescript
const entities = levelData?.entities ?? [];
const goalEntities = entities.filter(e => e.type === "goal");
const checkpointEntities = entities.filter(e => e.type === "checkpoint");
const spawnEntity = entities.find(e => e.type === "spawn");
const spawnPoint = spawnEntity
  ? { x: spawnEntity.x, y: spawnEntity.y }
  : { x: 2, y: 5 }; // fallback
```

### 3. Render Goal and Checkpoint Components

Inside GameScene3D's JSX, render the entities:

```tsx
{/* Goal entities */}
{goalEntities.map((g, i) => (
  <Goal
    key={`goal-${i}`}
    position={[g.x, g.y, 0]}
    onGoalReached={handleGoalReached}
  />
))}

{/* Checkpoint entities */}
{checkpointEntities.map((cp, i) => {
  const cpId = `checkpoint-${cp.x}-${cp.y}`;
  return (
    <Checkpoint
      key={cpId}
      id={cpId}
      position={[cp.x, cp.y, 0]}
      active={activeCheckpointId === cpId}
      onActivate={handleCheckpointActivate}
    />
  );
})}
```

### 4. Checkpoint Activation Management

Track the active checkpoint in GameScene3D:

```typescript
const [activeCheckpointId, setActiveCheckpointId] = useState<string | null>(null);
const setLastCheckpoint = useGameState((s) => s.setLastCheckpoint);

const handleCheckpointActivate = useCallback((id: string, x: number, y: number) => {
  setActiveCheckpointId(id);
  setLastCheckpoint(x, y);
}, [setLastCheckpoint]);
```

### 5. Goal Position for Celebration Sprite

Store the goal position for the celebration sprite (from T05):
```typescript
const goalPositionRef = useRef<{ x: number; y: number } | null>(null);

// Set from the first goal entity
useEffect(() => {
  if (goalEntities.length > 0) {
    goalPositionRef.current = { x: goalEntities[0].x, y: goalEntities[0].y };
  }
}, [goalEntities]);
```

### 6. Respawn Point for Mel

Pass the computed respawn point to Mel:
```typescript
const lastCheckpoint = useGameState((s) => s.lastCheckpoint);
const respawnPoint = lastCheckpoint || spawnPoint;

<Mel
  controlsRef={levelCompleting ? frozenControlsRef : controlsRef}
  onPositionUpdate={handlePositionUpdate}
  onCollisionDamage={handleDamage}
  invincible={invincibleRef.current}
  dead={lives <= 0}
  onLookUp={setIsLookingUp}
  onFlyStateUpdate={handleFlyStateUpdate}
  respawnPoint={respawnPoint}
/>
```

### 7. Mel Initial Position

When levelData is provided, Mel should start at the spawn point instead of the hardcoded `position={[2, 5, 0]}`. This requires either:
- Making Mel's initial position a prop: `initialPosition?: [number, number, number]`
- Or setting the RigidBody position from the spawnPoint

Simplest: Add `initialPosition` prop to Mel (used only on mount):
```typescript
// In Mel.tsx RigidBody:
<RigidBody
  ref={rigidBodyRef}
  position={initialPosition ?? [2, 5, 0]}
  // ...
>
```

### 8. Level Data Flow from LevelSelect / Editor

**From LevelSelect:** When a level is selected, its `LevelDataV2` is already fetched. Store it in a shared location (e.g., a ref in Game3D, or in useGameState as `currentLevelData`).

Recommended: Add `currentLevelData: LevelDataV2 | null` to useGameState and set it in `startLevel()`:
```typescript
startLevel: (levelId, levelData) => set({
  gameMode: "level",
  levelId,
  currentLevelData: levelData ?? null,
  // ...rest of startLevel fields...
});
```

Then in Game3D:
```typescript
const currentLevelData = useGameState((s) => s.currentLevelData);

{scene === "playing" && (
  <GameScene3D
    testMode={testMode}
    levelData={currentLevelData ?? undefined}
  />
)}
```

**From Editor Test:** The editor already has the level data in memory. Call `startLevel(tempId, editorLevelData)`.

### 9. ChunkRenderer Integration

When `levelData` is provided, the blocks should come from `levelData.grid` via `levelToSceneObjects()` (from F37). The existing `testChunks` prop on ChunkRenderer already supports pre-built chunk data. The `levelToSceneObjects` converter from F37 should produce a compatible format.

If `levelToSceneObjects` returns blocks in a different format than `testChunks`, a small adapter may be needed. Check the F37 converter output format and adapt.

### Gotchas

- LevelDataV2 might not have a `goal` entity (user forgot to place one). Handle gracefully: the level plays but never triggers completion. Consider logging a warning: `console.warn("Level has no goal entity")`.
- Multiple goals: only the first one reached triggers completion (T05's `levelCompleting` guard handles this).
- Checkpoints in infinite mode: `checkpointEntities` will be empty (infinite mode uses ChunkGenerator, no EntityData). No rendering needed.
- The `testChunks` and `levelData` props on GameScene3D are mutually exclusive. `testMode` with `testChunks` is for the hardcoded test level; `levelData` is for user/editor levels.
- Ensure that when `REPETIR` is clicked (re-calling `startLevel`), the GameScene3D fully re-mounts (React key change) so entities reset. Use `levelId` as key: `<GameScene3D key={levelId} ... />`.
- The `currentLevelData` in useGameState should be typed as `LevelDataV2 | null` and cleared on `resetGame()` and `setScene("menu")`.

## Testing

- Manual: Open the editor, place some blocks + a goal entity + 2 checkpoints. Click TESTAR.
- Verify: Goal renders in the scene. Checkpoints render as doghouses.
- Walk Mel into checkpoint 1 -> verify it activates.
- Walk into checkpoint 2 -> verify it activates, checkpoint 1 deactivates.
- Die (fall off) -> verify Mel respawns at checkpoint 2.
- Reach the goal -> verify celebration -> verify result screen shows stats.
- Click REPETIR -> verify level restarts fresh (checkpoints inactive, deaths=0).
- Click MENU -> verify returns to menu.
- Start infinite mode (JOGAR) -> verify no goals/checkpoints, game over still works.

- [ ] Mel spawns at the spawn entity position (from LevelDataV2) when in level mode

- [ ] `currentLevelData` stored in useGameState and passed through Game3D -> GameScene3D
- [ ] Level select calls `startLevel(levelId, levelData)` to enter level mode
- [ ] Editor test calls `startLevel(tempId, editorLevelData)` to enter level mode

- [ ] Infinite mode (JOGAR) is unaffected -- no goals or checkpoints rendered
- [ ] TypeScript compiles without errors
