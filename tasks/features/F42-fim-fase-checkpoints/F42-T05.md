# Task F42-T05 -- New "levelclear" Scene + Wire Goal Collision to Result + Score Save

**Feature:** F42
**Wave:** 2
**Type:** frontend
**Depends on:** F42-T01 (Goal entity), F42-T03 (useGameState levelclear), F42-T04 (LevelClearOverlay)
**Status:** planned

## User Story

As a player, I want reaching the goal to trigger a celebration moment followed by the result screen so that the level completion feels satisfying and polished.

## Objective

Wire the goal collision event in GameScene3D through the level-completion flow: freeze gameplay, show the jump_on_owner celebration sprite, transition to the "levelclear" scene, and render the LevelClearOverlay in Game3D. Also handle audio transitions.

### 2. Goal Collision Flow in `packages/frontend/src/game/scenes/GameScene3D.tsx`

Add a `handleGoalReached` callback:

```typescript
const setLevelCompleting = useGameState((s) => s.setLevelCompleting);
const levelCompleting = useGameState((s) => s.levelCompleting);
const completeLevel = useGameState((s) => s.completeLevel);
const gameMode = useGameState((s) => s.gameMode);

const handleGoalReached = useCallback(() => {
  if (gameMode !== "level") return; // goals only work in level mode
  setLevelCompleting(true);
  // After 1.5s celebration delay, transition to result screen
  setTimeout(() => {
    completeLevel(); // sets scene to "levelclear"
  }, 1500);
}, [gameMode, setLevelCompleting, completeLevel]);
```

### 3. Celebration Sprite (jump_on_owner)

During the 1.5s `levelCompleting` phase, display the `jump_on_owner.png` sprite at the goal position:

Option A (simpler): Inside GameScene3D, when `levelCompleting` is true, render a billboard sprite:
```tsx
{levelCompleting && goalPosition && (

      depthTest={false}

```

Load the texture:
```typescript
const jumpOnOwnerTexture = useMemo(() => {
  const tex = new THREE.TextureLoader().load("/sprites/mel/jump_on_owner.png");
  tex.magFilter = THREE.NearestFilter;
  tex.minFilter = THREE.NearestFilter;
  tex.colorSpace = THREE.SRGBColorSpace;

```

Store the goal position when the goal entity is rendered (from T06's entity loading).

Option B (advanced): Trigger the `jump_on_owner` animation state on Mel's sprite state machine. This requires the AnimationStateMachine to support the "special" group. If the animation system supports it, prefer this approach. If not, use Option A.

### 4. Freeze Gameplay During Celebration

When `levelCompleting` is true:
- Mel should stop accepting input. Pass `levelCompleting` as a prop to Mel, or check it in the controls hook.
- Simplest approach: In GameScene3D, when `levelCompleting`, stop passing `controlsRef` to Mel (pass a dummy ref with all keys false), OR add a `frozen` prop to Mel that skips input processing.

```typescript
<Mel
  controlsRef={levelCompleting ? frozenControlsRef : controlsRef}
  // ... other props
/>
```

Where `frozenControlsRef` is a ref with all controls set to false:
```typescript
const frozenControlsRef = useRef({
  left: false, right: false, up: false, down: false,
  jump: false, attack: false, jumpHeld: false,
});
```

### Gotchas

- The celebration sprite (jump_on_owner) contains both Mel and the owner. During the 1.5s celebration, the actual Mel entity is still in the scene. Either: (A) hide the Mel entity while `levelCompleting` (set visible=false), or (B) position the celebration sprite to overlap the goal and let it visually replace both. Option B is simpler.
- The celebration delay (1.5s) uses setTimeout. If the component unmounts during the timeout (unlikely but possible if user force-navigates), the `completeLevel()` call on an unmounted component is harmless (Zustand actions work regardless of component lifecycle).
- In infinite mode, if a goal entity somehow appears (it shouldn't, but defensively), `handleGoalReached` returns early because `gameMode !== "level"`.
- Ensure the Physics simulation doesn't cause Mel to fall during the 1.5s freeze. Passing frozen controls prevents input but gravity still applies. Consider also zeroing Mel's velocity: `rb.setLinvel({ x: 0, y: 0, z: 0 }, true)` when goal is reached. This could be done via a new `onGoalFreeze` callback prop on Mel.

## Test Scenarios

- **Happy path:** Mel touches goal -> freeze -> celebration sprite -> result screen
- **Edge case:** Player was mid-jump when hitting goal -- Mel should freeze in place (velocity zeroed)
- **Edge case:** Two goals in one level (design error) -- first one triggers, second is ignored (levelCompleting guard)
- **Regression:** Infinite mode gameplay unaffected by goal-related code
- **Timeout safety:** If completeLevel runs after component unmount -- no crash (Zustand is external)
