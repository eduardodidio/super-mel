# Task F48-T05 -- Wire Biome System into GameScene3D + Game3D

**Feature:** F48
**Wave:** 2
**Type:** frontend
**Depends on:** F48-T01 (BiomeManager), F48-T04 (BiomeTransition component)
**Status:** done

## User Story

As a player, I want the biome changes to happen automatically as I progress through infinite mode, without needing to select a theme from the menu.

## Objective

Integrate the BiomeManager and BiomeTransition into the game scene rendering pipeline. In infinite mode, the theme is driven automatically by the player's chunk position. In level mode and test mode, the theme remains static (user-selected or level-specified). Update useGameState to track the current biome separately from the user-selected theme.

## Dev Notes

### 1. Modify `packages/frontend/src/game/hooks/useGameState.ts`

Add biome tracking fields:

```typescript
// Add to GameState interface:
currentBiome: BackgroundTheme;
setCurrentBiome: (biome: BackgroundTheme) => void;
```

Default `currentBiome` to `"forest"`. Reset to `"forest"` in `resetGame()`, `startTestMode()`, `startDailyMode()`, and `startLevel()`.

The `currentBiome` field reflects what the player is currently seeing. It is separate from `theme` (which is the user's menu selection and is used for level/test mode).

### 2. Modify `packages/frontend/src/game/scenes/GameScene3D.tsx`

Add biome tracking logic in infinite mode:

```typescript
import { getBiomeForChunk, CHUNK_WIDTH } from "../systems/BiomeManager";

// Inside GameScene3D component:
const biomeStateRef = useRef<BiomeState>(getBiomeForChunk(0));

// In the useFrame or via a callback from ChunkRenderer:
// Compute current chunk index from player position
useFrame(() => {
  if (gameMode === "level" || testMode) return;
  const playerX = playerPosRef.current?.x ?? 0;
  const chunkIndex = Math.floor(playerX / CHUNK_WIDTH);
  const newBiomeState = getBiomeForChunk(chunkIndex);
  biomeStateRef.current = newBiomeState;

  // Update the store's currentBiome when the primary biome changes
  if (newBiomeState.current !== useGameState.getState().currentBiome) {
    setCurrentBiome(newBiomeState.current);
  }
});
```

Export the biome state to the parent via a ref or callback so Game3D can use it for the visual system.

### 3. Modify `packages/frontend/src/game/Game3D.tsx`

In the `SceneContent` component, switch between static and dynamic theming:

```typescript
function SceneContent() {
  const scene = useGameState((s) => s.scene);
  const theme = useGameState((s) => s.theme); // user-selected theme
  const currentBiome = useGameState((s) => s.currentBiome); // auto-tracked biome
  const gameMode = useGameState((s) => s.gameMode);
  const testMode = useGameState((s) => s.testMode);

  // In infinite mode: use BiomeTransition (driven by biomeState from GameScene3D)
  // In level/test mode: use static Skybox + Lighting with user-selected theme
  const useStaticTheme = gameMode === "level" || testMode;
  const effectiveTheme = useStaticTheme ? theme : currentBiome;

  return (
    <>
      {useStaticTheme ? (
        <>
          <Skybox theme={effectiveTheme} />
          <Lighting theme={effectiveTheme} />
        </>
      ) : (
        /* BiomeTransition is rendered inside GameScene3D or here */
        /* passing biomeState which includes transition info */
      )}
      {scene === "menu" && <MenuScene3D />}
      {scene === "playing" && (
        <GameScene3D ... />
      )}
    </>
  );
}
```

**Architecture decision:** The BiomeTransition component should be rendered inside GameScene3D (not SceneContent) because GameScene3D has access to the player position ref needed to compute the current chunk index. GameScene3D renders BiomeTransition alongside the existing BackgroundDecor.

Remove the standalone `<Skybox>` and `<Lighting>` from `SceneContent` when in infinite playing mode. Instead, GameScene3D renders `<BiomeTransition>` internally.

For menu scene, continue using the static `<Skybox theme={theme} /> <Lighting theme={theme} />`.

### 4. Menu "TEMA" button behavior

In infinite mode, the TEMA button should be hidden or disabled since the theme cycles automatically. Options:

- **Option A (preferred):** Hide the TEMA button entirely when `gameMode === "infinite"`. The button is only visible on the menu, and it controls the menu background theme. When the player starts infinite mode, the biome system takes over.
- **Option B:** Keep the button but show "BIOMAS: AUTO" as the label in infinite mode.

Since the menu is only visible when `scene === "menu"` and the biome system only runs when `scene === "playing"`, the TEMA button on the menu can continue to control the menu's visual theme without conflicting with the biome system.

### 5. Daily challenge integration

Daily challenge is a variant of infinite mode (`dailyMode === true`). It should use the same biome system. The biome is deterministic because it is based on `chunkIndex`, not on any random seed.

### Gotchas

- **Render order.** BiomeTransition must be rendered BEFORE the block meshes (ChunkRenderer) so that the skybox and lighting are set up before objects are drawn. In R3F, render order within `<>...</>` is generally first-to-last, but skybox is a scene-level effect that applies globally.
- **Menu theme is separate.** The menu still uses `useGameState.theme` for its background. Do not change the menu to use `currentBiome`. The biome system only applies during `scene === "playing"` in infinite mode.
- **Level mode themes.** In level mode, the theme can come from `LevelDataV2.theme` (if set) or fall back to the user-selected `theme`. This is the existing behavior -- do not change it.
- **Re-renders.** `setCurrentBiome` triggers a Zustand update. Only call it when the biome actually changes (compare before setting) to avoid unnecessary re-renders.
- **The SceneContent/GameScene3D split.** Currently, Skybox and Lighting are in SceneContent (Game3D.tsx), outside GameScene3D. For infinite mode, they need to move inside GameScene3D (or be conditionally rendered). Handle the conditional carefully so that level mode and menu still render Skybox+Lighting.
