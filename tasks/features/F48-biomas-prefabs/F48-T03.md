# Task F48-T03 -- ChunkGenerator Biome-Aware Generation

**Feature:** F48
**Wave:** 1
**Type:** frontend
**Depends on:** F48-T01 (BiomeManager for `getBlockPalette`), F48-T02 (PrefabLibrary for prefab injection)
**Status:** planned

## User Story

As a player, I want procedural chunks to look different in each biome (sand in the desert, iron in space) and occasionally encounter hand-crafted level segments, so that the infinite mode feels varied and curated.

## Objective

Extend `ChunkGenerator.ts` with a new `generateChunkBiome()` function that uses the biome's block palette for procedural generation and optionally substitutes a prefab chunk from PrefabLibrary. The existing `generateChunk()` function remains unchanged for backward compatibility (test mode, daily challenge seed behavior).

## Dev Notes

### 1. Add new function to `packages/frontend/src/game/systems/ChunkGenerator.ts`

```typescript
export function generateChunkBiome(
  chunkIndex: number,
  baseSeed: number,
  biome: BackgroundTheme,
  prefabPool: PrefabEntry[]
): Chunk
```

### 2. Prefab injection logic

At the top of `generateChunkBiome`, decide whether to use a prefab:
- If `chunkIndex < 10`: never use a prefab (let the player warm up)
- If `chunkIndex % 5 === 0` (every 5th chunk): 50% chance of prefab (seeded random)
  - Call `selectPrefab(prefabPool, chunkIndex * 7919 + baseSeed)` to pick deterministically
  - If a prefab is selected, call `repositionPrefab(entry, chunkIndex * CHUNK_WIDTH)` and return that chunk directly
- Otherwise: generate procedurally

### 3. Biome block palette substitution

When generating procedurally, import `getBlockPalette(biome)` from BiomeManager and use the palette to replace hardcoded block types:

Current code uses:
- `"dirt"` for surface -> replace with `palette.surface`
- `"stone"` for underground -> replace with `palette.underground`
- `"brick"` / `"wood"` / `"stone"` for platforms -> replace with `palette.platform` (or keep variety with a mix)
- `"iron"` / `"stone"` / `"brick"` for walls -> replace with `palette.wall`
- `"lava"` for hazards -> replace with `palette.hazard`
- `"stone"` / `"dirt"` for background terrain -> replace with `palette.background`
- `"wood"` for background tree trunk -> replace with `palette.tree`
- `"leaf"` for background tree canopy -> replace with `palette.canopy`

### 4. Implementation approach

The simplest approach is to clone the logic from `generateChunk()` into `generateChunkBiome()` and apply the palette. Do NOT refactor `generateChunk()` to avoid regressions. The new function can share utility functions (like `seededRandom`) but should be a standalone chunk generator.

Alternatively, if code duplication is too large (>100 lines of identical logic), extract the common procedural logic into a private helper that takes a palette parameter, and have both `generateChunk` and `generateChunkBiome` call it:

```typescript
function generateChunkInternal(
  chunkIndex: number,
  baseSeed: number,
  palette: BlockPalette
): Chunk

// generateChunk calls generateChunkInternal with the forest palette (backward compat)
// generateChunkBiome calls generateChunkInternal with the biome-specific palette
```

### 5. Background decoration per biome

The background section of chunk generation (z-depth blocks) should also use the palette:
- Desert: no trees in background (skip tree generation), use sand blocks
- Space: no trees, use iron/glass blocks
- Ocean: use sand for terrain, keep trees (driftwood)
- Night/Forest: keep trees with wood+leaf

Add a simple check:

```typescript
const hasTrees = biome !== "desert" && biome !== "space";
```

### Relevant Files

- `packages/frontend/src/game/systems/ChunkGenerator.ts` -- the file to modify
- `packages/frontend/src/game/systems/BiomeManager.ts` -- `getBlockPalette()` (from T01)
- `packages/frontend/src/game/systems/PrefabLibrary.ts` -- `selectPrefab()`, `repositionPrefab()` (from T02)

### Gotchas

- `generateChunk()` MUST NOT change behavior. It is used by test mode and daily challenge. Only `generateChunkBiome()` is the new function.
- The seeded random for prefab selection must use a different seed path than the procedural generation to avoid correlation artifacts (e.g., `chunkIndex * 7919 + baseSeed` for prefab, `chunkIndex * 7919 + 31 + baseSeed` for procedural, which is the existing seed).
- Prefab chunks from PrefabLibrary already contain coins, hearts, and blocks. Do NOT regenerate coins/hearts when using a prefab.
- The `difficulty` variable in `generateChunk` is `Math.min(chunkIndex / 25, 1)`. Keep the same formula in `generateChunkBiome`.
- When selecting platform/wall types, preserve some variety. Instead of always using `palette.platform`, use a random choice between `palette.platform` and the original varied types, weighted toward the palette type (e.g., 60% palette, 40% original random).

## Test Scenarios

- **Forest biome:** `generateChunkBiome(5, 0, "forest", [])` produces a chunk with dirt/stone blocks (same as current)
- **Desert biome:** `generateChunkBiome(15, 0, "desert", [])` produces a chunk with sand surface blocks
- **Prefab injection:** `generateChunkBiome(15, 0, "desert", prefabs)` where chunkIndex=15 (divisible by 5) may return a prefab chunk
- **No prefab early:** `generateChunkBiome(5, 0, "forest", prefabs)` never returns a prefab (chunkIndex < 10)
- **Backward compat:** `generateChunk(5, 0)` returns the same output as before this change
