# Task F48-T01 -- BiomeManager: Chunk-to-Biome Mapping

**Feature:** F48
**Wave:** 0
**Type:** frontend
**Depends on:** none (pure logic module)
**Status:** done

## User Story

As a player in infinite mode, I want the world theme to change every N chunks so that the game feels like a journey through different environments.

## Objective

Create a pure-logic module `BiomeManager.ts` that deterministically maps a chunk index to a `BackgroundTheme` (biome) and provides a transition interpolation factor for smooth visual blending between adjacent biomes.

## Dev Notes

### 1. Create `packages/frontend/src/game/systems/BiomeManager.ts`

This is a pure TypeScript module with no React dependencies. It exports functions and constants -- no component, no hooks.

### 2. Constants

```typescript
import type { BackgroundTheme } from "@super-mel/shared";

export const BIOME_SEQUENCE: BackgroundTheme[] = [
  "forest", "desert", "night", "space", "ocean"
];

export const CHUNKS_PER_BIOME = 10;
export const TRANSITION_CHUNKS = 2; // last N chunks of each biome blend into the next
```

### 3. Core function: `getBiomeForChunk(chunkIndex)`

Returns an object describing the biome state for a given chunk:

```typescript
export interface BiomeState {
  /** Primary (current) biome */
  current: BackgroundTheme;
  /** Next biome (only set during transition zone, otherwise null) */
  next: BackgroundTheme | null;
  /** Interpolation factor 0.0-1.0 (0 = fully current, 1 = fully next). 0 when not transitioning. */
  transitionFactor: number;
  /** The biome cycle number (0-based, increments each time through the full sequence) */
  cycle: number;
}

export function getBiomeForChunk(chunkIndex: number): BiomeState
```

Logic:
- `biomeIndex = Math.floor(chunkIndex / CHUNKS_PER_BIOME) % BIOME_SEQUENCE.length`
- `positionInBiome = chunkIndex % CHUNKS_PER_BIOME`
- If `positionInBiome >= CHUNKS_PER_BIOME - TRANSITION_CHUNKS` (i.e., in the last 2 chunks of this biome):
  - `transitionFactor = (positionInBiome - (CHUNKS_PER_BIOME - TRANSITION_CHUNKS)) / TRANSITION_CHUNKS`
  - `next = BIOME_SEQUENCE[(biomeIndex + 1) % BIOME_SEQUENCE.length]`
- Otherwise: `transitionFactor = 0`, `next = null`
- `cycle = Math.floor(chunkIndex / (CHUNKS_PER_BIOME * BIOME_SEQUENCE.length))`

### 4. Helper: `getBlockPalette(biome)`

Returns the block type substitutions for procedural chunk generation per biome:

```typescript
export interface BlockPalette {
  surface: Exclude<BlockType, "empty">;       // replaces "dirt"
  underground: Exclude<BlockType, "empty">;   // replaces "stone" underground
  platform: Exclude<BlockType, "empty">;      // common platform material
  wall: Exclude<BlockType, "empty">;          // obstacle walls
  hazard: Exclude<BlockType, "empty">;        // lava replacement
  background: Exclude<BlockType, "empty">;    // background terrain
  tree: Exclude<BlockType, "empty">;          // background tree trunk
  canopy: Exclude<BlockType, "empty">;        // background tree top
}
```

Palette definitions:
- **forest**: dirt, stone, brick, stone, lava, stone, wood, leaf (current defaults)
- **desert**: sand, stone, sand, iron, lava, sand, sand, sand (no trees in desert, canopy=sand so no visual trees)
- **night**: dirt, stone, brick, brick, lava, stone, wood, leaf (same blocks, different lighting)
- **space**: iron, iron, glass, iron, lava, iron, iron, glass (metallic/industrial)
- **ocean**: sand, stone, sand, stone, water, sand, wood, leaf (water hazards instead of lava)

### 5. Edge cases

- `chunkIndex < 0`: clamp to 0 (should not happen but be defensive)
- `chunkIndex = 0`: always forest, no transition
- Transition math must produce exact 0.0 at the start and approach 1.0 at the end, but never exceed 1.0

### Relevant Files

- `packages/shared/src/types.ts` -- `BackgroundTheme`, `BlockType`
- `packages/frontend/src/game/systems/ChunkGenerator.ts` -- consumer of `getBlockPalette`
- `packages/frontend/src/game/systems/Skybox.tsx` -- consumer of `getBiomeForChunk`

### Gotchas

- This module must be pure (no side effects, no state). All state tracking happens in the caller.
- The transition factor is per-chunk, not per-pixel. The visual systems (Skybox, Lighting) will use this factor as a lerp parameter. The transition is not frame-animated -- it is based on which chunk the player is currently in.
- Do NOT import React or any rendering library. This is a utility module.
