# Task F48-T02 -- PrefabLibrary: Chunk Prefab Registry

**Feature:** F48
**Wave:** 0
**Type:** frontend
**Depends on:** none (pure logic module, uses existing TestLevelData and ChunkGenerator types)
**Status:** planned

## User Story

As a player in infinite mode, I want to encounter hand-crafted level segments mixed with procedural chunks so that the gameplay has more variety and interesting design.

## Objective

Create a `PrefabLibrary.ts` module that maintains a registry of prefab chunks (in `Chunk` format from `ChunkGenerator.ts`) tagged by difficulty range. The existing 5 FASE TESTE chunks become the first set of prefabs. Expose a function to retrieve prefab candidates filtered by difficulty.

## Dev Notes

### 1. Create `packages/frontend/src/game/systems/PrefabLibrary.ts`

Pure TypeScript module. No React dependencies.

### 2. Data structures

```typescript
import type { Chunk } from "./ChunkGenerator";

export interface PrefabEntry {
  /** Unique identifier for this prefab */
  id: string;
  /** Difficulty rating 1-10. Used to filter prefabs by chunk difficulty range. */
  difficulty: number;
  /** The chunk data. startX is relative (0-based) and will be offset when injected. */
  chunk: Chunk;
  /** Optional biome affinity. If set, this prefab is preferred in matching biomes. */
  biomeAffinity?: BackgroundTheme;
}
```

### 3. Register FASE TESTE as prefabs

Import `generateTestLevel()` from `TestLevelData.ts` and convert the 5 returned chunks into `PrefabEntry[]`:

```typescript
import { generateTestLevel } from "./TestLevelData";

function buildTestLevelPrefabs(): PrefabEntry[] {
  const testChunks = generateTestLevel();
  return testChunks.map((chunk, i) => ({
    id: `test-chunk-${i}`,
    difficulty: i + 1, // chunk 0 = diff 1, chunk 4 = diff 5
    chunk: normalizeChunkStartX(chunk), // normalize startX to 0
  }));
}
```

The `normalizeChunkStartX` helper resets `chunk.startX` to 0 and adjusts all block/coin/heart X coordinates by subtracting the original `startX`. This makes prefabs position-independent so they can be injected at any chunk index.

### 4. Core exports

```typescript
/** All registered prefabs */
export const PREFAB_REGISTRY: PrefabEntry[];

/** Get prefab candidates matching a difficulty range */
export function getPrefabCandidates(
  minDifficulty: number,
  maxDifficulty: number,
  biome?: BackgroundTheme
): PrefabEntry[];

/** Select a specific prefab by seeded random from candidates */
export function selectPrefab(
  candidates: PrefabEntry[],
  seed: number
): PrefabEntry | null;

/** Reposition a prefab chunk to a target startX */
export function repositionPrefab(entry: PrefabEntry, targetStartX: number): Chunk;
```

### 5. `getPrefabCandidates` logic

- Filter `PREFAB_REGISTRY` where `entry.difficulty >= minDifficulty && entry.difficulty <= maxDifficulty`
- If `biome` is provided, sort results so matching `biomeAffinity` entries come first (but do not exclude non-matching entries)
- Return the filtered and sorted array

### 6. `selectPrefab` logic

- If `candidates.length === 0`, return `null`
- Use a seeded random (same `seededRandom` pattern as ChunkGenerator) with the given seed to pick an index
- Return `candidates[index]`

### 7. `repositionPrefab` logic

- Clone the chunk data
- Set `chunk.startX = targetStartX`
- Add `targetStartX` to every block, coin, and heart X coordinate
- Return the repositioned clone

### 8. Difficulty mapping for procedural chunks

Export a helper that maps chunk index to a difficulty range suitable for prefab selection:

```typescript
export function chunkDifficultyRange(chunkIndex: number): { min: number; max: number } {
  // Difficulty increases from 1 to 10 over the first 50 chunks, then stays at 8-10
  const progress = Math.min(chunkIndex / 50, 1);
  const center = 1 + progress * 9; // 1 to 10
  const range = 2;
  return {
    min: Math.max(1, Math.floor(center - range)),
    max: Math.min(10, Math.ceil(center + range)),
  };
}
```

### Gotchas

- The test chunks from `generateTestLevel()` have absolute `startX` values (0, 16, 32, 48, 64). The normalization step MUST subtract these to make them 0-based. Otherwise, `repositionPrefab` will produce incorrect positions.
- Prefab chunks use `CHUNK_WIDTH = 16` blocks wide, same as procedural chunks. Do not assume different widths.
- Deep-clone chunk data in `repositionPrefab` to avoid mutating the registry. Use `structuredClone` or manual cloning of arrays.
- The prefab registry is built once at module load time (top-level). No lazy initialization needed since test level generation is cheap.
