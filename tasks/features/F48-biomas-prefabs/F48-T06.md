# Task F48-T06 -- ChunkRenderer Integration: Biome-Aware Chunk Loading

**Feature:** F48
**Wave:** 2
**Type:** frontend
**Depends on:** F48-T01 (BiomeManager), F48-T02 (PrefabLibrary), F48-T03 (generateChunkBiome), F48-T05 (GameScene3D biome wiring)
**Status:** done

## User Story

As a player in infinite mode, I want the chunk renderer to generate biome-appropriate chunks (with the right block palette and occasional prefabs) so that the terrain visually matches the sky/lighting biome.

## Objective

Modify ChunkRenderer.tsx to use `generateChunkBiome()` instead of `generateChunk()` in infinite mode. The chunk renderer queries BiomeManager for the biome of each chunk index and passes the biome + prefab pool to the new generator function. Test mode and level mode (which use `testChunks` prop) remain unchanged.

## Dev Notes

### 1. Modify `packages/frontend/src/game/systems/ChunkRenderer.tsx`

#### 1a. New imports

```typescript
import { generateChunkBiome } from "./ChunkGenerator";
import { getBiomeForChunk } from "./BiomeManager";
import { PREFAB_REGISTRY, getPrefabCandidates, chunkDifficultyRange } from "./PrefabLibrary";
```

#### 1b. New prop

Add an optional `biomeEnabled` prop to ChunkRendererProps:

```typescript
interface ChunkRendererProps {
  playerPosRef: React.RefObject<{ x: number; y: number }>;
  onBlockDestroyed?: (x: number, y: number) => void;
  onHeartCollected?: () => void;
  onCoinCollected?: () => void;
  testChunks?: Chunk[];
  baseSeed?: number;
  biomeEnabled?: boolean; // when true, use generateChunkBiome instead of generateChunk
}
```

#### 1c. Modify the `useFrame` chunk generation loop

Currently, when `testChunks` is not provided, the loop calls `generateChunk(idx, baseSeed)`. Change this to:

```typescript
if (biomeEnabled) {
  const biomeState = getBiomeForChunk(idx);
  const { min, max } = chunkDifficultyRange(idx);
  const candidates = getPrefabCandidates(min, max, biomeState.current);
  next.set(idx, generateChunkBiome(idx, baseSeed ?? 0, biomeState.current, candidates));
} else {
  next.set(idx, generateChunk(idx, baseSeed ?? 0));
}
```

This ensures:
- Infinite mode with biomes uses `generateChunkBiome` (biome palette + prefab injection)
- Daily challenge mode can also use biome-aware generation (by passing `biomeEnabled={true}`)
- Backward compatibility: without `biomeEnabled`, behavior is identical to current

#### 1d. Optional: report biome info back to parent

Add an optional callback prop so GameScene3D can receive the biome state for the chunk the player is currently in:

```typescript
onBiomeUpdate?: (biomeState: BiomeState) => void;
```

In the `useFrame` loop, after determining which chunk the player is in, compute the BiomeState and call this callback. This is an alternative to having GameScene3D compute the biome state independently -- it keeps the biome logic centralized in ChunkRenderer where chunk index is already computed.

However, the simpler approach is to keep biome state computation in GameScene3D (as described in T05) and only use `biomeEnabled` in ChunkRenderer for chunk generation. Both approaches work; choose whichever avoids prop drilling.

### 2. Modify `packages/frontend/src/game/scenes/GameScene3D.tsx`

Pass `biomeEnabled` to ChunkRenderer in infinite mode:

```typescript
<ChunkRenderer
  ref={chunkRef}

  onCoinCollected={handleCoinCollected}
```

When `effectiveChunks` is provided (test mode or level mode), the `biomeEnabled` flag is irrelevant because ChunkRenderer skips procedural generation entirely for `testChunks`.

### 3. Add `difficulty` to shared types (optional, for future editor tagging)

In `packages/shared/src/types.ts`, add an optional `difficulty` field to `LevelDataV2`:

```typescript
export interface LevelDataV2 {
```

This field is not used by the editor yet but enables future features where editor-created levels can be tagged as prefab chunks with a difficulty rating.

### Gotchas

- **Test chunks bypass.** When `testChunks` is provided, the `useFrame` generation loop returns early (`if (testChunks) return;`). This means `biomeEnabled` has no effect when test chunks are present. This is correct behavior -- do not change it.
- **Chunk caching.** Generated chunks are stored in a `Map<number, Chunk>`. Once a chunk is generated and cached, it is NOT regenerated even if the biome would be different. This is correct because chunks should not change after generation. The biome for a chunk is determined at generation time.
- **Prefab pool per chunk.** The `getPrefabCandidates` call filters prefabs for each chunk's difficulty range and biome. This is called inside the chunk generation loop, which runs at most once per chunk per session. Performance is not a concern.
- **Daily challenge determinism.** Daily challenge uses `baseSeed = dailySeed`. With `biomeEnabled`, the biome is determined by `chunkIndex` (not seed), so two players on the same day will see the same biome sequence. The prefab injection is seed-dependent, so the same seed produces the same prefab placement. This is the desired behavior.
- **Shared types change.** Adding `difficulty?: number` to `LevelDataV2` is a non-breaking change (optional field). The backend does not validate this field (it stores level data as JSON blob). No migration needed.
