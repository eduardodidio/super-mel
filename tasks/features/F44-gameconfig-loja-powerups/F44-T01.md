# Task F44-T01 -- GAME_CONFIG centralizado + resolveConfig

**Feature:** F44
**Wave:** 0
**Type:** shared + frontend
**Depends on:** none (foundation task)
**Status:** planned

## User Story

As a developer, I want all gameplay constants in a single source of truth so that upgrades, Assist Mode, and tuning changes propagate automatically without hunting through individual component files.

## Objective

Move `GAME_CONFIG` from `shared/types.ts` to its own file `shared/gameConfig.ts`, extend it with all the constants currently hardcoded in `Mel.tsx` and `Projectile.tsx`, define `UpgradeId`, `UpgradeCatalog`, `ResolvedConfig`, and implement `resolveConfig()` -- a pure function that applies upgrade overrides to the base config.

### 4. Implement `resolveConfig`

```typescript
export function resolveConfig(equipped: UpgradeId[]): ResolvedConfig {
  const base: ResolvedConfig = { ...GAME_CONFIG };
  for (const id of equipped) {
    const upgrade = UPGRADE_CATALOG.find((u) => u.id === id);
    if (upgrade) {
      Object.assign(base, upgrade.effect);
    }
  }
  return base;
}
```

### 8. Create `packages/frontend/src/game/hooks/useResolvedConfig.ts`

```typescript
import { useMemo } from "react";
import { resolveConfig, type UpgradeId } from "@super-mel/shared";
import { useShopState } from "./useShopState";

export function useResolvedConfig() {
  const equipped = useShopState((s) => s.equipped);
  return useMemo(() => {
    const ids = equipped.filter((e): e is UpgradeId => e !== null);
    return resolveConfig(ids);
  }, [equipped]);
}
```

### Gotchas

- `GAME_CONFIG` is currently `as const` (deeply readonly). The `ResolvedConfig` type needs to be mutable since `resolveConfig` produces a mutable copy. Do NOT mutate the original `GAME_CONFIG`.
- Some files may import `GAME_CONFIG` directly from `@super-mel/shared`. The re-export in `types.ts` must keep these working.
- The `chunkWidth` and `viewDistance` fields are still used by `ChunkGenerator.ts`. Make sure they remain accessible.
- `useResolvedConfig` will initially return base config with no upgrades (stub). This is correct -- T02 provides the real shop state.
