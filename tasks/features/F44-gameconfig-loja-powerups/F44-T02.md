# Task F44-T02 -- Shop State (useShopState) + Persistence via Progress

**Feature:** F44
**Wave:** 0
**Type:** frontend
**Depends on:** F41 (Progress backend -- already done)
**Status:** done

## User Story

As a player, I want my purchased upgrades and equipment loadout to be saved so that they persist across sessions and devices (when logged in).

## Objective

Create the `useShopState` Zustand store that manages purchased upgrades, 2 equipment slots, and buy/equip/unequip actions. Wire the shop state into `useProgressSync` so it persists via the F41 progress system.

## Dev Notes

### 1. Create `packages/frontend/src/game/hooks/useShopState.ts`

```typescript
import { create } from "zustand";
import type { UpgradeId } from "@super-mel/shared";

interface ShopState {
  purchased: UpgradeId[];
  equipped: [UpgradeId | null, UpgradeId | null];

  buy: (id: UpgradeId, price: number) => boolean;
  equip: (id: UpgradeId, slot: 0 | 1) => void;
  unequip: (slot: 0 | 1) => void;
  loadFromProgress: (data: { purchased?: string[]; equipped?: string[] }) => void;
  getProgressData: () => { purchased: string[]; equipped: (string | null)[] };
}
```

Key behaviors:

- **buy(id, price):** Checks `totalCoins >= price` (read from `useGameState`). If affordable, deducts coins (via `useGameState`), adds `id` to `purchased[]`, returns `true`. If already purchased or insufficient coins, returns `false`.
- **equip(id, slot):** Only if `id` is in `purchased[]`. If the item is already equipped in the other slot, swap. Sets `equipped[slot] = id`.
- **unequip(slot):** Sets `equipped[slot] = null`.
- **loadFromProgress(data):** Called on mount by `useProgressSync`. Validates that each id in `data.purchased` and `data.equipped` is a valid `UpgradeId` before loading.
- **getProgressData():** Returns `{ purchased, equipped }` for sync to backend.

const STORAGE_KEY = "supermel_shop";

function loadShopFromStorage(): { purchased: UpgradeId[]; equipped: [UpgradeId | null, UpgradeId | null] } {
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    if (!raw) return { purchased: [], equipped: [null, null] };
    const parsed = JSON.parse(raw);
    // validate UpgradeId values...
    return parsed;
  } catch {
    return { purchased: [], equipped: [null, null] };
  }

### 4. Coin deduction for purchases

The `buy()` action needs to deduct coins from `useGameState.totalCoins`:

```typescript
buy: (id, price) => {
  const gameState = useGameState.getState();
  if (gameState.totalCoins < price) return false;
  if (get().purchased.includes(id)) return false;

  // Deduct coins
  const newTotal = gameState.totalCoins - price;
  useGameState.setState({ totalCoins: newTotal });
  try { localStorage.setItem("supermel_total_coins", String(newTotal)); } catch {}

  // Add to purchased
  set((s) => ({ purchased: [...s.purchased, id] }));
  return true;
},
```

### Gotchas

- **Circular dependency risk:** `useShopState` reads from `useGameState` (for `totalCoins`). `useGameState` does NOT read from `useShopState`. Keep the dependency one-directional.
- **UpgradeId validation on load:** The backend `data` field is `Json` (any). Always validate that loaded upgrade IDs are members of the `UpgradeId` union before storing them.
- **Race condition:** On mount, `useProgressSync` loads progress and then hydrates the shop state. Ensure the shop loads from localStorage first (instant), then overwrites with backend data when it arrives. Use the same `Math.max` conflict resolution as `useProgressSync` does for coins.
- **Persist on buy/equip:** Each mutation should trigger a localStorage write immediately and a debounced backend sync.
