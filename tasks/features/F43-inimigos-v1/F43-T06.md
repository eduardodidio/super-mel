# Task F43-T06 -- ChunkGenerator Enemy Spawns + LevelSceneConverter Enemy Extraction

**Feature:** F43
**Wave:** 2
**Type:** frontend
**Depends on:** F43-T04 (EnemyManager and EnemySpawnData type)
**Status:** done

## User Story

As a player, I want enemies to appear naturally in infinite mode, becoming more frequent and varied as I progress, so that the difficulty curve feels right and keeps me challenged.

## Objective

Extend ChunkGenerator to produce enemy spawn data based on the difficulty curve. Extend LevelSceneConverter to extract enemy entities from LevelDataV2 into a dedicated `enemies` field. Add `EnemySubtype` type to shared types.

### Part B: ChunkGenerator Enemy Spawns

#### `packages/frontend/src/game/systems/ChunkGenerator.ts`

```typescript
export interface EnemyChunkData {
  subtype: EnemySubtype;

  y: number;
}

export interface Chunk {

  blocks: BlockData[];
  hearts: HeartData[];
  coins: CoinData[];

```

**2. Generate enemies in `generateChunk()`:**

Add enemy generation section after the existing coin generation, before the `return` statement:

```typescript
const enemies: EnemyChunkData[] = [];

// No enemies in safe zone (chunks 0-2)
if (chunkIndex >= 3) {
  // --- VACUUM (Aspirador-robo) ---
  // Appears from chunk 3+ (difficulty >= 0.12)
  // Spawns on ground segments (not in gaps)
  for (let x = 2; x < CHUNK_WIDTH - 2; x += 5 + Math.floor(rand() * 4)) {
    if (gapPositions.has(x)) continue;
    const vacuumChance = 0.08 + difficulty * 0.12; // 8%-20% per position
    if (rand() < vacuumChance) {
      enemies.push({
        subtype: "vacuum",
        x: startX + x,
        y: heights[x] + 1, // on top of ground
      });
    }
  }

  // --- PIGEON (Pombo) ---
  // Appears from chunk 8+ (difficulty >= 0.32)
  if (difficulty > 0.3) {
    for (let x = 3; x < CHUNK_WIDTH - 3; x += 7 + Math.floor(rand() * 5)) {
      const pigeonChance = 0.05 + (difficulty - 0.3) * 0.15; // 5%-15.5%
      if (rand() < pigeonChance) {
        const flyY = (heights[x] || 0) + 3 + Math.floor(rand() * 3); // 3-5 above ground
        enemies.push({
          subtype: "pigeon",
          x: startX + x,
          y: flyY,
        });
      }
    }
  }

  // --- BEE (Abelha) ---
  // Appears from chunk 15+ (difficulty >= 0.6)
  if (difficulty > 0.6) {
    for (let x = 4; x < CHUNK_WIDTH - 4; x += 10 + Math.floor(rand() * 6)) {
      const beeChance = 0.04 + (difficulty - 0.6) * 0.1; // 4%-8%
      if (rand() < beeChance) {
        const beeY = (heights[x] || 0) + 2 + Math.floor(rand() * 2);
        enemies.push({
          subtype: "bee",
          x: startX + x,
          y: beeY,
        });
      }
    }
  }

  // Cap enemies per chunk (max 3) to avoid overcrowding
  if (enemies.length > 3) enemies.length = 3;
}
```

### Part D: ChunkRenderer Enemy Data Pass-through

#### `packages/frontend/src/game/systems/ChunkRenderer.tsx`

The ChunkRenderer currently renders blocks, hearts, and coins from chunks. For enemies, it does NOT render them directly (that is EnemyManager's job). Instead, it needs to expose the current enemy data for the parent to pass to EnemyManager.

**Option A (Preferred):** Add an `onEnemiesUpdate` callback prop that fires whenever visible chunks change, providing the aggregated enemy list from all visible chunks.

**Option B:** Add enemies to the imperative handle so the parent can query them.

**Option C (Simplest):** The parent (GameScene3D in T07) generates chunks independently for enemy data. Since ChunkRenderer already generates chunks, this would duplicate work.

Go with **Option A**:
```typescript
interface ChunkRendererProps {
  // ... existing props
  onEnemiesUpdate?: (enemies: EnemyChunkData[]) => void;
}
```

In the `useFrame` chunk update logic, after updating visible chunks, call `onEnemiesUpdate` with the aggregated enemies from all visible chunks. Give each enemy a stable ID based on chunk index + position: `enemy-${chunkIdx}-${e.x}-${e.y}`.

### Gotchas

- The `EnemyChunkData` type from ChunkGenerator needs to be convertible to `EnemySpawnData` from EnemyManager. The conversion adds an `id` field. This happens in ChunkRenderer's callback or in GameScene3D.
- Enemy spawn positions must be on valid ground. Use the `heights[]` array and `gapPositions` set to ensure vacuums spawn on actual platforms, not in gaps.
- The seeded random ensures deterministic enemy placement for a given chunk index, important for the daily challenge mode.
- Cap at 3 enemies per chunk to prevent overwhelming the player and maintain performance.
- When chunks unload, their enemies should be removed from the active enemy list (EnemyManager handles this via prop changes).
- The `enemies: []` field must be added to all Chunk return statements to avoid undefined.
