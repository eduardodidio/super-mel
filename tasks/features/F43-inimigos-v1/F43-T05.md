# Task F43-T05 -- Stomp Bounce (Mel.tsx) + Projectile x Enemy Collision (ProjectileManager.tsx)

**Feature:** F43
**Wave:** 1
**Type:** frontend
**Depends on:** F43-T01, F43-T02, F43-T03 (enemy components exist with named RigidBodies)
**Status:** planned

## User Story

As a player, I want to bounce upward when I stomp on an enemy (like Mario) and I want my Bola do Infinito to defeat enemies it hits, so that combat feels responsive and rewarding.

## Objective

Make two targeted modifications to existing components:
1. **Mel.tsx:** Add a mechanism for the parent scene to trigger a stomp bounce (upward velocity impulse) on Mel's rigid body.
2. **ProjectileManager.tsx:** Extend collision detection so projectiles detect and report hits on enemy rigid bodies (name prefix `"enemy-"`).

## Dev Notes

### Part A: Stomp Bounce in Mel.tsx

#### Option 1 (Preferred): Imperative Handle via forwardRef

Wrap Mel in `forwardRef` and expose a `stompBounce()` method via `useImperativeHandle`:

```typescript
export interface MelHandle {
  stompBounce: () => void;
}

export const Mel = forwardRef<MelHandle, MelProps>(function Mel(props, ref) {
  const rigidBodyRef = useRef<RapierRigidBody>(null);

  useImperativeHandle(ref, () => ({
    stompBounce() {
      if (!rigidBodyRef.current) return;
      const vel = rigidBodyRef.current.linvel();
      rigidBodyRef.current.setLinvel(
        { x: vel.x, y: STOMP_BOUNCE_FORCE, z: 0 },
        true
      );
      // Reset flying/jumping state so Mel can re-jump
      jumping.current = false;
      flying.current = false;
      flyTimer.current = 0;
    },
  }));

  // ... rest of Mel component
});
```

Constants:
```typescript
const STOMP_BOUNCE_FORCE = 7; // ~70% of JUMP_FORCE (10)
```

The parent (GameScene3D) holds a `melRef = useRef<MelHandle>(null)` and calls `melRef.current?.stompBounce()` when the EnemyManager reports a stomp.

#### Option 2 (Simpler): Callback Prop

Add an `onStompBounce` mechanism by having the parent set a ref that Mel reads:

```typescript
interface MelProps {
  // ... existing props
  stompBounceSignal?: React.RefObject<boolean>;
}
```

In Mel's `useGameFrame`, check if `stompBounceSignal.current` is true. If so, apply the bounce velocity and reset the flag to false. This avoids needing forwardRef but is slightly less clean.

**Decision:** Use Option 1 (forwardRef) as it is more explicit and does not pollute the frame loop with a polling check.

#### Changes to Mel.tsx

1. Import `forwardRef`, `useImperativeHandle` from React
2. Convert `Mel` from a regular function to `forwardRef<MelHandle, MelProps>`
3. Add the `useImperativeHandle` block exposing `stompBounce()`
4. Export the `MelHandle` type
5. Add `STOMP_BOUNCE_FORCE` constant
6. Ensure the existing `stateRef` prop still works (it is separate from the imperative handle)

**Important:** This change must be backward-compatible. All existing callers of `<Mel>` that do not pass a ref should still work without changes.

### Part B: Projectile x Enemy Collision in ProjectileManager.tsx

#### Changes to ProjectileManager.tsx

Add a new prop:
```typescript
interface ProjectileManagerProps {
  // ... existing props
  onEnemyHit?: (enemyId: string) => void;
}
```

Pass `onEnemyHit` down to each `<Projectile>` component as a new prop.

#### Changes to Projectile.tsx

In the `handleCollision` function, extend the logic:

```typescript
const handleCollision = (payload: CollisionPayload) => {
  if (exploding) return;
  const otherName = payload.other.rigidBodyObject?.name || "";

  // Existing: block hit
  if (otherName.startsWith("block-")) {
    // ... existing block hit logic (unchanged)
  }

  // NEW: enemy hit
  if (otherName.startsWith("enemy-")) {
    const pos = rbRef.current?.translation();
    if (pos) explodePosRef.current.set(pos.x, pos.y, pos.z);
    setExploding(true);
    onEnemyHit?.(otherName); // pass the full RigidBody name
  }
};
```

The parent (EnemyManager via GameScene3D) will parse the enemy ID from the name string (e.g., `"enemy-vacuum-abc123"` -> `"abc123"`).

#### Changes to Projectile.tsx Props

```typescript
  // ... existing props

}
```

### Gotchas

- **Backward compatibility:** Mel is used in GameScene3D without a ref today. Converting to forwardRef with `useImperativeHandle` is backward-compatible -- components that do not pass a ref will work fine.
- **Stomp bounce physics:** The bounce force (7) should feel good -- not as high as a full jump (10) but enough to chain stomps on consecutive enemies. Test and adjust.
- **Projectile explode on enemy:** The projectile should play the same explosion animation as when hitting a block. The `setExploding(true)` call handles this.
- **Collision group filtering:** Ensure projectiles do NOT collide with Mel's own rigid body. Currently, the Projectile uses `sensor` mode and `onIntersectionEnter`, which only triggers on intersection. Since Mel's collider overlaps the projectile spawn point, check if there is an initial false positive. The existing offset (`playerX + dir * 0.8`) should prevent this.
- **Enemy name parsing:** The convention is `enemy-{subtype}-{id}`. The EnemyManager (T04) will need to extract the id portion. This is straightforward string manipulation.
