# Task F43-T04 -- EnemyManager: Lifecycle, Defeat, and Coin Drops

**Feature:** F43
**Wave:** 1
**Type:** frontend
**Depends on:** F43-T01, F43-T02, F43-T03 (enemy components)
**Status:** planned

## User Story

As a player, I want a unified system managing all enemies in the current scene so that they spawn correctly, drop coins when defeated, and are properly cleaned up.

## Objective

Create the EnemyManager component that orchestrates enemy lifecycle: receives enemy data from the parent scene (either from level data or from ChunkGenerator), renders the appropriate enemy components, handles defeat (stomp and projectile kills), triggers coin drops via the existing DroppedCoin system, and removes defeated enemies after their animation completes.

## Dev Notes

### 1. Create `packages/frontend/src/game/systems/EnemyManager.tsx`

Props interface:
```typescript
export interface EnemySpawnData {
  id: string;
  subtype: "vacuum" | "pigeon" | "bee";
  x: number;
  y: number;
}

interface EnemyManagerProps {
  enemies: EnemySpawnData[];
  playerPosRef: React.RefObject<{ x: number; y: number }>;
  onMelDamage: () => void;
  onMelStompBounce: () => void;
  onSpawnCoins: (x: number, y: number, count: number) => void;
}
```

### 2. Internal State

Maintain an internal map of active enemies with their current state:

```typescript
interface ActiveEnemy {
  data: EnemySpawnData;
  defeated: boolean;
  defeatTime: number; // timestamp when defeated, for animation cleanup
}
```

Use `useState<Map<string, ActiveEnemy>>` initialized from the `enemies` prop. When the `enemies` prop changes (new chunks loaded, etc.), merge new enemies into the map, keeping existing ones' state. Remove enemies whose IDs are no longer in the prop (chunk unloaded).

### 3. Rendering

Map over active enemies and render the appropriate component based on `subtype`:
```tsx
{activeEnemies.map(enemy => {
  switch (enemy.data.subtype) {
    case "vacuum":
      return <EnemyVacuum key={enemy.data.id} ... />;
    case "pigeon":
      return <EnemyPigeon key={enemy.data.id} ... />;
    case "bee":
      return <EnemyBee key={enemy.data.id} playerPosRef={playerPosRef} ... />;
  }
})}
```

Pass `defeated={enemy.defeated}` to each component, plus the shared `onContactMel` handler.

### 4. Contact Handler (Stomp vs Damage)

The `onContactMel` callback receives `(enemyId, isStompable)`:

**If isStompable (stomp from above):**
1. Mark the enemy as defeated: `setActiveEnemies(prev => ...)` with `defeated: true` and `defeatTime: performance.now()`
2. Call `onMelStompBounce()` -- this tells the parent scene to apply upward velocity to Mel
3. Spawn coins: determine count based on enemy subtype (vacuum: 1-2, pigeon: 2-3, bee: 2-3) and call `onSpawnCoins(enemyX, enemyY, count)`

**If NOT stompable (lateral contact):**
1. Call `onMelDamage()` -- this triggers the existing damage/invincibility flow in GameScene3D
2. Do NOT defeat the enemy

### 5. Projectile Kill Handler

Expose a method or callback that the parent scene (or ProjectileManager) can use to report a projectile hitting an enemy:

```typescript
onProjectileHitEnemy: (enemyId: string) => void
```

When called:
1. Find the enemy by ID in the active map
2. If not already defeated, mark as defeated + set defeatTime
3. Spawn coins (same logic as stomp)
4. Do NOT call `onMelStompBounce` (no bounce for projectile kills)

This callback is passed to the parent via props or exposed via `forwardRef`/`useImperativeHandle`.

### 6. Cleanup

In `useFrame`, check defeated enemies whose `defeatTime` is more than 800ms ago (enough time for defeat animation) and remove them from the active map entirely.

### 7. Distance Culling

For performance, only render enemies within a 30-unit horizontal distance from Mel. Enemies beyond this range are still tracked in state but not rendered (no component mounted). When they come back into range, they are rendered again (with their patrol position potentially different -- this is acceptable for v1).

### Gotchas

- The `enemies` prop can change when chunks load/unload in infinite mode. The manager must handle enemies appearing and disappearing gracefully.
- Do not re-create enemies that were already defeated when chunks reload (use the `destroyedEnemies` ref set, similar to `destroyedBlocks` in ChunkRenderer).
- Multiple stomps on the same enemy should be idempotent (guard with `defeated` flag).
- The coin spawn callback reuses the existing `spawnDroppedCoins` function signature from GameScene3D.
- Export `EnemySpawnData` type from this file so ChunkGenerator and LevelSceneConverter can use it.
