# Task F43-T01 -- EnemyVacuum Component (Aspirador-robo)

**Feature:** F43
**Wave:** 0
**Type:** frontend
**Depends on:** F37 (EntityType "enemy" in LevelDataV2)
**Status:** done

## User Story

As a player, I want to encounter a patrolling vacuum robot enemy on platforms so that the game has ground-level hazards that I need to jump over or defeat.

## Objective

Create the Aspirador-robo enemy component -- a metallic robot that patrols back and forth on its platform, turning around at edges. It damages Mel on lateral contact but can be defeated by stomping or by the Bola do Infinito.

## Dev Notes

### 1. Create `packages/frontend/src/game/entities/EnemyVacuum.tsx`

Props interface:
```typescript
interface EnemyVacuumProps {
  id: string;
  position: [number, number, number];
  onContactMel: (enemyId: string, isStompable: boolean) => void;
  defeated?: boolean;
}
```

### 2. Visual: Metallic Vacuum Robot

Build from simple box geometries (voxel-style, consistent with game aesthetic):
- **Body:** Rounded box (BoxGeometry 0.8 x 0.5 x 0.6), metallic gray color (`#808080`), `metalness: 0.6`, `roughness: 0.3`
- **Top light:** Small sphere (0.08 radius) on top, red emissive (`#FF0000`, `emissiveIntensity: 2`), pulsing intensity via `useFrame`
- **Front bumper:** Thin box at the front face, slightly darker gray
- Overall scale: fits within ~1 block width, shorter than Mel (0.5 units tall vs Mel's 0.9)

### 3. AI: Platform Patrol

Implement in `useFrame`:
- Move horizontally at `PATROL_SPEED = 2` units/s in the current facing direction
- Use `world.castRay()` to detect ground ahead (same pattern as Mel's ground check but offset forward by 0.5 units). If no ground detected (edge), reverse direction.
- Use `world.castRay()` horizontally to detect walls. If wall detected within 0.3 units ahead, reverse direction.
- Flip the visual mesh group's X scale when direction changes (like Mel does)
- Add a subtle vertical bob: `y += Math.sin(time * 4) * 0.03`

### 4. Physics Body

Follow the pattern from Coin.tsx / Heart.tsx but with kinematic body:
- `RigidBody type="kinematicPosition"` -- we control position manually in useFrame
- `CuboidCollider args={[0.35, 0.2, 0.25]}` -- slightly smaller than visual for fair gameplay
- `name={`enemy-vacuum-${id}`}` -- name prefix "enemy-" is used by ProjectileManager for hit detection
- `sensor={false}` -- NOT a sensor; it should be a solid body so Mel can stand on top of it

**Important:** Use `kinematicPosition` type, NOT `dynamic`. The enemy position is controlled by the AI, not by physics simulation. Set position each frame using `rb.setNextKinematicTranslation()`.

### 5. Collision Detection

Use `onCollisionEnter` (NOT `onIntersectionEnter` since it is not a sensor):
- Check if `payload.other.rigidBodyObject?.name === "mel"`
- Determine stomp vs lateral: read Mel's rigid body velocity from the collision payload. If `melVelY < -1` and the contact manifold normal points upward (Mel is above), it is a stomp. Otherwise, it is lateral damage.
- Call `onContactMel(id, isStompable)` where `isStompable = true` means it was a stomp from above.

Alternative approach (simpler): Use a separate small `CuboidCollider` sensor on top of the enemy (the "stomp zone", args=[0.3, 0.05, 0.25], position offset [0, 0.25, 0]) with `onIntersectionEnter` to detect stomps, and use the main body `onCollisionEnter` for lateral damage. This gives cleaner separation.

### 6. Defeat Animation

When `defeated` prop becomes true:
- Stop all AI movement
- Play "fly away" animation over 0.6s: translate upward + shrink scale to 0 + rotate slightly
- After animation completes, the parent (EnemyManager) will remove the component from the render tree
- Optional: spawn a few sparkle particles (small emissive spheres that fade out)

### Gotchas

- Do NOT handle coin drops, score changes, or Mel damage inside this component. Only call the `onContactMel` callback. EnemyManager (T04) handles all side effects.
- Use `useGameFrame` instead of `useFrame` if available, to respect the game's pause state. If not, check `useGameState.getState().paused` at the top of the frame callback.
- The enemy should be visible and have physics even while Mel is invincible -- the damage logic is handled by the parent. The enemy just reports contact.
- Platform edge detection needs to work for platforms of any width, including single-block-wide platforms.
