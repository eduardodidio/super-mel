# Task F38-T04 -- Screen Shake System + Item Block Bump

**Feature:** F38
**Wave:** 1
**Type:** frontend (VFX / camera / game feel)
**Depends on:** (none for screen shake; block bump is independent)
**Status:** planned

## User Story

As a player, I want to feel the impact of block destruction and damage through brief screen shakes, and I want item blocks to visually bump when hit, so that interactions feel punchy and satisfying.

## Objective

1. Create a `useScreenShake` hook/store that any component can trigger
2. Apply shake offset to the camera in CameraRig.tsx
3. Trigger shake on block destroy (small) and on damage (medium)
4. Add bump animation to item_block in Block.tsx when activated
5. Add 40ms hit-stop (physics time scale) on damage

## Dev Notes

### 1. New file: `packages/frontend/src/game/systems/useScreenShake.ts`

Create a tiny Zustand store + hook:

```typescript
import { create } from "zustand";

interface ShakeState {
  intensity: number;   // current shake amplitude (world units)
  duration: number;    // remaining duration (seconds)
  offsetX: number;     // current random X offset to apply
  offsetY: number;     // current random Y offset to apply
  shake: (intensity: number, duration: number) => void;
  tick: (delta: number) => void;
}

export const useScreenShake = create<ShakeState>((set, get) => ({
  intensity: 0,
  duration: 0,
  offsetX: 0,
  offsetY: 0,

  shake: (intensity: number, duration: number) => {
    const current = get();
    // Only override if new shake is stronger than remaining shake
    if (intensity >= current.intensity) {
      set({ intensity, duration });
    }
  },

  tick: (delta: number) => {
    const s = get();
    if (s.duration <= 0) {
      if (s.offsetX !== 0 || s.offsetY !== 0) {
        set({ offsetX: 0, offsetY: 0, intensity: 0 });
      }
      return;
    }

    const remaining = Math.max(0, s.duration - delta);
    const decay = remaining / s.duration; // 1 -> 0 as shake finishes
    const amp = s.intensity * decay;

    set({
      duration: remaining,
      offsetX: (Math.random() - 0.5) * 2 * amp,
      offsetY: (Math.random() - 0.5) * 2 * amp,
    });
  },
}));
```

### 2. CameraRig.tsx -- Apply shake offset

**Import the shake store:**
```typescript
import { useScreenShake } from "./useScreenShake";
```

**In useFrame, tick the shake and apply offset:**
```typescript
useFrame((_, delta) => {
  // Tick screen shake
  const shakeTick = useScreenShake.getState().tick;
  shakeTick(delta);
  const { offsetX: shakeX, offsetY: shakeY } = useScreenShake.getState();

  /* ... existing deadzone/target computation ... */

  const goalPos = new THREE.Vector3(
    targetX + offset[0] + lookaheadRef.current + shakeX,   // add shakeX
    targetY + offset[1] + lookOffsetRef.current + shakeY,  // add shakeY
    offset[2]
  );
  camera.position.lerp(goalPos, lerpSpeed);
  camera.lookAt(
    targetX + offset[0] + lookaheadRef.current,  // lookAt stays stable (no shake)
    targetY + offset[1] + lookOffsetRef.current,
    0
  );
});
```

**Important:** Apply shake offset to camera.position but NOT to camera.lookAt. This creates a physical "jolt" effect where the camera position moves but the look target stays stable, which feels more natural than jittering the look target.

### 4. Hit-stop (40ms physics freeze) on damage

In `handleDamage`, briefly set the Rapier world's timestep to 0:

This requires access to the Rapier world. Since GameScene3D is inside the Physics provider, we can use a ref or a small helper.

**Simpler approach:** Use a `paused` state that stops the useFrame in Mel.tsx for 40ms. But this is complex.

**Simplest approach:** Use `world.timestep = 0` for 40ms. However, this requires the world ref from `useRapier()`. Since GameScene3D cannot call hooks conditionally, the developer should create a small `HitStop` component:

```typescript
// Inside GameScene3D.tsx or new file
function HitStop({ triggerRef }: { triggerRef: React.RefObject<boolean> }) {
  const { world } = useRapier();
  const originalTimestep = useRef(1/60);
  const timerRef = useRef(0);
  const active = useRef(false);

  useFrame((_, delta) => {
    if (triggerRef.current && !active.current) {
      originalTimestep.current = world.timestep;
      world.timestep = 0;
      active.current = true;
      timerRef.current = 0;
      triggerRef.current = false;
    }

    if (active.current) {
      timerRef.current += delta;
      if (timerRef.current >= 0.04) { // 40ms
        world.timestep = originalTimestep.current;
        active.current = false;
      }
    }
  });

  return null;
}
```

In GameScene3D, add a hitStop ref and trigger it on damage:
```typescript

// In JSX:
<HitStop triggerRef={hitStopRef} />
```

### 5. Block.tsx -- Item block bump animation

When an item_block's `activated` prop changes from `false` to `true`, animate the visual mesh upward and back.

**Add refs and state for bump:**
```typescript
const meshRef = useRef<THREE.Mesh>(null);
const bumpRef = useRef({ active: false, timer: 0 });
const prevActivated = useRef(activated);
```

**Detect activation change and trigger bump:**
```typescript
useFrame((_, delta) => {
  // Detect activation edge
  if (activated && !prevActivated.current) {
    bumpRef.current = { active: true, timer: 0 };
  }
  prevActivated.current = activated;

  // Animate bump
  if (bumpRef.current.active && meshRef.current) {
    bumpRef.current.timer += delta;
    const t = bumpRef.current.timer;
    const UP_DURATION = 0.06;   // 60ms up
    const DOWN_DURATION = 0.12; // 120ms down
    const BUMP_HEIGHT = 0.15;

    if (t < UP_DURATION) {
      // Rising phase
      meshRef.current.position.y = THREE.MathUtils.lerp(0, BUMP_HEIGHT, t / UP_DURATION);
    } else if (t < UP_DURATION + DOWN_DURATION) {
      // Falling phase
      const dt = (t - UP_DURATION) / DOWN_DURATION;
      meshRef.current.position.y = THREE.MathUtils.lerp(BUMP_HEIGHT, 0, dt);
    } else {
      // Done
      meshRef.current.position.y = 0;
      bumpRef.current.active = false;
    }
  }
});
```

**Wrap the mesh in the activated item_block branch with the ref:**

The activated item_block render (lines 27-41 in Block.tsx) currently returns a RigidBody with a mesh. Add `ref={meshRef}` to the mesh and wrap the useFrame logic so it only runs for item_block type:

```typescript
if (type === "item_block" && activated) {
  return (
    <RigidBody type="fixed" position={position} colliders="cuboid" /* ... */>
      <mesh ref={meshRef} castShadow receiveShadow>
        <boxGeometry args={[1, 1, 1]} />
        <meshStandardMaterial color="#555555" roughness={0.9} metalness={0} />
      </mesh>
    </RigidBody>
  );
}
```

Note: The useFrame hook must be placed at the component level (not inside a conditional). Use the `type === "item_block"` check inside the useFrame callback to skip when not applicable.

## Testing

### Manual Tests -- Screen Shake
1. Destroy a block with the ball -- brief subtle shake
2. Get hit by damage -- stronger shake
3. Shake should decay smoothly (no sudden stop)
4. Multiple rapid shakes (e.g. destroying several blocks) -- strongest shake wins

### Manual Tests -- Item Block Bump
1. Hit an item_block from below -- block mesh should visually bump up ~0.15 units and settle back
2. Bump animation should take ~180ms total (60ms up, 120ms down)
3. Coins pop out at the same time as the bump
4. Already-activated item_block does not bump again

### Manual Tests -- Hit-Stop
1. Take damage -- physics should freeze for ~40ms then resume
2. The freeze should be barely perceptible (40ms = ~2.5 frames) but adds "weight" to damage
3. Other entities (coins, projectiles) also freeze during hit-stop (they use the same physics world)

### Edge Cases
- Shake during look-up offset -- both should combine without fighting
- Shake with 0 intensity -- should be a no-op
- Multiple item_blocks hit in rapid succession -- each bumps independently
