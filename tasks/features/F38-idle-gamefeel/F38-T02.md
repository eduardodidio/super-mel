## User Story

As a player, I want to see floating "zzz" letters above Mel when she lies down, so it is clear she has fallen asleep and the idle animations feel polished and cute.

## Objective

1. Add a "zzz" effect type to EffectSprite.tsx
2. Add zzz spawn logic to EffectManager.tsx when entering `lie_down` state (repeating while in lie_down)
3. Wire EffectManager into GameScene3D.tsx (it exists but is not imported anywhere)

## Dev Notes

### 1. EffectSprite.tsx -- Add ZzzEffect component

Add "zzz" to the EffectSpriteProps type union:
```typescript
export interface EffectSpriteProps {
  type: "dust" | "stars" | "heart" | "exclamation" | "zzz";
  /* ... */
}
```

Add to EFFECT_CONFIGS:
```typescript
zzz: { duration: 2.0 },
```

Create the ZzzEffect component. Design: three small "Z" letters (using BoxGeometry arranged as a Z shape, or simple small planes) that float upward in sequence with a gentle sway, fading out. A simpler approach is to use three small white spheres that drift upward at staggered intervals to represent a "zzz" pattern:

```typescript
function ZzzEffect({
  position,
  onComplete,
  scale = 1,
}: Omit<EffectSpriteProps, "type">) {
  const groupRef = useRef<THREE.Group>(null);
  const elapsed = useRef(0);
  const config = EFFECT_CONFIGS.zzz;

  // Three "z" particles at staggered delays
  const zData = useRef([
    { delay: 0.0, startY: 0, offsetX: 0 },
    { delay: 0.4, startY: 0, offsetX: 0.15 },
    { delay: 0.8, startY: 0, offsetX: -0.1 },
  ]);

  useFrame((_, delta) => {
    elapsed.current += delta;
    const t = elapsed.current / config.duration;

    if (t >= 1) {
      onComplete();
      return;
    }

    if (!groupRef.current) return;
    const children = groupRef.current.children;

    for (let i = 0; i < zData.current.length; i++) {
      const z = zData.current[i];
      const localT = Math.max(0, (elapsed.current - z.delay) / (config.duration - z.delay));
      if (localT <= 0) {
        // Not started yet -- hide
        children[i].visible = false;
        continue;
      }
      children[i].visible = true;

      // Float upward with gentle sway
      const yOffset = localT * 1.2;
      const xSway = Math.sin(elapsed.current * 3 + i * 2) * 0.08;
      children[i].position.set(
        z.offsetX + xSway,
        z.startY + yOffset,
        0.1
      );

      // Scale: grow in, then stable
      const s = Math.min(localT * 4, 1) * 0.08 * scale * (1 - i * 0.15);
      children[i].scale.setScalar(s);

      // Fade out in last 40%
      const mat = (children[i] as THREE.Mesh).material as THREE.MeshBasicMaterial;
      mat.opacity = localT > 0.6 ? THREE.MathUtils.lerp(0.9, 0, (localT - 0.6) / 0.4) : 0.9;
    }
  });

  return (
    <group ref={groupRef} position={position}>
      {zData.current.map((_, i) => (
        <mesh key={i} visible={false}>
          <boxGeometry args={[0.2, 0.2, 0.02]} />
          <meshBasicMaterial
            color={0xaaddff}
            transparent
            opacity={0.9}
            depthWrite={false}
          />
        </mesh>
      ))}
    </group>
  );
}
```

Add to the switch in `EffectSprite`:
```typescript
case "zzz":
  return <ZzzEffect {...props} />;
```

**Visual note:** The Z shapes are small light-blue boxes (0.2x0.2) that float upward with staggered timing. This gives the classic cartoon "sleeping" look without needing a text sprite.

### 2. EffectManager.tsx -- Add zzz spawn on lie_down

The EffectManager already has state-change detection (`stateChanged` + `prevStateRef`). Add:

```typescript
// --- Zzz: when entering lie_down ---
if (stateChanged && playerState === "lie_down") {
  spawnEffect("zzz", [playerX, playerY + 0.8, 0.1]);
}
```

Also add a recurring zzz spawn while in lie_down (every 2.5s):

```typescript
// Add a ref for zzz timer
const zzzTimerRef = useRef(0);

// In useFrame, after the stateChanged block:
if (playerState === "lie_down") {
  zzzTimerRef.current += delta;
  if (zzzTimerRef.current >= 2.5) {
    zzzTimerRef.current = 0;
    spawnEffect("zzz", [playerX, playerY + 0.8, 0.1]);
  }
} else {
  zzzTimerRef.current = 0;
}
```

### 3. Wire EffectManager into GameScene3D.tsx

EffectManager.tsx is fully implemented but never imported. To wire it:

**Import:**
```typescript
import { EffectManager } from "../systems/EffectManager";
```

**Track Mel's state for EffectManager.** The EffectManager needs `playerState`, `playerGrounded`, `playerVelX`. These are internal to Mel.tsx. Options:
- Add new callback props to Mel to expose state
- Use a shared ref

**Recommended approach:** Add an `onStateUpdate` callback to MelProps:
```typescript
interface MelProps {
  /* existing ... */
  onStateUpdate?: (state: string, grounded: boolean, velX: number) => void;
}
```

In Mel.tsx, call it at the end of useFrame:
```typescript
onStateUpdate?.(stateMachine.current.state, grounded.current, vel.x);
```

In GameScene3D.tsx, add refs to capture the data:
```typescript
const melStateRef = useRef({ state: "idle", grounded: true, velX: 0 });
const [melState, setMelState] = useState({ state: "idle", grounded: true, velX: 0 });

const handleStateUpdate = useCallback((state: string, grounded: boolean, velX: number) => {
  melStateRef.current = { state, grounded, velX };
}, []);
```

Use a useFrame or interval to sync the ref to state (to avoid re-renders every frame):
```typescript
// Sync melState at lower frequency (use a simple approach: update state when state name changes)
```

Actually, a simpler approach: since EffectManager runs in useFrame and reads props, we can pass refs directly. But EffectManager currently takes plain values. **Simplest integration:** make EffectManager accept refs.

**Revised approach:** Refactor EffectManager props to accept a ref object:
```typescript
export interface EffectManagerProps {
  playerRef: React.RefObject<{ x: number; y: number; state: string; grounded: boolean; velX: number }>;
}
```

Or keep it simple and just use a single state object ref from Mel:

Add to MelProps:
```typescript
stateRef?: React.MutableRefObject<{ state: string; grounded: boolean; velX: number }>;
```

Mel.tsx writes to it each frame. GameScene3D creates the ref and passes it to both Mel and EffectManager. EffectManager reads from the ref in useFrame.

**This is the cleanest approach.** Let the developer choose between callback vs ref -- both work. The key constraint is: EffectManager must read Mel's current AnimState, grounded, and velX each frame.

**Render EffectManager in GameScene3D's JSX:**
```typescript
<EffectManager
  playerX={playerPosRef.current.x}
  playerY={playerPosRef.current.y}
  playerState={melStateRef.current.state}
  playerGrounded={melStateRef.current.grounded}
  playerVelX={melStateRef.current.velX}
/>
```
