# Task F38-T01 -- Idle Thresholds + Wait/Affection States

**Feature:** F38
**Wave:** 0
**Type:** frontend (game logic)
**Depends on:** (none)
**Status:** planned

## User Story

As a player, I want Mel to sit down after 5 seconds idle (not 8), lie down after 12 seconds (not 16), look impatient after staring up for 3 seconds, and show affection when picking up a heart, so that Mel feels like a living character with personality.

## Objective

1. Adjust idle thresholds in AnimationStateMachine: >5s -> sit, >12s -> lie_down
2. Add `wait` AnimState that triggers after lookingUp for >3s continuously
3. Add `affection` AnimState as a one-shot (0.6s) triggered by heart collection
4. Register `wait` and `affection` animation definitions in SpriteAnimator.ts
5. Wire the new AnimInput fields in Mel.tsx and GameScene3D.tsx

## Testing

### Manual Tests
1. Stand still for 5s -- Mel should transition to `sit` animation
2. Stand still for 12s -- Mel should transition to `lie_down` animation
3. Hold up arrow for >3s -- Mel should transition from `look_up` to `wait` animation
4. Release up arrow from `wait` -- Mel should return to `idle`
5. Collect a heart item -- Mel should briefly play `affection` animation (~0.6s)
6. Collect a heart while already in `affection` -- should not interrupt (one-shot)
7. Get damaged during `affection` -- damage should still override (higher priority)
8. Attack from `wait` or `sit` state -- should work (canStartAttack updated)

### Edge Cases
- `wait` only triggers while grounded and lookingUp -- going airborne resets
- `affection` is non-interruptible only during its 0.6s duration (via ONE_SHOT mechanism)
- Moving interrupts sit/lie_down immediately (idleTime resets to 0)
- If heart is collected while airborne, affection should still trigger (not blocked by grounded check)
