# Task F38-T03 -- Camera Lookahead in Facing Direction

**Feature:** F38
**Wave:** 0
**Type:** frontend (camera)
**Depends on:** (none)
**Status:** planned

## User Story

As a player, I want the camera to subtly shift in the direction Mel is facing so I can see more of the terrain ahead, making platforming feel responsive and giving me better visibility of upcoming obstacles.

## Objective

Add a camera lookahead offset in Mel's facing direction to CameraRig.tsx. The offset should smoothly lerp to avoid jarring snaps when Mel turns around.

## Dev Notes

### CameraRig.tsx changes

**Add a new prop for facing direction:**
```typescript
interface CameraRigProps {
  /* existing ... */
  facingRight?: boolean;
  lookaheadX?: number; // units to look ahead in facing direction, default 1.5
}
```

**Add a smoothed lookahead ref:**
```typescript
const lookaheadRef = useRef(0);
```

**In useFrame, compute and apply the lookahead offset:**

After the existing lookOffset computation (line 32-33), add:
```typescript
// Smooth lookahead in facing direction
const targetLookahead = (facingRight ?? true) ? (lookaheadX ?? 1.5) : -(lookaheadX ?? 1.5);
lookaheadRef.current = THREE.MathUtils.lerp(lookaheadRef.current, targetLookahead, lerpSpeed);
```

**Apply the lookahead to the goal position and lookAt target:**

The existing code computes `targetX` and `targetY` from deadzone logic, then builds `goalPos`. Add the lookahead to the X component:

```typescript
const goalPos = new THREE.Vector3(
  targetX + offset[0] + lookaheadRef.current,   // <-- add lookahead
  targetY + offset[1] + lookOffsetRef.current,
  offset[2]
);
camera.position.lerp(goalPos, lerpSpeed);
camera.lookAt(
  targetX + offset[0] + lookaheadRef.current,   // <-- add lookahead
  targetY + offset[1] + lookOffsetRef.current,
  0
);
```

### GameScene3D.tsx changes

**Pass `facingRight` to CameraRig:**
```typescript
<CameraRig
  targetRef={melTracker}
  offset={[0, 3, 18]}
  lerpSpeed={0.08}
  deadzone={{ x: 2, y: 1.5 }}
  isLookingUp={isLookingUp}
  lookUpOffset={5}
  facingRight={facingRightRef.current}
  lookaheadX={1.5}
/>
```

Note: `facingRightRef` already exists in GameScene3D.tsx (line 44) and is already updated in `handlePositionUpdate` (lines 58-61). However, since CameraRig runs in useFrame and `facingRightRef.current` is a ref value, the prop will always reflect the latest value.

**Important consideration:** The `facingRight` prop passed to CameraRig is read from `facingRightRef.current` which changes every frame. Since CameraRig uses useFrame internally (not re-render), this works correctly -- CameraRig reads the prop value on every frame.

Actually, since React props don't update on ref changes without a re-render, a cleaner approach is to pass the ref itself:

```typescript
interface CameraRigProps {
  /* existing ... */
  facingRightRef?: React.RefObject<boolean>;
  lookaheadX?: number;
}
```

Then in CameraRig's useFrame:
```typescript
const isFacingRight = facingRightRef?.current ?? true;
const targetLookahead = isFacingRight ? (lookaheadX ?? 1.5) : -(lookaheadX ?? 1.5);
```

And in GameScene3D:
```typescript
<CameraRig
  /* ... */
  facingRightRef={facingRightRef}
  lookaheadX={1.5}
/>
```

This avoids the ref-to-prop timing issue entirely.

### Tuning constants

- **Lookahead distance:** 1.5 world units. This is subtle but noticeable. The existing deadzone.x is 2.0, so the lookahead is smaller than the deadzone -- it nudges the view without fighting the deadzone.
- **Lerp speed:** Use the same `lerpSpeed` (0.08) for the lookahead interpolation. This ensures smooth turning transitions. At 60fps, `lerp(current, target, 0.08)` takes about 30 frames (~0.5s) to reach 90% of the target, which feels natural.

## Testing

### Manual Tests
1. Walk right -- camera should be slightly offset to show more of the right side
2. Walk left -- camera should smoothly shift to show more of the left side
3. Stand still -- camera lookahead remains in the last facing direction
4. Rapid direction changes (left-right-left) -- camera should smoothly interpolate without snapping
5. Look up while facing right -- both lookUp offset and lookahead should combine naturally
6. Fly upward -- lookahead should still track horizontal facing direction

### Edge Cases
- Game start: camera initializes with correct lookahead for default facing (right)
- Very fast movement: lookahead stays smooth (lerp prevents overshoot)
- Deadzone interaction: lookahead adds to the deadzone position, not fighting it
