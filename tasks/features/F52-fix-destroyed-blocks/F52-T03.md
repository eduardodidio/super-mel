# Task F52-T03 -- Integration Testing and Edge Case Verification

**Feature:** F52
**Wave:** 1
**Type:** test
**Depends on:** F52-T01, F52-T02
**Status:** done

## User Story

As a developer, I need to verify that block destruction works correctly in all
scenarios -- projectile hits, dig, chunk boundaries, rapid multi-destruction, and
level mode -- so that I can be confident the fix is complete and does not regress.

## Objective

Create a comprehensive test suite that validates block destruction end-to-end.
Cover the core destruction path, edge cases, and verify that no Rapier colliders
persist after destruction.

## Dev Notes

### Test Scenarios

#### 1. Projectile Destroys Destructible Block
- Spawn a `wood` or `glass` block
- Fire a projectile at it
- Assert: block mesh is removed from the R3F scene tree
- Assert: no `RigidBody` with the block's position remains in the Rapier world
- Assert: `BlockParticles` effect renders at the block's former position
- Assert: `getBlockAt(x, y, z)` returns `null`

#### 2. Projectile Hits Non-Destructible Block
- Spawn a `stone` or `iron` block
- Fire a projectile at it
- Assert: block remains in the scene (mesh + collider)
- Assert: projectile explodes (does not pass through)
- Assert: no `BlockParticles` spawned

#### 3. Dig Destroys Block Below
- Position Mel on top of a `dirt` or `sand` block
- Trigger dig (Down + Z)
- Assert: block is removed from scene
- Assert: collider is removed
- Assert: particle effect plays

#### 4. Chunk Boundary Destruction
- Destroy a block at the edge of a chunk (x = chunkIndex * 16 or x = chunkIndex * 16 + 15)
- Assert: block is removed correctly
- Assert: adjacent chunk's blocks are unaffected
- Assert: if the chunk is later unloaded and reloaded (player moves away and back),
  the destroyed block remains destroyed (since `destroyedBlocks` state persists)

#### 5. Multiple Simultaneous Destructions
- Fire projectile through multiple blocks in quick succession (or script it)
- Assert: all destroyed blocks are removed
- Assert: all particle effects play
- Assert: no blocks are "left behind"

#### 6. Block Destruction in Level Mode
- Load a level from `LevelDataV2` with destructible blocks
- Destroy a block
- Assert: same behavior as infinite mode -- block removed, particles play

#### 7. Item Block Activation (Regression Guard)
- Hit an `item_block` with a projectile
- Assert: it is NOT destroyed, but activated (gray texture, coins pop)
- Assert: collider remains active (cannot walk through it)

#### 8. Destroy Effect Cleanup
- Destroy a block
- Wait > 1 second
- Assert: `BlockParticles` component has unmounted (onComplete fired)
- Assert: `destroyEffects` state array no longer contains the effect

### Implementation

**File: `packages/frontend/src/game/__tests__/blockDestruction.test.tsx`**

Use `@testing-library/react` with R3F's test utilities. Since R3F and Rapier
are hard to unit test directly, focus on:

1. **ChunkRenderer unit test:** Mock the chunks state, call `destroyBlock` via
   the imperative handle, and assert that the filtered output excludes the
   destroyed block.

2. **BlockParticles unit test:** Render `BlockParticles` with a mock `onComplete`,
   advance time with `act(() => jest.advanceTimersByTime(1100))`, and assert
   `onComplete` was called.

3. **Manual test checklist** (documented in this file) for scenarios that require
   the full game loop (Rapier physics, projectile collision).

### Manual Test Checklist

Run the game locally (`pnpm dev`) and verify each scenario:

- [ ] Shoot a wood block -> block disappears, particles burst, can walk through
- [ ] Shoot a glass block -> same
- [ ] Shoot a stone block -> block stays, projectile explodes against it
- [ ] Dig a dirt block -> block removed, particles appear
- [ ] Dig a sand block -> same
- [ ] Hit an item_block -> NOT destroyed, turns gray, coins pop
- [ ] Destroy block at chunk edge -> no visual glitch, block gone
- [ ] Rapid-fire 3+ blocks -> all disappear
- [ ] Destroy block, walk through its position -> no invisible wall
- [ ] Destroy block, observe particles fade after ~1s
- [ ] Open console -> no React warnings or Rapier errors related to destruction
