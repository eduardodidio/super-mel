# Task F52-T02 -- Clean Up Block.tsx Dead Code and Extract Particle Effects

**Feature:** F52
**Wave:** 0
**Type:** refactor
**Depends on:** none
**Status:** done

## User Story

As a player, when I destroy a block, I want to see a particle burst effect at the block's
position so that the destruction feels satisfying and complete.

## Objective

Remove the dead `destroyed` state and unused `onDestroy` callback from `Block.tsx`. Extract
the `BlockParticles` component so it can be spawned independently by `ChunkRenderer` when
a block is destroyed. Ensure particle effects still play correctly after the block is
removed from the scene.

## Dev Notes

### Current Problem

`Block.tsx` has dead code:
- `const [destroyed, setDestroyed] = useState(false);` -- `setDestroyed` is never called.
- `onDestroy?: () => void` prop -- accepted but never invoked internally by the Block.
- The `if (destroyed) return <BlockParticles .../>` path is unreachable.

When ChunkRenderer filters out a destroyed block (via the `.filter()` in the render),
the entire `<Block>` component unmounts. This means `BlockParticles` is NEVER rendered
because the Block unmounts before `destroyed` could be set to true.

### Fix Strategy

1. **Remove dead code from `Block.tsx`:**
   - Remove the `destroyed` state (`useState(false)`)
   - Remove the `onDestroy` prop from `BlockProps`
   - Remove the `if (destroyed) return <BlockParticles .../>` branch
   - The `Block` component should only render the block mesh + RigidBody

2. **Export `BlockParticles` from `Block.tsx`:**
   - Make `BlockParticles` a named export (currently it's a private function in `Block.tsx`)
   - It already works standalone -- it takes `position` and `type` props

3. **Add destruction effects state to `ChunkRenderer.tsx`:**
   - Add a state array for active destruction effects:
     ```typescript
     interface DestroyEffect {
       key: string;
       position: [number, number, number];
       type: Exclude<BlockType, "empty">;
     }

     const [destroyEffects, setDestroyEffects] = useState<DestroyEffect[]>([]);
     ```
   - When `destroyBlock` is called, add a destroy effect entry:
     ```typescript
     setDestroyEffects(prev => [
       ...prev,
       { key: `fx-${key}`, position: [x, y, z], type: blockTypeAtPosition }
     ]);
     ```
   - To know the block type, look it up from `chunks` before marking it destroyed.
     Since `destroyBlock` runs synchronously (the ref check happens before state update),
     we can query the chunk data to find the block type.

4. **Render effects in ChunkRenderer JSX:**
   ```tsx
   {destroyEffects.map(fx => (
     <BlockParticles
       key={fx.key}
       position={fx.position}
       type={fx.type}
       onComplete={() => {
         setDestroyEffects(prev => prev.filter(e => e.key !== fx.key));
       }}
     />
   ))}
   ```

5. **Add `onComplete` callback to `BlockParticles`:**
   - Currently `BlockParticles` sets `visible` to false after 1 second but never cleans
     up. Add an `onComplete` prop that is called when the particle animation finishes,
     so ChunkRenderer can remove it from the effects array.
   - Modify the `if (lifeRef.current > 1)` branch:
     ```typescript
     if (lifeRef.current > 1) {
       setVisible(false);
       onComplete?.();
       return;
     }
     ```
   - Guard against multiple calls with a ref:
     ```typescript
     const completedRef = useRef(false);
     // ...
     if (lifeRef.current > 1 && !completedRef.current) {
       completedRef.current = true;
       setVisible(false);
       onComplete?.();
       return;
     }
     ```

6. **Look up block type in `destroyBlock`:**
   The imperative handle needs to find the block type before destroying it. Use the
   existing chunk data:
   ```typescript
   destroyBlock(x, y, z) {
     const key = `${x},${y},${z}`;
     if (destroyedKeysRef.current.has(key)) return false;

     // Find block type for particle effect
     let blockType: Exclude<BlockType, "empty"> | null = null;
     for (const chunk of chunks.values()) {
       for (const b of chunk.blocks) {
         if (b.x === x && b.y === y && b.z === z) {
           blockType = b.type;
           break;
         }
       }
       if (blockType) break;
     }

     destroyedKeysRef.current.add(key);
     setDestroyedBlocks(prev => {
       const next = new Set(prev);
       next.add(key);
       return next;
     });

     // Spawn particle effect
     if (blockType) {
       setDestroyEffects(prev => [
         ...prev,
         { key: `fx-${key}`, position: [x, y, z], type: blockType! }
       ]);
     }

     onBlockDestroyed?.(x, y);
     return true;
   },
   ```

   **Note:** This block-type lookup accesses `chunks` from the closure. Since
   `useImperativeHandle` depends on `chunks`, it will have the latest value. Add
   `chunks` to the dependency array of `useImperativeHandle`.

7. **Remove `onDestroy` from ChunkRenderer render JSX:**
   The `onDestroy` prop is no longer needed on `<Block>`. Remove the
   `onDestroy={() => handleDestroy(...)}` from the Block render.
   Also remove the `handleDestroy` callback since it becomes unused.
