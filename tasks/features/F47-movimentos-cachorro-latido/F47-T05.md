## User Story

As a developer, I want the animation state machine and sprite system to support bark, dig, and sniff states so that Mel's visual representation reflects the new dog abilities with correct transitions and sprite frames.

## Objective

Add `bark`, `dig`, and `sniff` animation states to `AnimationStateMachine.ts`. Add corresponding animation definitions to `SpriteAnimator.ts`. These are placeholder animations using existing sprites until dedicated sprites are created.

### 4. Handle bark event in existing attack flow

The `bark_fire` event is already checked in `Mel.tsx` (line ~260):
```typescript
if (event === "bark_fire" && lastEvent.current !== "bark_fire") {
  onAttackFrame?.();
}
```

This fires `onAttackFrame` which currently spawns a projectile. For bark, we need a different callback. Solutions:
- **Check the current anim state:** If `animName === "bark"`, call `onBarkFrame?.()` instead of `onAttackFrame?.()`.
- Add a new prop `onBarkFrame?: () => void` to MelProps.

```typescript
if (event === "bark_fire" && lastEvent.current !== "bark_fire") {
  if (stateMachine.current.state === "bark") {
    onBarkFrame?.();
  } else {
    onAttackFrame?.();
  }
}
```

### Gotchas

- The `bark` state shares the `bark_fire` event name with the existing attack animation. The differentiation is done by checking the ASM state (`bark` vs `attack_prep`/`attack_1` etc.), NOT the event name alone.
- `sniff` is a looping state (like `sit` or `crouch`), NOT one-shot. It continues as long as the input conditions hold.
- `dig` is one-shot and returns to `crouch` (since the player is still holding down). If the player releases down during dig, the one-shot finishes and transitions to `idle` via the normal priority chain.
- `bark` is higher priority than `attack` so that pressing X while Z is available doesn't conflict. They use different keys anyway, but the priority ordering is a safety net.
- All three new states must have entries in `ANIM_NAME_MAP` or `getAnimName()` will return "idle".
- When adding `barkPressed`, `digging`, `sniffing` to `AnimInput`, ensure all callers provide them (currently only Mel.tsx creates AnimInput -- check for other usages).
