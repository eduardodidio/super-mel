# Task F47-T02 -- Dig Logic + BLOCK_PROPERTIES Diggable Flag (Cavar)

**Feature:** F47
**Wave:** 0
**Type:** frontend + shared
**Depends on:** none (standalone subsystem)
**Status:** planned

## User Story

As a player, I want to crouch and attack on dirt or sand blocks so that Mel digs through them, removing the block and revealing bones or coins hidden underneath, opening up underground exploration.

## Objective

Add a `diggable` flag to `BLOCK_PROPERTIES` in the shared types, create dig detection logic that checks the block below Mel when crouching + attacking, and wire it to remove the block via ChunkRenderer's `destroyBlock`. Spawn bone/coin drops from destroyed blocks.

### 2. Create `packages/frontend/src/game/systems/DigSystem.ts`

A pure logic module (no React component needed) with a single function:

```typescript
import { BLOCK_PROPERTIES, type BlockType } from "@super-mel/shared";

export interface DigResult {
  success: boolean;
  blockX: number;
  blockY: number;
  blockZ: number;
  dropType: "bone" | "coin" | "none";
}

/**
 * Attempt to dig the block below Mel.
 * @param melX - Mel's world X position
 * @param melY - Mel's world Y position
 * @param getBlockAt - function to query block type at grid position
 * @returns DigResult indicating success and what dropped
 */
export function tryDig(
  melX: number,
  melY: number,
  getBlockAt: (x: number, y: number, z: number) => BlockType | null
): DigResult {
  // The block directly below Mel's feet
  const blockX = Math.round(melX);
  const blockY = Math.round(melY) - 1; // one block below
  const blockZ = 0;

  const blockType = getBlockAt(blockX, blockY, blockZ);

  if (!blockType || blockType === "empty") {
    return { success: false, blockX, blockY, blockZ, dropType: "none" };
  }

  const props = BLOCK_PROPERTIES[blockType as Exclude<BlockType, "empty">];
  if (!props || !props.diggable) {
    return { success: false, blockX, blockY, blockZ, dropType: "none" };
  }

  // Determine drop
  const roll = Math.random();
  let dropType: "bone" | "coin" | "none";
  if (roll < 0.3) {
    dropType = "bone";  // 30% chance bone
  } else if (roll < 0.6) {
    dropType = "coin";  // 30% chance coin
  } else {
    dropType = "none";  // 40% chance nothing
  }

  return { success: true, blockX, blockY, blockZ, dropType };
}
```

### 3. Modify `packages/frontend/src/game/systems/ChunkRenderer.tsx`

Add `getBlockAt` to the `ChunkRendererHandle` imperative handle:
```typescript
export interface ChunkRendererHandle {
  destroyBlock: (x: number, y: number, z: number) => boolean;
  activateBlock: (x: number, y: number, z: number) => boolean;
  getBlockAt: (x: number, y: number, z: number) => BlockType | null; // NEW
}
```

Implementation inside `useImperativeHandle`:
```typescript
getBlockAt(x, y, z) {
  const key = `${x},${y},${z}`;
  if (destroyedBlocks.current.has(key)) return null;
  // Search chunks for the block at this position
  for (const chunk of chunks.values()) {
    for (const b of chunk.blocks) {
      if (b.x === x && b.y === y && b.z === z) {
        return b.type;
      }
    }
  }
  return null;
}
```

Note: This is O(n) over blocks in visible chunks. For the current game scale (~4 chunks, ~64 blocks each = ~256 blocks), this is fine. If performance becomes an issue, a Map index can be added later.

### 4. Wire dig in `Mel.tsx` or `GameScene3D.tsx`

The dig trigger is: `crouching && ctrl.shoot && cooldown_expired`. The logic lives in GameScene3D (not Mel.tsx) because it needs access to ChunkRenderer's handle.

In GameScene3D, add a dig detection in the existing projectile/attack flow:
- When `ctrl.shoot` fires while `crouching`:
  1. Call `tryDig(melX, melY, chunkRef.current.getBlockAt)`.
  2. If `result.success`:
     - Call `chunkRef.current.destroyBlock(result.blockX, result.blockY, result.blockZ)`.
     - Spawn drops based on `result.dropType` (coins via `spawnDroppedCoins`, bones as score points for now).
     - Apply screen shake (small: 0.06, 0.1).
  3. If `!result.success`: do nothing (the regular attack/projectile fires as normal).

Important: When dig succeeds, do NOT fire the projectile. The attack is consumed by the dig action. Check dig first, then fall through to projectile if dig failed.

Add a dig cooldown of 0.4s to prevent rapid digging (separate from attack cooldown).

### Gotchas

- Adding `diggable` to BLOCK_PROPERTIES changes the type signature. All existing entries must get `diggable: false` to compile.
- The dig check must happen BEFORE the projectile spawn in the attack flow. If dig succeeds, suppress the projectile.
- `Math.round(melY) - 1` targets the block directly below Mel's feet. Mel's collider center is at her feet level roughly, so this should be correct. Test with different block alignments.
- The `getBlockAt` query must respect already-destroyed blocks (check `destroyedBlocks` set).
- Dig should not work while airborne -- only when `grounded && crouching`.
- Sand and dirt blocks were previously non-destructible (`destructible: false`). Dig bypasses the `destructible` check entirely -- it uses the separate `diggable` flag. The Bola do Infinito still cannot destroy sand/dirt (it checks `destructible`).
