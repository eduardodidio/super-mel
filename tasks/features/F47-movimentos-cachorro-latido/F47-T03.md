# Task F47-T03 -- Boomerang Ball / Buscar (Projectile Return)

**Feature:** F47
**Wave:** 0
**Type:** frontend
**Depends on:** none (standalone Projectile modification)
**Status:** planned

## User Story

As a player, I want the Bola do Infinito to return to Mel like a boomerang after reaching its max range so that it collects coins on the way back, making the ball feel like a dog's fetch toy and adding a coin-gathering strategy.

## Objective

Modify `Projectile.tsx` to support a return path after reaching max range. When returning, the ball reverses direction, homes slightly toward Mel, and collects coins it passes through. Modify `ProjectileManager.tsx` to pass the return flag and handle return-path coin collection.

## Dev Notes

### 1. Modify `packages/frontend/src/game/entities/Projectile.tsx`

Add a `returnMode` prop to `ProjectileProps`:
```typescript
interface ProjectileProps {
  id: string;
  startPosition: [number, number, number];
  direction?: number;
  onHit: (id: string, targetName?: string, blockPos?: { x: number; y: number; z: number }) => void;
  onExpire: (id: string) => void;
  returnMode?: boolean; // NEW: if true, ball returns after max range
  playerPosRef?: React.RefObject<{ x: number; y: number }>; // NEW: needed for return homing
  onReturnCoinCollect?: (id: string) => void; // NEW: coin collection on return
}
```

Behavior changes when `returnMode === true`:

**Phase 1 -- Outbound (existing behavior):**
- Ball travels forward at `SPEED` in `direction` for `LIFETIME` seconds (10 blocks).
- On block hit: explode and destroy block as before (no change).

**Phase 2 -- Return (new):**
- When `lifeRef.current >= LIFETIME` and NOT exploding:
  - Instead of calling `onExpire(id)`, enter return phase (`returning.current = true`).
  - Reverse direction. Add slight Y homing toward Mel: `dy = (playerY - ballY) * 0.5`.
  - Ball travels back at `SPEED * 0.8` (slightly slower for visual readability).
  - Ball is now a sensor that does NOT interact with blocks (disable block collision on return).
  - Ball DOES interact with coins (DroppedCoin, Coin entities) -- on intersection with name "coin" or "dropped-coin", call `onReturnCoinCollect(id)`.
  - Return lifetime: another `LIFETIME` seconds (10 blocks distance). After that, expire for real.
  - Visual: on return, the bark_wave sprite plays in reverse (or just use the same frames), and the glow color shifts to slightly bluer (`#FFA500` -> `#FFD700`).

**Return collision handling:**
```typescript
if (returning.current) {
  // Ignore block hits on return
  if (otherName.startsWith("block-")) return;

  // Collect coins
  if (otherName === "coin" || otherName === "dropped-coin") {
    onReturnCoinCollect?.(id);
  }

  // Self-destruct when reaching Mel (within 1.5 units)
  const playerX = playerPosRef?.current?.x ?? 0;
  const playerY = playerPosRef?.current?.y ?? 0;
  const ballPos = rbRef.current?.translation();
  if (ballPos) {
    const dist = Math.sqrt(
      (ballPos.x - playerX) ** 2 + (ballPos.y - playerY) ** 2
    );
    if (dist < 1.5) {
      onExpire(id); // Mel "catches" the ball
      return;
    }
  }
}
```

**Return movement:**
```typescript
if (returning.current) {
  const ballPos = rbRef.current.translation();
  const playerX = playerPosRef?.current?.x ?? ballPos.x;
  const playerY = playerPosRef?.current?.y ?? ballPos.y;

  const dx = playerX - ballPos.x;
  const dy = playerY - ballPos.y;
  const dist = Math.sqrt(dx * dx + dy * dy);

  if (dist > 0.5) {
    const nx = dx / dist;
    const ny = dy / dist;
    const speed = SPEED * 0.8;
    rbRef.current.setLinvel({ x: nx * speed, y: ny * speed, z: 0 }, true);
  }
}
```

### Gotchas

- The returning ball must NOT destroy blocks. This is critical. On return, block collisions are ignored.
- The returning ball must be a sensor (it already is in outbound mode). Ensure `sensor` stays true during return.
- Coin collection on return requires the Coin/DroppedCoin RigidBody names to be known. Check what names they use:
  - `Coin.tsx`: check if RigidBody has `name="coin"` -- if not, add it.
  - `DroppedCoin.tsx`: check if RigidBody has `name="dropped-coin"` -- if not, add it.
- Multiple projectiles can be in-flight. Each independently tracks its own outbound/return state.
- When the ball hits a block on outbound, it still explodes (no return). Return only happens when it reaches max range without hitting anything.
- The homing toward Mel is gentle (normalized direction * speed), not instant teleportation. If Mel moves far away, the ball gracefully curves toward her.
- `returnMode` is hardcoded to `true` for now. A future feature (F44 Shop) will make it a purchasable upgrade. The default should be easy to change to `false`.
- Add a slight visual indicator for the return: the point light color shifts from `#FFD700` to `#87CEEB` (light blue) during return.
