# Task F50-T02 -- Backend Validation + Auth Gate for Custom Assets

**Feature:** F50
**Wave:** 0
**Type:** backend
**Depends on:** F37 (level routes already validate v2 data)

## User Story

As the system, I need to validate custom assets on the backend to prevent abuse (oversized images, too many assets, invalid data URIs) and restrict uploads to logged-in accounts only.

## Objective

1. Create `customAssetValidation.ts` with a validation function for the `customAssets` array.
2. Update `levelValidation.ts` to include `"custom"` in `VALID_BLOCK_TYPES` and `"custom_block_asset"` in `VALID_ENTITY_TYPES`, and call the new custom asset validator.
3. Update `levels.ts` routes to reject saves with custom assets from guest/anonymous players.

## Dev Notes

### 1. Create `packages/backend/src/validation/customAssetValidation.ts`

```typescript
interface CustomAssetValidationResult {
  valid: boolean;
  errors: string[];
}

export function validateCustomAssets(assets: unknown): CustomAssetValidationResult {
  const errors: string[] = [];

  if (!Array.isArray(assets)) {
    return { valid: false, errors: ["customAssets must be an array"] };
  }

  if (assets.length > 10) {
    errors.push("customAssets exceeds maximum of 10 assets per level");
  }

  for (let i = 0; i < assets.length; i++) {
    const a = assets[i];
    if (!a || typeof a !== "object") {
      errors.push(`customAssets[${i}] must be an object`);
      continue;
    }
    const asset = a as Record<string, unknown>;

    // id
    if (typeof asset.id !== "string" || asset.id.length === 0) {
      errors.push(`customAssets[${i}].id must be a non-empty string`);
    }

    // name
    if (typeof asset.name !== "string" || asset.name.length === 0 || asset.name.length > 20) {
      errors.push(`customAssets[${i}].name must be 1-20 characters`);
    }

    // dataUri
    if (typeof asset.dataUri !== "string") {
      errors.push(`customAssets[${i}].dataUri must be a string`);
    } else {
      if (!asset.dataUri.startsWith("data:image/")) {
        errors.push(`customAssets[${i}].dataUri must start with "data:image/"`);
      }
      if (asset.dataUri.length > 15000) {
        errors.push(`customAssets[${i}].dataUri exceeds 15KB limit (${asset.dataUri.length} chars)`);
      }
    }
  }

  return { valid: errors.length === 0, errors };
}
```

### 3. Update `packages/backend/src/routes/levels.ts`

In the POST and PUT handlers, after migration and validation, check if the level has custom assets and the player is a guest:

```typescript
// After validation passes:
const hasCustomAssets = levelData.customAssets && levelData.customAssets.length > 0;
if (hasCustomAssets) {
  // Check if creator is logged in (non-guest)
  const isGuest = !creatorId || creatorId.startsWith("local-") || creatorId.startsWith("dev-");
  // For dev users: allow (they are known users)
  // For local- users: deny (anonymous)
  if (creatorId.startsWith("local-")) {
    return reply.status(403).send({
      error: "Crie uma conta para usar imagens personalizadas",
    });
  }

  // For DB users, check isGuest flag
  try {
    const player = await prisma.player.findUnique({ where: { id: creatorId } });
    if (player?.isGuest) {
      return reply.status(403).send({
        error: "Crie uma conta para usar imagens personalizadas",
      });
    }
  } catch {
    // If DB is down, allow save (graceful degradation)
  }
}
```

Note: `dev-*` users (like `dev-rafa`) are allowed to upload because they are known dev accounts.

### Gotchas

- The `dev-*` prefix users should be ALLOWED to upload (they are the game developers/testers). Only `local-*` prefix and `isGuest: true` DB users should be blocked.
- The body limit for Fastify defaults to 1 MB (`bodyLimit` option). With 10 assets at 15 KB each = 150 KB of custom assets + the rest of the level data, we stay well under. No need to change the body limit.
- Do NOT import the `CustomAsset` type from shared in the validation file -- keep it as runtime checks on `unknown` (same pattern as `levelValidation.ts`).
