# Task F50-T01 -- Shared Types: CustomAsset + LevelDataV2 Extension + Migration Update

**Feature:** F50
**Wave:** 0
**Type:** shared
**Depends on:** F37 (LevelDataV2 types already exist)
**Status:** done

## User Story

As a developer, I need the shared type definitions for custom assets so that the frontend and backend can agree on the data shape for uploaded images embedded in levels.

## Objective

Extend `packages/shared/src/types.ts` with the `CustomAsset` interface, add `"custom"` to `BlockType`, add `customAssets` to `LevelDataV2`, and update the migration function to handle the new field.

## Dev Notes

### 1. Add to `packages/shared/src/types.ts`

Add the `CustomAsset` interface:
```typescript
export interface CustomAsset {
  id: string;        // unique ID within the level, e.g. "custom-1695000000"
  name: string;      // user-given name, max 20 chars
  dataUri: string;   // base64 data URI, e.g. "data:image/png;base64,..."
}
```

Add `"custom"` to the `BlockType` union:
```typescript
export type BlockType =
  | "empty"
  | "stone"
  // ... existing types ...
  | "item_block"
  | "custom";       // <-- NEW
```

Add `"custom"` to `BLOCK_PROPERTIES`:
```typescript
custom: { solid: true, destructible: false, dangerous: false, platform: false },
```

Add `customAssets` to `LevelDataV2`:
```typescript
export interface LevelDataV2 {
  version: 2;
  grid: BlockCell[][];
  width: number;
  height: number;
  entities: EntityData[];
  theme?: BackgroundTheme;
  missions?: Mission[];
  customAssets?: CustomAsset[];  // <-- NEW: max 10 per level
}
```

Add `"custom_block_asset"` to the `EntityType` union:
```typescript
export type EntityType =
  | "coin"
  | "heart"
  // ... existing types ...
  | "enemy"
  | "custom_block_asset";  // <-- NEW: links a grid position to a customAssetId
```

### 2. Update `packages/shared/src/levelMigration.ts`

In the `migrateLevelData` function, ensure that `customAssets` defaults to `[]` when converting v1 data to v2, and when a v2 object lacks the field:

```typescript
// After creating the v2 object:
if (!result.customAssets) {
  result.customAssets = [];
}
```

### 3. Update `ENTITY_TYPES` constant

Add `"custom_block_asset"` to the `ENTITY_TYPES` array.

### Relevant Files

- `packages/shared/src/types.ts` -- main types file
- `packages/shared/src/levelMigration.ts` -- migration function

### Gotchas

- The `"custom"` block type must NOT break existing `BLOCK_VISUALS` lookups in `BlockTextures3D.ts`. That file uses `Exclude<BlockType, "empty">` as key type. Adding `"custom"` to `BlockType` means `BlockTextures3D.ts` must also add a `custom` entry to `BLOCK_VISUALS` -- that happens in T04. Until T04 is done, the type will exist but `getBlockMaterials("custom")` will crash. This is fine because T04 is in Wave 1 and runs before any rendering code uses `"custom"`.
- The `VALID_BLOCK_TYPES` set in `levelValidation.ts` also needs `"custom"` -- that happens in T02.
- The `VALID_ENTITY_TYPES` set in `levelValidation.ts` needs `"custom_block_asset"` -- that also happens in T02.
