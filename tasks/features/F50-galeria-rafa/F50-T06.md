# Task F50-T06 -- Game Rendering: Custom Blocks + Signs in Gameplay

**Feature:** F50
**Wave:** 2
**Type:** frontend
**Depends on:** F50-T01 (types), F50-T04 (CustomTextureCache), F50-T05 (editor wiring -- for the data flow)
**Status:** done

## User Story

As a player loading a community level that has custom blocks and signs with drawings, I need to see the creator's uploaded images rendered on the blocks and signs during gameplay.

## Objective

Update the gameplay rendering pipeline to support custom blocks and sign entities with custom images. When `GameScene3D` or `ChunkRenderer` encounters a `"custom"` block type, it looks up the associated `custom_block_asset` entity to find the `customAssetId`, then uses `CustomTextureCache` to get the texture. Sign entities with `customAssetId` render the custom image on a billboard plane.

### 2. Update `packages/frontend/src/game/scenes/GameScene3D.tsx`

When rendering blocks from `SceneObjects`, check for `type === "custom"`:

```typescript
import { getCustomBlockMaterials } from "../systems/BlockTextures3D";
import { preloadCustomTextures } from "../systems/CustomTextureCache";

// On level load:
if (sceneObjects.customAssets.length > 0) {
  preloadCustomTextures(sceneObjects.customAssets);
}

// In block rendering:
if (block.type === "custom") {
  const assetId = sceneObjects.customBlockAssets.get(`${block.x},${block.y}`);
  const asset = sceneObjects.customAssets.find(a => a.id === assetId);
  if (asset) {
    const materials = getCustomBlockMaterials(asset.dataUri);
    // Use these materials for this block mesh
  } else {
    // Fallback: use default "custom" block visual (purple)
    const materials = getBlockMaterials("custom" as any);
  }
}
```

### 4. Update Block Component (if using Block.tsx)

If `ChunkRenderer.tsx` handles block rendering separately from `GameScene3D.tsx`, ensure it also supports the `"custom"` block type. Since custom blocks only exist in user-created levels (not in procedural chunks), the `ChunkGenerator` never produces `"custom"` blocks. ### 5. Cleanup on Level Unload

When leaving a level (back to menu, restart, etc.), call `disposeCustomTextures()` and `disposeCustomBlockMaterials()` to free GPU memory. Hook this into the existing cleanup in `GameScene3D` or in the scene transition logic.

```typescript
import { disposeCustomTextures } from "../systems/CustomTextureCache";
import { disposeCustomBlockMaterials } from "../systems/BlockTextures3D";

// In cleanup / useEffect return:

  disposeCustomTextures();
  disposeCustomBlockMaterials();
};
```

### Gotchas

- Custom blocks only exist in level-mode play (LevelDataV2). The infinite/procedural mode (`ChunkGenerator`) never generates `"custom"` blocks. No changes needed in `ChunkGenerator.ts`.
- If a `custom` block at position (x,y) has no matching `custom_block_asset` entity (data corruption or asset was deleted), render the purple fallback color. Do NOT crash.
- The sign entity type `"sign"` is already in the `EntityType` union but `Sign.tsx` does not exist yet. F50 creates a minimal custom sign rendering path. If B-10 is implemented later, it should extend this.
- Texture disposal is critical. Each level load creates new textures; without disposal, GPU memory leaks. The cleanup must run on scene change.
- `sceneObjectsToChunks()` wraps blocks into chunks for ChunkRenderer. Custom blocks pass through as regular blocks with `type: "custom"`. The ChunkRenderer needs to handle this type by looking up the custom texture.
