# Task F50-T03 -- ImageUploader Component (Client-Side Resize + Pixelation)

**Feature:** F50
**Wave:** 1
**Type:** frontend
**Depends on:** F50-T01 (CustomAsset type)
**Status:** done

## User Story

As a level creator, I want to upload a PNG or JPG image in the editor, see a pixelated 64x64 preview, name it, and confirm -- so it becomes a custom asset I can place in my level.

## Objective

Create the `ImageUploader` React component that handles file selection, canvas-based 64x64 resizing with nearest-neighbor pixelation, a preview, a name input, and a confirm callback that returns a `CustomAsset` object.

## Dev Notes

### 1. Create `packages/frontend/src/game/editor/ImageUploader.tsx`

Props:
```typescript
interface ImageUploaderProps {
  onConfirm: (asset: CustomAsset) => void;
  onCancel: () => void;
  existingCount: number;  // how many custom assets already exist (for limit display)
}
```

### 2. File Selection

- Use a hidden `<input type="file" accept="image/png,image/jpeg" />` triggered by a styled button
- On file selected, read with `FileReader.readAsDataURL()`
- Show a loading state while processing

### 3. Canvas Resize + Pixelation

Once the data URL is loaded:

```typescript
const img = new Image();
img.onload = () => {
  const canvas = document.createElement("canvas");
  canvas.width = 64;
  canvas.height = 64;
  const ctx = canvas.getContext("2d")!;

  // Nearest-neighbor scaling for pixel art look
  ctx.imageSmoothingEnabled = false;

  // Draw the source image scaled to 64x64
  ctx.drawImage(img, 0, 0, 64, 64);

  // Get the pixelated result as a data URI
  const pixelatedDataUri = canvas.toDataURL("image/png");

  setPreviewUri(pixelatedDataUri);
};
img.src = rawDataUrl;
```

The key is `imageSmoothingEnabled = false` which gives the blocky Minecraft-style look.

### 4. Preview + Name Input

Show:
- The pixelated 64x64 preview image at a larger display size (e.g., 128x128 with `image-rendering: pixelated` CSS)
- A text input for the asset name (max 20 chars, default to filename without extension, truncated)
- "Confirmar" button (creates the `CustomAsset` and calls `onConfirm`)
- "Cancelar" button (calls `onCancel`)
- Asset count indicator: "Imagens: {existingCount}/10"

### 5. CustomAsset Creation

On confirm:
```typescript
const asset: CustomAsset = {
  id: `custom-${Date.now()}`,
  name: nameInput.trim().slice(0, 20),
  dataUri: previewUri,  // the pixelated 64x64 PNG data URI
};
onConfirm(asset);
```

### 6. Validation Before Confirm

- If name is empty, show inline error "Digite um nome"
- If `existingCount >= 10`, disable the confirm button and show "Limite de 10 imagens atingido"
- If the resulting data URI is > 15000 chars (extremely unlikely for 64x64 PNG, but safety), show "Imagem muito grande"

### 7. Styling

Use inline styles consistent with EditorUI (dark theme, monospace font, `rgba(0,0,0,0.85)` overlay background). The component is rendered as a modal overlay on top of the editor.

### Relevant Files

- `packages/frontend/src/game/scenes/EditorUI.tsx` -- styling reference (dark theme, monospace)
- `packages/shared/src/types.ts` -- `CustomAsset` interface (from T01)

### Gotchas

- Must handle EXIF orientation on mobile photos. Using canvas `drawImage` already normalizes orientation in modern browsers, but test with a rotated phone photo.
- The `image-rendering: pixelated` CSS property ensures the preview stays crisp when scaled up. Fallback: `image-rendering: crisp-edges` for older browsers.
- File size of the original image does not matter -- only the 64x64 output size matters. A 10 MB photo becomes a 2-5 KB pixelated PNG.
- Do NOT use any external image processing library. Canvas API is sufficient and adds zero dependencies.

## Testing
