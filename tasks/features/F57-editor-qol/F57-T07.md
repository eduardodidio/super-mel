# Task F57-T07 -- Drag-Move Selection

**Feature:** F57
**Wave:** 2
**Type:** frontend / integration
**Depends on:** F57-T03 (undo/redo wiring), F57-T04 (selection rect rendering + move callbacks)
**Status:** planned

## User Story

As a level creator, I want to drag a selected group of blocks and entities to a new position so that I can rearrange my level layout without having to delete and recreate structures.

## Objective

Implement drag-move for selected content: when the user clicks and drags inside an active selection rectangle, the selected blocks and entities move with the cursor as a ghost preview. On release, the move is committed -- blocks/entities are removed from old positions and added at new positions. The operation is undoable.

## Dev Notes

### 1. Move initiation (already set up in T04)

In `EditorScene3D`, when the user clicks inside an existing selection rectangle with the select tool active, `onStartMove(x, y)` is called (set up in T04). This records the drag start position in the `useEditorSelection` hook.

### 2. Move state in useEditorSelection

The `startMove(x, y)` method in `useEditorSelection` (T02) should:
- Set `mode = "moving"`
- Record the move origin (drag start grid position)
- Set `ghostOrigin` to the current cursor position

`updateMovePosition(x, y)` updates `ghostOrigin` as the cursor moves.

### 3. Ghost preview during move

EditorWrapper computes ghost blocks/entities during move, similar to paste:

```typescript
const moveGhostData = useMemo(() => {
  if (selection.state.mode !== "moving" || !selection.state.rect || !selection.state.ghostOrigin) {
    return { ghostBlocks: null, ghostEntities: null };
  }

  const rect = selection.state.rect;
  const ghost = selection.state.ghostOrigin;
  // The move origin is stored in the hook. Compute delta.
  const moveOrigin = selection.getMoveOrigin(); // { x, y } of where drag started
  if (!moveOrigin) return { ghostBlocks: null, ghostEntities: null };

  const dx = ghost.x - moveOrigin.x;
  const dy = ghost.y - moveOrigin.y;

  // Get blocks in selection (current Z only)
  const selectedBlocks = blocks.filter(b =>
    b.z === currentZ &&
    b.x >= rect.x1 && b.x <= rect.x2 &&
    b.y >= rect.y1 && b.y <= rect.y2
  );

  // Get entities in selection
  const selectedEntities = entities.filter(e =>
    e.x >= rect.x1 && e.x <= rect.x2 &&
    e.y >= rect.y1 && e.y <= rect.y2
  );

  const ghostBlocks = selectedBlocks.map(b => ({
    ...b,
    x: b.x + dx,
    y: b.y + dy,
  }));

  const ghostEntities = selectedEntities.map(e => ({
    ...e,
    x: e.x + dx,
    y: e.y + dy,
  }));

  return { ghostBlocks, ghostEntities };
}, [selection.state, blocks, entities, currentZ]);
```

Merge this with the paste ghost data when passing to EditorScene3D:

```typescript
const combinedGhostBlocks = ghostData.ghostBlocks ?? moveGhostData.ghostBlocks;
const combinedGhostEntities = ghostData.ghostEntities ?? moveGhostData.ghostEntities;
```

### 4. Visual: Dim original blocks during move

While dragging (mode === "moving"), the blocks at their original positions should render dimmer to indicate they will be moved. Add an `isBeingMoved` flag to the block rendering in EditorScene3D:

```typescript
const isBeingMoved = selectionMode === "moving" && selectionRect &&
  b.z === currentZ &&
  b.x >= selectionRect.x1 && b.x <= selectionRect.x2 &&
  b.y >= selectionRect.y1 && b.y <= selectionRect.y2;
```

When `isBeingMoved`, render with reduced opacity (e.g., 0.3) to show they are "picked up".

### 5. Commit move on pointer up

When `onPointerUp` fires during `mode === "moving"` (handled in T04), it calls `onCommitMove()`. This callback in EditorWrapper:

```typescript
const handleCommitMove = useCallback(() => {
  const rect = selection.state.rect;
  const moveOrigin = selection.getMoveOrigin();
  const ghost = selection.state.ghostOrigin;

  if (!rect || !moveOrigin || !ghost) {
    selection.cancelMove();
    return;
  }

  const dx = ghost.x - moveOrigin.x;
  const dy = ghost.y - moveOrigin.y;

  // If no movement, just cancel
  if (dx === 0 && dy === 0) {
    selection.cancelMove();
    return;
  }

  // Push undo snapshot before move
  pushSnapshot(getCurrentSnapshot());

  // Remove blocks from original positions (current Z layer only)
  // Add blocks at new positions
  setBlocks(prev => {
    const inSelection = prev.filter(b =>
      b.z === currentZ &&
      b.x >= rect.x1 && b.x <= rect.x2 &&
      b.y >= rect.y1 && b.y <= rect.y2
    );
    const outside = prev.filter(b =>
      !(b.z === currentZ &&
        b.x >= rect.x1 && b.x <= rect.x2 &&
        b.y >= rect.y1 && b.y <= rect.y2)
    );
    const moved = inSelection.map(b => ({
      ...b,
      x: b.x + dx,
      y: b.y + dy,
    }));
    // Remove any existing blocks at the destination positions
    const movedPositions = new Set(moved.map(b => `${b.x},${b.y},${b.z}`));
    const outsideFiltered = outside.filter(b => !movedPositions.has(`${b.x},${b.y},${b.z}`));
    return [...outsideFiltered, ...moved];
  });

  // Move entities
  setEntities(prev => {
    const inSelection = prev.filter(e =>
      e.x >= rect.x1 && e.x <= rect.x2 &&
      e.y >= rect.y1 && e.y <= rect.y2
    );
    const outside = prev.filter(e =>
      !(e.x >= rect.x1 && e.x <= rect.x2 &&
        e.y >= rect.y1 && e.y <= rect.y2)
    );
    const moved = inSelection.map(e => ({
      ...e,
      x: e.x + dx,
      y: e.y + dy,
    }));
    return [...outside, ...moved];
  });

  // Update spawn point if it was in the selection
  if (spawnPoint.x >= rect.x1 && spawnPoint.x <= rect.x2 &&
      spawnPoint.y >= rect.y1 && spawnPoint.y <= rect.y2) {
    setSpawnPoint({ x: spawnPoint.x + dx, y: spawnPoint.y + dy });
  }

  markDataChanged();

  // Update selection rect to the new position
  const newRect = {
    x1: rect.x1 + dx,
    y1: rect.y1 + dy,
    x2: rect.x2 + dx,
    y2: rect.y2 + dy,
  };
  selection.commitMove(blocks, entities, ghost.x, ghost.y);
  // The hook should update the internal rect to newRect
}, [selection, blocks, entities, currentZ, spawnPoint, pushSnapshot, getCurrentSnapshot, markDataChanged]);
```

### 6. Update selection rect after move

After the move is committed, the selection rectangle should update to the new position (the moved area). The `commitMove` method in `useEditorSelection` should set `rect` to the new offset position and return to `"selected"` mode.

Add a `setRect` capability or have `commitMove` accept the delta and internally update:
```typescript
// In useEditorSelection's commitMove:
setRect(prev => prev ? {
  x1: prev.x1 + dx,
  y1: prev.y1 + dy,
  x2: prev.x2 + dx,
  y2: prev.y2 + dy,
} : null);
setMode("selected");
```

### 7. Cancel move

If the user presses Escape during a move, `selection.cancelMove()` is called (handled in T05). This resets the mode to `"selected"` with the original rect, and the ghost preview disappears. No blocks are moved.

### 8. Move origin tracking

Add a `getMoveOrigin()` method to `useEditorSelection` that returns the stored move start position. This is needed to compute the delta.

Alternatively, expose `moveOrigin` as part of `SelectionState`:
```typescript
export interface SelectionState {
  // ... existing fields ...
  moveOrigin: { x: number; y: number } | null;
}
```

### Gotchas

- **Spawn point sync:** If the spawn entity is within the selection and gets moved, `spawnPoint` state must also update. Check for this explicitly.
- **Entity singletons during move:** Unlike paste, move does not create duplicates -- it relocates. So spawn/goal entities CAN be moved.
- **Destination collision:** Blocks at the destination are overwritten (same as paste). This is by design -- move is a "stamp" operation.
- **Same position = no-op:** If the user releases without moving (dx === 0, dy === 0), cancel the move silently (no undo snapshot, no state change).
- **Selection rect follows the move:** After moving, the selection rect updates to the new position, so the user can continue to move or operate on the same selection.
- **Blocks outside current Z:** Only blocks on the current Z layer are moved. Blocks on other Z layers at the same (x,y) remain untouched.
- **Large moves:** Moving a 20x10 selection across the grid should be smooth. The ghost preview uses the same block count as the selection, which is bounded by the selection area.
