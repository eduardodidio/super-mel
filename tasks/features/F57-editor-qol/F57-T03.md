# Task F57-T03 -- Wire Undo/Redo into EditorWrapper

**Feature:** F57
**Wave:** 1
**Type:** frontend / integration
**Depends on:** F57-T01 (useEditorHistory hook)
**Status:** planned

## User Story

As a level creator, I want the undo/redo system to automatically capture every change I make in the editor so that pressing Ctrl+Z reliably reverses my last action.

## Objective

Integrate the `useEditorHistory` hook into `EditorWrapper.tsx` so that every mutating action (place block, remove block, place entity, remove entity, set spawn) automatically pushes a snapshot before execution, and undo/redo correctly restores the editor state.

### 2. Create a snapshot helper

Add a helper function that builds the current snapshot from state:

```typescript
const getCurrentSnapshot = useCallback(() => ({
  blocks: [...blocks],
  entities: [...entities],
  spawnPoint: { ...spawnPoint },
}), [blocks, entities, spawnPoint]);
```

**Important:** This uses the current state values. Because React state updates are batched, call `getCurrentSnapshot()` BEFORE calling any state setters in the same handler.

### 3. Wrap every mutating handler

Each handler that changes blocks, entities, or spawnPoint must call `pushSnapshot(getCurrentSnapshot())` as its first action. Modify these handlers:

- **handlePlaceBlock** (line 65): Add `pushSnapshot(getCurrentSnapshot())` at the top, before `setBlocks`.
- **handleRemoveBlock** (line 101): Add `pushSnapshot(getCurrentSnapshot())` at the top.
- **handleSetSpawn** (line 106): Add `pushSnapshot(getCurrentSnapshot())` at the top.
- **handlePlaceEntity** (line 116): Add `pushSnapshot(getCurrentSnapshot())` at the top.
- **handleRemoveEntity** (line 157): Add `pushSnapshot(getCurrentSnapshot())` at the top.

Note: The drag-painting behavior (pointer move while dragging) calls `handlePlaceBlock` or `handleRemoveBlock` on every new grid cell. This means every painted cell gets its own snapshot. This is intentional -- undo reverses one cell at a time, which is the expected behavior for a paint tool.

**Optimization consideration:** If undo-per-cell feels too granular, a future enhancement could batch drag operations into a single undo entry by pushing snapshot only on `pointerDown` and not on subsequent drag moves. However, for this task, keep it simple: one snapshot per mutation call.

### 4. Implement undo/redo handlers

```typescript
const handleUndo = useCallback(() => {
  const snapshot = undo(getCurrentSnapshot());
  if (snapshot) {
    setBlocks(snapshot.blocks);
    setEntities(snapshot.entities);
    setSpawnPoint(snapshot.spawnPoint);
    markDataChanged();
  }
}, [undo, getCurrentSnapshot, markDataChanged]);

const handleRedo = useCallback(() => {
  const snapshot = redo(getCurrentSnapshot());
  if (snapshot) {
    setBlocks(snapshot.blocks);
    setEntities(snapshot.entities);
    setSpawnPoint(snapshot.spawnPoint);
    markDataChanged();
  }
}, [redo, getCurrentSnapshot, markDataChanged]);
```

### Gotchas

- **React state batching:** `getCurrentSnapshot()` must be called BEFORE any `setBlocks`/`setEntities` calls in the same handler. React 18 batches state updates, so the snapshot would capture stale state if called after a setter.
- **Drag painting granularity:** Each cell painted during a drag gets its own snapshot. This is correct but verbose. Users can hold Ctrl+Z to rapidly undo. A batched approach could be a future optimization.
- **Entity deduplication:** When restoring from a snapshot, directly replace the entire arrays -- do not merge. `setBlocks(snapshot.blocks)` replaces all blocks.
- **markDataChanged on undo/redo:** Undo/redo must call `markDataChanged()` because the level data has changed (clear-check invalidation).
- **Spawn entity sync:** When restoring `spawnPoint`, also ensure the spawn entity in the `entities` array is consistent. The snapshot stores both, so full restore is correct.
