# Task F57-T06 -- Copy/Paste with Ghost Preview

**Feature:** F57
**Wave:** 2
**Type:** frontend / integration
**Depends on:** F57-T03 (undo/redo wiring), F57-T04 (selection rect rendering), F57-T05 (keyboard shortcuts)
**Status:** planned

## User Story

As a level creator, I want to copy a selected region and paste it at a different location so that I can quickly duplicate patterns, platforms, and obstacles without rebuilding them manually.

## Objective

Wire the copy/paste flow end-to-end: Ctrl+C captures selected content to clipboard, Ctrl+V enters paste mode with a ghost preview following the cursor, and clicking commits the paste. The paste operation pushes an undo snapshot and merges new blocks/entities into the editor state.

## Dev Notes

### 1. Copy flow (already stubbed in T05)

The `handleCopy` in EditorWrapper calls `selection.copySelection(blocks, entities)`. The `useEditorSelection` hook (T02) stores the clipboard internally. The `copySelection` method filters blocks within `selectionRect` (on `currentZ` layer), stores them with positions relative to `(x1, y1)`, and does the same for entities.

Ensure `currentZ` is passed to `copySelection`:

```typescript
const handleCopy = useCallback(() => {
  if (!selection.state.hasSelection) return;
  selection.copySelection(blocks, entities, currentZ);
}, [selection, blocks, entities, currentZ]);
```

Update the `copySelection` signature in `useEditorSelection` to accept `currentZ`:
```typescript
copySelection: (blocks: EditorBlock[], entities: EntityData[], currentZ: number) => void;
```

### 2. Paste mode activation

When `Ctrl+V` is pressed and clipboard has content, `handlePaste` calls `selection.startPaste()`. This sets `mode = "pasting"`.

### 3. Ghost preview during paste

When in paste mode, the cursor position determines where the paste will land. EditorWrapper computes the ghost blocks/entities by offsetting clipboard contents by the current cursor position:

```typescript
const ghostData = useMemo(() => {
  if (selection.state.mode !== "pasting" || !selection.state.clipboard || !selection.state.ghostOrigin) {
    return { ghostBlocks: null, ghostEntities: null };
  }

  const { clipboard, ghostOrigin } = selection.state;
  const ghostBlocks = clipboard.blocks.map(b => ({
    ...b,
    x: b.x + ghostOrigin.x,
    y: b.y + ghostOrigin.y,
    z: currentZ,
  }));
  const ghostEntities = clipboard.entities.map(e => ({
    ...e,
    x: e.x + ghostOrigin.x,
    y: e.y + ghostOrigin.y,
  }));

  return { ghostBlocks, ghostEntities };
}, [selection.state, currentZ]);
```

Pass `ghostData.ghostBlocks` and `ghostData.ghostEntities` to `EditorScene3D` (which renders them as wireframe previews, per T04).

### 4. Paste position update

In `EditorScene3D`, when `selectionMode === "pasting"`, pointer move calls `onPastePositionUpdate(x, y)`. In EditorWrapper, this callback updates the ghost origin via `selection.updatePastePosition(x, y)`.

### 5. Commit paste on click

When the user clicks during paste mode, commit the paste:

```typescript
const handleCommitPaste = useCallback(() => {
  if (selection.state.mode !== "pasting" || !selection.state.ghostOrigin) return;

  const result = selection.commitPaste(selection.state.ghostOrigin.x, selection.state.ghostOrigin.y);
  if (!result) return;

  // Push undo snapshot before paste
  pushSnapshot(getCurrentSnapshot());

  // Merge pasted blocks (overwrite existing at same positions)
  setBlocks(prev => {
    const newPositions = new Set(result.blocks.map(b => `${b.x},${b.y},${b.z}`));
    const filtered = prev.filter(b => !newPositions.has(`${b.x},${b.y},${b.z}`));
    return [...filtered, ...result.blocks];
  });

  // Merge pasted entities (replace at same position+type)
  setEntities(prev => {
    const newPositions = new Set(result.entities.map(e => `${e.type},${e.x},${e.y}`));
    const filtered = prev.filter(e => !newPositions.has(`${e.type},${e.x},${e.y}`));
    return [...filtered, ...result.entities];
  });

  markDataChanged();
}, [selection, pushSnapshot, getCurrentSnapshot, markDataChanged]);
```

### 6. Cancel paste

Pressing Escape during paste mode calls `selection.cancelPaste()` (already handled in T05's handleEscape). This clears the ghost preview and returns to `"selected"` mode (or `"idle"` if there was no prior selection).

### 7. Paste mode in EditorScene3D click handling

In `EditorScene3D`, when in paste mode and the user clicks:

```typescript
// In onPointerDown:
if (selectionMode === "pasting") {
  onCommitPaste?.();
  return;
}
```

### 8. Multiple pastes

After committing a paste, the clipboard is NOT cleared. The user can paste multiple times. After committing, the mode returns to "selected" (or "idle"). Pressing Ctrl+V again enters paste mode again with the same clipboard content.

### 9. Paste does not remove source

Paste is a copy operation, not a cut. The original blocks/entities remain in place. If the user wants cut behavior, they copy, then delete the selection.

### Gotchas

- **Block overlap on paste:** When pasting, blocks at overlapping positions replace existing blocks. Use a Set of position keys to filter out collisions before merging.
- **Entity handling on paste:** Singleton entities (spawn, goal) should NOT be pasted if they already exist. Filter them out of the paste result to avoid duplicates. Or better: skip spawn/goal entities from clipboard entirely during `copySelection`.
- **Z layer for pasted blocks:** Pasted blocks use the current `currentZ` layer, not the original Z from the clipboard. This allows cross-layer pasting.
- **Ghost origin updates:** The ghost origin must update every frame as the cursor moves. Use `selection.updatePastePosition` called from the pointer move handler.
- **Paste at negative coordinates:** If the cursor is near (0,0) and the clipboard has blocks at positive offsets, some pasted blocks may end up at negative coordinates. Allow this -- the editor already supports arbitrary coordinates.
- **Performance:** Ghost preview re-renders on every cursor move. Since it is a `useMemo` dependent on `ghostOrigin`, React will recompute only when the cursor grid position changes (integer snap), not on every pixel move.
