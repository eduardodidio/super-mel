# Task F57-T01 -- useEditorHistory Hook (Undo/Redo Snapshot Stack)

**Feature:** F57
**Wave:** 0
**Type:** frontend / editor
**Depends on:** None (standalone hook)
**Status:** planned

## User Story

As a level creator, I want to undo and redo my actions in the editor so that I can experiment freely without fear of losing work or having to manually rebuild mistakes.

## Objective

Create a standalone React custom hook `useEditorHistory` that manages a snapshot-based undo/redo stack for the editor state (`blocks`, `entities`, `spawnPoint`). The hook provides `pushSnapshot`, `undo`, `redo`, and state accessors.

### 2. Types

```typescript
interface EditorBlock {
  type: Exclude<BlockType, "empty">;
  x: number;
  y: number;
  z: number;
}

export interface EditorSnapshot {
  blocks: EditorBlock[];
  entities: EntityData[];
  spawnPoint: { x: number; y: number };
}

export interface EditorHistoryState {
  canUndo: boolean;
  canRedo: boolean;
  undoCount: number;
  redoCount: number;
}
```

### 3. Hook API

```typescript
export function useEditorHistory(maxSnapshots?: number): {
  /** Push a snapshot BEFORE a mutating action. Returns void. */
  pushSnapshot: (snapshot: EditorSnapshot) => void;

  /** Undo: pop from undo stack, push current to redo, return the restored snapshot. Returns null if nothing to undo. */
  undo: (currentState: EditorSnapshot) => EditorSnapshot | null;

  /** Redo: pop from redo stack, push current to undo, return the restored snapshot. Returns null if nothing to redo. */
  redo: (currentState: EditorSnapshot) => EditorSnapshot | null;

  /** Clear all history (e.g., on level load) */
  clear: () => void;

  /** Current history state for UI */
  state: EditorHistoryState;
}
```

### 4. Implementation Details

- Use `useRef` for the undo and redo stacks to avoid unnecessary re-renders on every push. Use a `useState` counter that increments on push/undo/redo to trigger UI updates for the `state` object.
- `maxSnapshots` defaults to 50. When the undo stack exceeds this limit, drop the oldest entry (shift from front of array).
- **Deep clone:** Use `JSON.parse(JSON.stringify(snapshot))` for deep cloning. The data is plain objects/arrays with no functions or circular refs, so structured clone is unnecessary.
- `pushSnapshot(snapshot)`: deep-clone and push to undo stack. **Clear the redo stack** (new action invalidates redo history). Trim undo stack if over limit.
- `undo(currentState)`: if undo stack is empty, return null. Pop last entry from undo stack, push deep-clone of `currentState` to redo stack, return the popped snapshot.
- `redo(currentState)`: if redo stack is empty, return null. Pop last entry from redo stack, push deep-clone of `currentState` to undo stack, return the popped snapshot.
- `clear()`: reset both stacks to empty.

### Gotchas

- The hook itself does NOT manage the editor state (blocks/entities/spawnPoint). It only stores snapshots. The consumer (EditorWrapper) is responsible for calling `pushSnapshot` before mutations and restoring state from `undo`/`redo` results.
- Deep cloning via JSON parse/stringify is fast enough for the expected data sizes (< 2000 blocks, < 100 entities). Profile only if users report lag on undo.
- The `state` object must be reactive (triggers re-render) so that undo/redo buttons can show disabled state. Use a version counter in useState.
- Do not store `customAssets` in snapshots -- they are not part of the level geometry and changes to them are rare (upload/delete).
