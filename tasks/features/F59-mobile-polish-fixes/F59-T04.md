# F59-T04 — Fullscreen Mobile (Esconder Header do Browser)

**Wave:** 0
**Type:** frontend
**Depends on:** (none)
**Status:** planned

## User Story

As a mobile player, I want the game to take up the entire screen without browser chrome visible, so that I have maximum screen real estate for gameplay.

## Objective

Make the game run in true fullscreen on mobile: update viewport meta tags, fix CSS viewport height, handle safe areas, and trigger Fullscreen API on first user interaction.

## Dev Notes

**Current state (index.html line 5):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, user-scalable=no" />
```
Missing `viewport-fit=cover` for notch-aware layout.

**Current CSS (index.html line ~17):**
```css
#root { width: 100vw; height: 100vh; }
```
`100vh` on mobile includes the browser address bar height, causing content to be pushed below visible area.

**iOS meta tags already present (lines 8-10):**
```html
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent" />
<meta name="apple-mobile-web-app-title" content="Super Mel" />
```
These are correct for iOS standalone mode but don't help in-browser.

- `packages/frontend/index.html` — viewport meta + root CSS

## Implementation Details

1. **Update viewport meta tag in index.html:**
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover" />
   ```

2. **Fix CSS viewport height in index.html:**
   ```css
   html, body {
     margin: 0;
     padding: 0;
     overflow: hidden;
     position: fixed;           /* prevents iOS bounce scroll */
     width: 100%;
     height: 100%;
   }

   #root {
     width: 100vw;
     height: 100dvh;            /* dynamic viewport height (modern) */
     height: 100vh;             /* fallback for older browsers (must come FIRST) */
   }
   ```
   Note: put `100vh` first as fallback, then `100dvh` overrides in supporting browsers.

3. **Add safe-area CSS:**
   ```css
   #root {
     padding: env(safe-area-inset-top, 0) env(safe-area-inset-right, 0) env(safe-area-inset-bottom, 0) env(safe-area-inset-left, 0);
     box-sizing: border-box;
   }
   ```

4. **Trigger Fullscreen API on first user interaction (mobile only):**
   In the root game component or App.tsx, add a one-time fullscreen request:
   ```tsx
   useEffect(() => {
     const isMobile = /Android|iPhone|iPad|iPod/i.test(navigator.userAgent);
     if (!isMobile) return;

     const requestFS = () => {
       const el = document.documentElement;
       const rfs = el.requestFullscreen
         || (el as any).webkitRequestFullscreen
         || (el as any).msRequestFullscreen;
       if (rfs) rfs.call(el).catch(() => {});
       document.removeEventListener('pointerdown', requestFS);
     };

     document.addEventListener('pointerdown', requestFS, { once: true });
     return () => document.removeEventListener('pointerdown', requestFS);
   }, []);
   ```

5. **Lock orientation to landscape (optional enhancement):**
   ```tsx
   if (screen.orientation?.lock) {
     screen.orientation.lock('landscape').catch(() => {});
   }
   ```

6. **Verify manifest.json display mode:**
   - Should be `"display": "standalone"` (currently correct)
   - Consider changing to `"display": "fullscreen"` for maximum immersion when installed as PWA

## Acceptance Criteria

- [ ] Browser address bar is not visible during gameplay on Chrome Android
- [ ] Browser address bar is not visible during gameplay on Safari iOS
- [ ] Game fills entire screen including notch area (viewport-fit=cover)
- [ ] No bounce scroll on iOS (html/body fixed position)
- [ ] Content is not hidden behind notch/Dynamic Island (safe-area-inset padding)
- [ ] Fallback works on older browsers (100vh still functional)
- [ ] Desktop layout is not affected (no regression)
- [ ] Diagram `F59-journey.mmd` created

## Testing

**Framework:** Manual testing on mobile devices + Chrome DevTools
**Command:** `cd packages/frontend && npx vite dev --host`

## Test Scenarios

1. **Happy path — Chrome Android:** Open game, tap to start. Browser chrome should hide.
2. **Happy path — Safari iOS:** Open game, tap. Address bar should minimize.
3. **Edge case — notch device:** Test on iPhone with notch. Content should not overlap with notch (safe area padding).
4. **Edge case — rotate device:** Start in portrait, rotate to landscape. Fullscreen maintained.
5. **Edge case — exit/re-enter:** Switch apps and come back. Fullscreen should resume on next tap.
6. **Regression — desktop:** Open in Chrome desktop. No visual changes or unwanted fullscreen.
7. **PWA mode:** Install as PWA, open from home screen. Should be fullscreen without any browser chrome.
