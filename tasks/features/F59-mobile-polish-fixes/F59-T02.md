# F59-T02 — Fix Colisores Invisiveis (Mel Travando)

**Wave:** 0
**Type:** frontend
**Depends on:** (none)
**Status:** planned

## User Story

As a player, I want Mel to move smoothly through the level without getting stuck on invisible barriers, so that the gameplay feels fluid and responsive.

## Objective

Fix non-solid blocks (leaf, water) that incorrectly create sensor colliders, causing Mel to get stuck or have false ground detection on invisible elements.

## Dev Notes

**Root cause:** In `Block.tsx` (line ~103), the collider logic is:
```tsx
sensor={!props.solid && !props.dangerous}
```
This creates a sensor collider for non-solid, non-dangerous blocks (leaf, water). Even though sensors don't physically block, they interfere with Mel's ray-cast ground detection.

**Key files:**
- `packages/frontend/src/game/entities/Block.tsx` — block collider setup (line ~82-108)
- `packages/frontend/src/game/entities/Mel.tsx` — ground detection ray cast (lines ~135-148)
- `packages/shared/src/types.ts` — BLOCK_PROPERTIES definitions (lines ~180-196)

**Block properties from types.ts:**
```
leaf:  { solid: false, destructible: false, dangerous: false, platform: true }
water: { solid: false, destructible: false, dangerous: false }
lava:  { solid: false, destructible: false, dangerous: true }
```

**Current Block.tsx render logic:**
- Background blocks (Z < 0): plain mesh, no physics ✅
- Foreground blocks (Z = 0): RigidBody with `colliders="cuboid"`
  - solid=true blocks: normal collider ✅
  - dangerous=true blocks (lava): sensor collider for damage ✅
  - solid=false, dangerous=false (leaf, water): sensor collider ❌ should have NO collider

**Mel ground detection (Mel.tsx):**
- Uses `world.castRay()` which detects ALL colliders including sensors
- Ray from `pos.y - 0.55` downward, length 0.3
- Can falsely detect ground on leaf/water sensor colliders

Veja `tasks/features/F59-_tmp-brief.md` para contexto completo.

## Implementation Details

1. **In Block.tsx**, change the foreground block rendering logic:
   - If `solid=false && dangerous=false`: render ONLY the visual mesh (no RigidBody, no collider)
   - If `dangerous=true && solid=false` (lava): keep RigidBody with sensor=true
   - If `solid=true`: keep RigidBody with sensor=false (normal collider)

   ```tsx
   // Pseudocode for the new logic:
   const needsPhysics = props.solid || props.dangerous;

   if (!needsPhysics) {
     // Render visual-only mesh (same as background blocks)
     return <mesh ...>{/* texture */}</mesh>;
   }

   // Render with RigidBody
   return (
     <RigidBody type="fixed" sensor={!props.solid && props.dangerous} ...>
       <mesh ...>{/* texture */}</mesh>
     </RigidBody>
   );
   ```

2. **Verify Mel.tsx ground detection:**
   - After removing non-solid block colliders, verify ray cast still works correctly
   - The `castRay` filter flags may need adjustment if sensors are still detected
   - Consider using `QueryFilterFlags` to exclude sensors from ray cast if Rapier supports it

3. **Check for water/leaf gameplay mechanics:**
   - If water blocks need to slow Mel down or leaf blocks need visual pass-through, those mechanics should use overlap detection in Mel.tsx, not block-level sensors
   - Currently no special water/leaf mechanics exist, so removing colliders is safe
