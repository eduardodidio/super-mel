# F59-T03 — Fix Controles Touch Mobile

**Wave:** 0
**Type:** frontend
**Depends on:** (none)
**Status:** planned

## User Story

As a mobile player, I want the on-screen touch buttons to respond reliably to my taps, so that I can actually play the game on my phone.

## Objective

Fix TouchControls3D.tsx to use the modern Pointer Events API (onPointerDown/onPointerUp) instead of onTouchStart/onTouchEnd, add visual feedback, and ensure no event propagation conflicts with the R3F canvas.

## Dev Notes

**Root cause:** `TouchControls3D.tsx` uses only `onTouchStart` and `onTouchEnd` handlers. These can fail on:
- Browsers that implement Pointer Events but don't reliably fire Touch Events
- Chrome DevTools mobile emulation (pointer events only)
- Hybrid touch+mouse devices (Surface, iPad with mouse)
- Event propagation conflicts where the R3F canvas captures touches before buttons

**Key file:** `packages/frontend/src/game/systems/TouchControls3D.tsx`

**Current structure:**
- Buttons defined as `<button>` elements with inline styles
- Handler: `set()` function that updates game input state + calls `e.preventDefault()`
- Container has `touchAction: "none"` and `pointerEvents: "auto"` (good)
- D-pad (4 directions) + A (jump) + B (attack) + C (bark) buttons
- Z-index should be above canvas

**Game input system:** Buttons call `set()` which writes to a shared controls ref (likely `useGameState` or similar input store).

## Implementation Details

1. **Replace touch events with pointer events on ALL buttons:**
   ```tsx
   // Before:
   onTouchStart={(e) => { e.preventDefault(); set('left', true); }}
   onTouchEnd={(e) => { e.preventDefault(); set('left', false); }}

   // After:
   onPointerDown={(e) => { e.preventDefault(); e.stopPropagation(); set('left', true); }}
   onPointerUp={(e) => { e.preventDefault(); e.stopPropagation(); set('left', false); }}
   onPointerLeave={(e) => { set('left', false); }}  // release on leave
   onPointerCancel={(e) => { set('left', false); }}  // release on cancel
   ```

2. **Add onPointerLeave and onPointerCancel** to every button — if the finger slides off a button, it must release. Without this, buttons get "stuck" in pressed state.

3. **Add visual feedback (pressed state):**
   ```tsx
   // Track pressed state for visual feedback
   const [pressed, setPressed] = useState<Record<string, boolean>>({});

   // In button style:
   style={{
     ...baseButtonStyle,
     opacity: pressed[key] ? 0.6 : 0.85,
     transform: pressed[key] ? 'scale(0.9)' : 'scale(1)',
     transition: 'opacity 0.1s, transform 0.1s',
   }}
   ```

4. **CSS hardening on button elements:**
   ```css
   touch-action: manipulation;  /* prevent double-tap zoom */
   user-select: none;           /* prevent text selection */
   -webkit-touch-callout: none; /* prevent iOS callout */
   -webkit-user-select: none;
   ```

5. **Ensure z-index layering:** Buttons container must be above the R3F canvas. Check that the canvas doesn't have a higher z-index or pointer-events that steal events.

6. **Context menu prevention:** Add `onContextMenu={(e) => e.preventDefault()}` to prevent long-press context menu on Android.

## Acceptance Criteria

- [ ] All buttons (D-pad left/right/up/down, A, B, C) respond to taps on Chrome Android
- [ ] All buttons respond to taps on Safari iOS
- [ ] Visual feedback visible when button is pressed (opacity/scale change)
- [ ] Buttons release correctly when finger slides off (onPointerLeave)
- [ ] No "stuck" buttons — pressing and releasing always pairs correctly
- [ ] No accidental zoom/scroll when using touch controls
- [ ] D-pad allows moving while pressing action buttons (multi-touch)
- [ ] Desktop mouse click on buttons also works (regression test)
- [ ] No context menu appears on long-press

## Testing

**Framework:** Manual testing on mobile device + Chrome DevTools mobile emulation
**Command:** `cd packages/frontend && npx vite dev --host` (expose to network for mobile testing)

## Test Scenarios

1. **Happy path — single button:** Tap each button individually. Verify input registers and releases.
2. **Happy path — multi-touch:** Hold right D-pad + tap A (jump while moving). Both inputs register.
3. **Edge case — slide off button:** Press left, slide finger off button. Input must release.
4. **Edge case — rapid taps:** Tap A button rapidly (5+ times/sec). All taps register.
5. **Edge case — long press:** Hold A for 3 seconds. No context menu, input stays held.
6. **Error case — two fingers on same button:** Should not crash or produce duplicate events.
7. **Regression — desktop:** Click buttons with mouse. Still works.
8. **Chrome DevTools emulation:** Toggle device toolbar, tap buttons with emulated touch. Must work.
