# Task F45-T04 -- Infinite Missions Hook + HUD Badges + Mel Level

**Feature:** F45
**Wave:** 1
**Type:** frontend (React hook + UI + state)
**Depends on:** F45-T01 (GameEventBus), F45-T02 (MissionTracker)
**Status:** planned

## User Story

As a player in infinite mode, I want to see 3 active missions with progress bars during gameplay (e.g., "collect 50 coins: 23/50"), earn coin rewards when I complete them, and see my Mel level grow over time, so that every run feels purposeful.

## Objective

1. Define a pool of 10+ predefined infinite mission definitions.
2. Create `useInfiniteMissions` hook that manages 3 active missions, tracks progress via MissionTracker + GameEventBus, rewards coins, rotates completed missions, and persists state.
3. Add Mel level tracking (XP from completed missions).
4. Display active missions as compact badges in HUD3D during infinite mode.
5. Display Mel level in the menu.
6. Persist state in localStorage and sync via useProgressSync.

### 2. useInfiniteMissions.ts (`packages/frontend/src/game/hooks/useInfiniteMissions.ts`)

**Persisted state shape (localStorage key `supermel_infinite_missions`):**

```typescript
interface InfiniteMissionsState {
  activeMissionIds: string[];  // 3 active mission IDs from pool
  completedIds: string[];      // all completed mission IDs (for rotation)
  melXp: number;               // total XP earned
  melLevel: number;            // derived: Math.floor(melXp / 500) + 1 (or similar formula)
}
```

**Hook API:**

```typescript
interface UseInfiniteMissionsResult {
  activeMissions: MissionStatus[];
  melLevel: number;
  melXp: number;
  xpToNextLevel: number;
}

export function useInfiniteMissions(
  active: boolean  // true when scene === "playing" and gameMode === "infinite"
): UseInfiniteMissionsResult;
```

**Key behaviors:**

- On `run_start` (infinite mode): load active missions from localStorage, create MissionTracker for those 3 missions, subscribe to GameEventBus.
- During gameplay: tracker accumulates events. Hook periodically checks completion (on each relevant event, not every frame).
- On mission completion mid-run:
  - Award coin reward (call `useGameState.getState().addCoin()` N times, or better, add a `addCoins(n)` helper or just update totalCoins directly)
  - Add XP to melXp, recalculate melLevel
  - Emit a custom event or set state to trigger MissionToast (T05)
  - Mark mission as completed in `completedIds`
  - Rotate in a new mission from pool (pick randomly from those not in `activeMissionIds` and not recently completed)
  - Save to localStorage
- On `run_end`: save final state to localStorage.

**Mel level formula:**

```typescript
const XP_PER_LEVEL = 500;
function calculateLevel(xp: number): number {
  return Math.floor(xp / XP_PER_LEVEL) + 1;
}
function xpToNext(xp: number): number {
  return XP_PER_LEVEL - (xp % XP_PER_LEVEL);
}
```

**Initial assignment (first time):**

When no localStorage data exists, pick 3 random missions from pool as initial active missions. Use a seeded shuffle to ensure variety.

### 6. useProgressSync.ts changes

Add infinite missions data to the sync payload for registered users:

In the subscribe callback that debounces writes, also include:

```typescript
const infData = localStorage.getItem("supermel_infinite_missions");
const parsedInf = infData ? JSON.parse(infData) : null;
if (parsedInf) {
  putProgress(token, {
    totalCoins: current.totalCoins,
    data: {
      infiniteMissions: parsedInf,
    },
  });
} else {
  putProgress(token, { totalCoins: current.totalCoins });
}
```

Also, on mount (load from backend), merge `data.infiniteMissions` into localStorage if backend has newer data.

### 7. Mission completion signaling for MissionToast (T05)

When a mission completes mid-run, the hook needs to signal the toast system. Two approaches:

**Option A (recommended):** Export a Zustand store or a simple ref that T05's MissionToast reads:
```typescript
export const missionCompletionSignal = { current: null as Mission | null };
```

**Option B:** Use gameEventBus to emit a custom `mission_completed` event that MissionToast subscribes to. This is cleaner but requires adding the event type.

Go with Option B -- add `mission_completed: { mission: Mission; reward: number }` to `GameEvents` in GameEventBus.

## Testing

### Manual Tests
1. Start infinite mode fresh (clear `supermel_infinite_missions` from localStorage) -- 3 random missions should appear in bottom-left HUD
2. Collect coins -- "Colete 20 moedas" progress bar should fill
3. Complete a mission -- toast should appear (T05 dependency), coins should be awarded, new mission should rotate in
4. Die and restart -- completed missions should remain completed; new active set loaded
5. Check Mel level in menu -- should show "Mel Lv.1" initially, increase after completing missions
6. Log in as registered user -- verify progress syncs to backend (`/api/progress` includes `data.infiniteMissions`)

### Edge Cases
- All 10 missions completed -- pool should wrap/recycle (missions can reappear)
- localStorage corrupted -- should fallback to fresh state
- Playing level mode -- infinite missions should NOT track or display
- Multiple missions completing on same event -- all should be processed
- Coin reward should add to totalCoins (persistent) not just session coins
