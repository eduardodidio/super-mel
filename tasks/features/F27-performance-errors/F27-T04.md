# Task F27-T04 — React Re-render & State Optimization

**Feature:** F27
**Wave:** 1
**Type:** frontend
**Depends on:** F27-T01
**Status:** planned

## User Story

As a player, I want the game to run without unnecessary React re-renders, so that the UI and game loop don't compete for CPU time.

## Objective

Reduce React re-render frequency in the game loop by eliminating per-frame setState calls and optimizing callback dependencies.

## Dev Notes

### Problem 1: Per-frame setState in GameScene3D

**GameScene3D.tsx** — `handlePositionUpdate` (line 27-36):
- Called every frame from Mel's `onPositionUpdate`
- Calls `setPlayerPos({ x, y })` — triggers React re-render of GameScene3D
- This re-renders: ProjectileManager, ChunkRenderer, BackgroundDecor — EVERY FRAME
- **Fix:** Use `useRef` for playerPos instead of `useState`:
  ```ts
  const playerPosRef = useRef({ x: 2, y: 5 });
  ```
  - Pass `playerPosRef.current.x` and `.y` to children, OR
  - Better: pass the ref itself and let children read from it in their useFrame
  - ProjectileManager, ChunkRenderer, BackgroundDecor should read position from a ref, not a re-render prop
  - This eliminates 60 React re-renders per second

**Similarly** `setFacingRight` (line 33) — triggers re-render per frame when moving:
- **Fix:** Use ref instead of state

### Problem 2: Callback Dependencies

**GameScene3D.tsx** — `handleHeartCollected` (line 47-50):
- `useCallback` with `[lives, setLives]` dep — recreated whenever `lives` changes
- This causes ChunkRenderer to get a new callback prop -> re-render
- **Fix:** Use the Zustand setter directly which doesn't need the current value:
  ```ts
  const handleHeartCollected = useCallback(() => {
    useGameState.getState().setLives(Math.min(useGameState.getState().lives + 1, 3));
  }, []);
  ```
  - Or simpler: define a `healLife` action in the store that handles the max-3 logic

### Problem 3: ChunkRenderer setChunks in useFrame

**ChunkRenderer.tsx** — `setChunks()` inside useFrame (lines 28-47):
- Even with the 200ms throttle, calling `setChunks()` triggers a full re-render of all Block/Heart/Coin components
- Comparing `changed` flag helps, but the intermediate arrays and React reconciliation are still expensive
- **Fix:**
  a. Use `useRef` for chunks storage instead of `useState`
  b. Use a `forceUpdate` counter (useState<number>) incremented only when chunks actually change
  c. This way, adding a chunk triggers 1 re-render, not continuous re-renders while player is in the same area

### Problem 4: BackgroundDecor re-renders

- BackgroundDecor receives `playerX` as a prop -> re-renders every time position changes
- **Fix:** Accept a ref instead, read in useFrame
