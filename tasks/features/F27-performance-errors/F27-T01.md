## User Story

As a developer, I want a comprehensive audit of console errors and performance bottlenecks, so that I know exactly what to fix and in what priority.

## Objective

Run the game, catalog ALL console errors/warnings, profile rendering performance with browser DevTools, and produce a prioritized fix list. This task is research-only (no code changes).

## Dev Notes

### Known Likely Issues (based on code review):

**1. Sprite Loading Warnings (SpriteAnimator.ts)**
- `loadSprites()` logs `[SpriteAnimator] Sprite "X" not found, will use fallback` for every missing sprite file
- `loadTexture()` error callback logs `[SpriteAnimator] Failed to load sprite "X", using fallback`
- These fire for EVERY animation frame name that doesn't have a matching .png file in `/sprites/mel/`
- Missing sprites likely: `walk_right`, `walk_right_b`, `run_right`, `run_right_b`, `jump_rise`, `jump_air`, `jump_fall`, `jump_land`, `attack_prep`, `attack_1`, `attack_2`, `attack_end`, `hurt_light`, `hurt_medium`, `hurt_heavy`, `death`, `sit`, `lie_down`
- Each missing sprite = 1 console.warn per load + potential 404 network error

**2. Deprecated Function Warnings (SpriteAnimator.ts)**
- `loadSpritesheet()` and `updateSpriteUV()` log deprecation warnings
- If anything still calls these, they spam every frame

**3. Block/Coin Rendering Overhead**
- Every `Coin` has a `<pointLight>` — N coins * 1 light each = expensive
- Every `Block` with type "lava" has a `<pointLight>` — same issue
- `BlockParticles` creates 8 mesh children with `new THREE.Vector3()` per particle per frame via `.clone().multiplyScalar()`
- `ChunkRenderer` uses `.flatMap()` + `.filter()` + `.map()` on every React render — creates intermediate arrays

**4. Physics Overhead**
- `world.castRay()` called every frame in Mel.tsx — generally OK but should verify no excessive collider count
- Each Block is a separate RigidBody (type="fixed") — could be many colliders

**5. React Re-render Pressure**
- `GameScene3D` creates new callbacks with `useCallback` but deps change (e.g., `lives` in `handleHeartCollected`)
- `ChunkRenderer` calls `setChunks()` inside `useFrame` which triggers React re-render of ALL chunk children
- `setPlayerPos()` called every frame in GameScene3D -> re-renders ProjectileManager + ChunkRenderer + BackgroundDecor

**6. Three.js Resource Disposal**
- Textures, geometries, and materials may not be disposed when chunks unload
- BlockParticles creates geometries that are never disposed

### Audit Procedure:
1. Run game via `pnpm dev` in the frontend package
2. Open Chrome DevTools Console — catalog all errors/warnings
3. Open Performance tab — record 30s of gameplay, look for:
   - Long frames (>16ms)
   - Excessive GC pauses
   - Layout thrashing
4. Open Memory tab — take heap snapshot, look for:
   - Growing object counts (Three.js geometries, materials)
   - Detached DOM nodes
5. Check Network tab for 404s on sprite files
6. Use R3F `<Stats />` component or `useFrame` timing to measure frame time

### Output:
Create `tasks/features/F27-performance-errors/audit-report.md` with:
- List of all console errors/warnings (with counts)
- Performance profile summary (avg frame time, worst frames, GC frequency)
- Prioritized fix list (P0=critical, P1=high, P2=medium)
