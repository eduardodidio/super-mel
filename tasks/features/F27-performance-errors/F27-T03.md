# Task F27-T03 — Rendering Optimizations (Lights, Materials, Instancing)

**Feature:** F27
**Wave:** 1
**Type:** frontend
**Depends on:** F27-T01
**Status:** planned

## User Story

As a player, I want the game to run at a stable 60fps, so that gameplay feels smooth without stutters.

## Objective

Optimize the heaviest rendering bottlenecks: excessive point lights, per-block material creation, and chunk rendering overhead.

## Dev Notes

### Problem 1: Excessive PointLights

**Coin.tsx** — every Coin has a `<pointLight>` (line 57):
- 10-15 coins per chunk * 5-7 visible chunks = 50-100+ point lights
- Each point light = shadow map computation (even without shadows, it's a draw call)
- **Fix:** Remove individual coin pointLights. Add a single ambient glow via emissive material (already has `emissive="#FFA500"` + `emissiveIntensity={0.4}`). The emissive alone gives adequate glow without the light overhead.

**Block.tsx** — lava blocks have `<pointLight>` (line 51):
- Fewer lava blocks, but still adds up
- **Fix:** Same approach — increase lava emissive intensity, remove pointLight. Or keep but only for max 3 nearest lava blocks (LOD).
- Simpler: just remove pointLight from lava, increase emissiveIntensity on lava material.

### Problem 2: Material Creation

**BlockTextures3D.ts** — check if `getBlockMaterials()` creates new materials each call or caches them. If it creates new ones per block, that's a major leak.
- **Fix:** Ensure materials are cached/shared. All blocks of same type should share the same material instance.

### Problem 3: ChunkRenderer Array Overhead

**ChunkRenderer.tsx** — the render function (lines 67-98) does:
```tsx
{Array.from(chunks.values()).flatMap((chunk) => [
  ...chunk.blocks.filter(...).map(...),
  ...chunk.hearts.filter(...).map(...),
  ...chunk.coins.filter(...).map(...)
])}
```
- This creates multiple intermediate arrays every render cycle
- Plus `.includes()` in useFrame (line 41) is O(n) per chunk
- **Fix:**
  a. Use `useMemo` to memoize the rendered elements, only recalculating when `chunks` state changes
  b. Replace `visibleIndices.includes(idx)` with a `Set` for O(1) lookup
  c. Consider moving destroyed/collected checks into a ref-based approach to avoid re-renders

### Problem 4: BlockParticles GC Pressure

**Block.tsx** — `BlockParticles` (line 89):
- `p.vel.clone().multiplyScalar(delta)` creates a new Vector3 every frame per particle
- 8 particles * N destroyed blocks = many allocations
- **Fix:** Use a temp vector: `const _tmpVec = new THREE.Vector3()` outside, then `_tmpVec.copy(p.vel).multiplyScalar(delta)` — zero allocations.

### Problem 5: Canvas Shadow Configuration

**Game3D.tsx** — `<Canvas shadows ...>`:
- Shadow mapping is expensive. Verify if shadows are actually visible/needed for this 2.5D sprite game
- If shadows aren't visually important: disable with `shadows={false}`
- If needed: use `shadow-mapSize={[512, 512]}` instead of default 1024 to halve shadow cost
