# Task F36-T04 -- Service Worker Registration in main.tsx

**Feature:** F36
**Wave:** 1
**Type:** frontend (React entry point)
**Depends on:** T02 (sw.js exists), T03 (index.html has manifest link)
**Status:** planned

## User Story

As a player, I want the service worker to be automatically registered when I visit the game so that caching and server wake-up happen transparently without any manual action.

## Objective

Add service worker registration logic to `packages/frontend/src/main.tsx`. The registration should:
- Only register in production (not during Vite dev server)
- Handle registration errors gracefully (log, don't crash)
- Log registration success for debugging

## Dev Notes

### Modify `packages/frontend/src/main.tsx`

Add SW registration after the React render call. The current file is minimal:

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { App } from "./App";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);

// --- ADD BELOW ---

// Register service worker for PWA support
if ("serviceWorker" in navigator) {
  window.addEventListener("load", () => {
    navigator.serviceWorker
      .register("/sw.js")
      .then((registration) => {
        console.log("[SW] Registered:", registration.scope);
      })
      .catch((error) => {
        console.warn("[SW] Registration failed:", error);
      });
  });
}
```

### Key Design Points

1. **Feature detection**: `"serviceWorker" in navigator` ensures the code doesn't run in browsers that don't support SW (old browsers, some WebViews). This is a no-op gracefully.

2. **`window.addEventListener("load")`**: Delays SW registration until after the page finishes loading. This prevents the SW install (which fetches precache assets) from competing with the main page load for bandwidth.

3. **No production-only guard**: Unlike apps using `vite-plugin-pwa`, our hand-written SW at `/sw.js` in `public/` is served by Vite dev server too. However, in development the SW won't cause issues because:
   - Vite dev server serves files from `public/` at the root
   - The SW will register and cache, but Vite's HMR uses WebSocket (not affected by SW)
   - If dev friction occurs, the developer can add a `import.meta.env.PROD` guard:
     ```tsx
     if (import.meta.env.PROD && "serviceWorker" in navigator) { ... }
     ```
   - Recommendation: start WITHOUT the PROD guard. If dev friction appears, add it.

4. **No update handling for MVP**: For the initial release, we don't need "new version available" prompts. The SW uses `skipWaiting()` so updates apply immediately. This can be enhanced in a future feature if needed.

5. **Console logging**: The `[SW]` prefix makes it easy to filter SW logs in DevTools. These logs help debug installation issues, especially on mobile.

## Testing

- Build the frontend (`pnpm build`) and serve with `pnpm preview`
- Open in browser, check DevTools > Application > Service Workers
- SW should show as "activated and is running"
- Console should show `[SW] Registered: http://localhost:4173/`
- In dev mode (`pnpm dev`), SW should also register (or be guarded by PROD check)

## Test Scenarios

- **Happy path:** Open page -- console shows `[SW] Registered: ...`
- **Happy path:** DevTools > Application > Service Workers shows active SW
- **Error path:** Rename sw.js temporarily -- console shows `[SW] Registration failed: ...` (no crash)
- **Edge case:** Browser without SW support (e.g., very old) -- no error, code is skipped
- **Regression:** React app renders correctly (StrictMode, root mount)
- **Regression:** HMR still works in dev mode
