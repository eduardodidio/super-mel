# Task F36-T02 -- Service Worker (Cache Strategy + Server Wake-Up)

**Feature:** F36
**Wave:** 0
**Type:** frontend (static asset, vanilla JS)
**Depends on:** (none)
**Status:** planned

## User Story

As a mobile player opening the app from my home screen, I want the game to start waking up the server immediately while showing me a loading experience, so that by the time I press JOGAR the backend is ready.

## Objective

Create a hand-written service worker (`sw.js`) that:
1. Caches essential static assets for faster loads
2. Pings the backend health endpoint on activation to wake the Render free-tier server
3. Uses network-first strategy for HTML (always fresh) and cache-first for static assets (sprites, JS, CSS)

## Dev Notes

### Create `packages/frontend/public/sw.js`

```js
// Super Mel Service Worker
// Strategy: network-first for HTML, cache-first for static assets
// Special: wake-up ping to Render backend on activation

const CACHE_NAME = "super-mel-v1";
const API_HEALTH_URL = "/api/health";

// Assets to pre-cache on install
const PRECACHE_ASSETS = [
  "/",
  "/manifest.json"
  // JS chunks and sprites are cached on first fetch (runtime caching)
];

// File extensions that get cache-first treatment
const CACHEABLE_EXTENSIONS = [
  ".js", ".css", ".png", ".jpg", ".jpeg", ".webp",
  ".json", ".mp4", ".woff", ".woff2", ".svg"
];

self.addEventListener("install", (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => {
      return cache.addAll(PRECACHE_ASSETS);
    })
  );
  // Activate immediately, don't wait for old SW to stop
  self.skipWaiting();
});

self.addEventListener("activate", (event) => {
  event.waitUntil(
    Promise.all([
      // Clean old caches
      caches.keys().then((keys) =>
        Promise.all(
          keys
            .filter((key) => key !== CACHE_NAME)
            .map((key) => caches.delete(key))
        )
      ),
      // Wake up the Render backend (fire-and-forget)
      fetch(API_HEALTH_URL, { method: "HEAD" }).catch(() => {
        // Silently ignore -- server may not be reachable yet
      }),
      // Take control of all clients immediately
      self.clients.claim()
    ])
  );
});

self.addEventListener("fetch", (event) => {
  const url = new URL(event.request.url);

  // Skip non-GET requests
  if (event.request.method !== "GET") return;

  // Skip API requests (except health ping) -- let them go to network
  if (url.pathname.startsWith("/api")) return;

  // For navigation requests (HTML): network-first with cache fallback
  if (event.request.mode === "navigate") {
    event.respondWith(
      fetch(event.request)
        .then((response) => {
          // Cache the fresh HTML
          const clone = response.clone();
          caches.open(CACHE_NAME).then((cache) => cache.put(event.request, clone));
          return response;
        })
        .catch(() => {
          // Offline: serve cached HTML
          return caches.match(event.request).then(
            (cached) => cached || caches.match("/")
          );
        })
    );

    // Also fire a wake-up ping to the backend (parallel, non-blocking)
    fetch(API_HEALTH_URL, { method: "HEAD" }).catch(() => {});
    return;
  }

  // For static assets: cache-first with network fallback
  const isCacheable = CACHEABLE_EXTENSIONS.some((ext) =>
    url.pathname.endsWith(ext)
  );

  if (isCacheable) {
    event.respondWith(
      caches.match(event.request).then((cached) => {
        if (cached) return cached;
        return fetch(event.request).then((response) => {
          // Cache new static assets for next time
          if (response.ok) {
            const clone = response.clone();
            caches.open(CACHE_NAME).then((cache) =>
              cache.put(event.request, clone)
            );
          }
          return response;
        });
      })
    );
    return;
  }

  // Everything else: just fetch normally
});
```

### Key Design Points

1. **`skipWaiting()` + `clients.claim()`**: Ensures the new SW takes effect immediately without requiring the user to close all tabs. Important for a game where users may have only one tab open.

2. **Wake-up ping on navigate**: Every time the user opens the app (navigation request), the SW fires a HEAD request to `/api/health` in parallel. This is fire-and-forget -- it doesn't block page load. The Render backend will start spinning up from sleep.

3. **Cache versioning via `CACHE_NAME`**: When updating the SW, bump `super-mel-v1` to `v2` etc. The `activate` handler cleans old caches.

4. **No API caching**: All `/api/*` requests pass through to the network. We never want to serve stale game data (scores, levels, auth).

5. **Runtime caching for sprites/chunks**: Rather than listing every sprite and JS chunk in PRECACHE_ASSETS (which would be brittle), we cache them on first access. After the first full load, subsequent loads are fast.

### Production API URL Consideration

In production, `/api/health` is routed to `super-mel-api.onrender.com`. The SW's fetch to `/api/health` will follow the same routing as the main app. If the static site on Render does NOT proxy `/api`, the developer should update the health URL to the full backend URL:

```js
const API_HEALTH_URL = "https://super-mel-api.onrender.com/api/health";
```

The developer should check whether `/api/health` resolves in production and adjust accordingly. If it does not resolve (404), use the absolute URL above. Note: cross-origin fetch to a different Render service is allowed because the backend has CORS configured for `super-mel.onrender.com`.

- Verify API calls (`/api/scores`, `/api/levels`) are NOT cached (return network error when offline)

## Test Scenarios

- **Happy path:** Load page, check DevTools > Service Workers -- SW is active
- **Happy path:** Load page, go offline, reload -- cached HTML and assets load
- **Wake-up:** Load page, check Network tab -- HEAD `/api/health` fires alongside HTML fetch
- **Edge case:** Multiple tabs open -- SW update activates in all tabs immediately (skipWaiting)
- **Regression:** Gameplay works identically with SW registered (physics, audio, controls)
- **Regression:** API calls (leaderboard, level save) work normally (not cached)
