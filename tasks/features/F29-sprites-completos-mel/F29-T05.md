# F29-T05 — Ajustar Timing e FPS das Animacoes

**Wave:** 2
**Type:** frontend
**Depends on:** F29-T03
**Status:** done

## User Story

As a player, I want animation timing that feels responsive and smooth, so that the character responds to my inputs fluidly.

## Objective

Ajustar FPS e timing de todas as animacoes no SpriteAnimator para que os novos frames intermediarios resultam em movimentacao fluida. Fine-tuning de velocidades de transicao.

### Ajustes de timing de transicao (AnimationStateMachine.ts)

- `jump_land` duration: 0.2s → 0.15s (landing mais snappy)
- `attack_prep` duration: 0.17s → 0.12s (ataque mais responsivo)
- Coyote time: manter 0.1s (ja bom)

### Arquivos a modificar

   - Atualizar `fps` em cada animacao no ANIMATIONS object
   - Atualizar `frames` arrays com novos sprites (de T04)

2. **`packages/frontend/src/game/systems/AnimationStateMachine.ts`**
   - Ajustar duracao de one-shot states se necessario

### Processo de fine-tuning
1. Aplicar valores da tabela acima
2. Testar jogando
3. Iterar: se walk parecer lento, aumentar FPS; se run parecer borrado, diminuir
4. O objetivo e que SINTA responsivo e fluido

## Acceptance Criteria

- [ ] FPS de cada animacao ajustado conforme tabela (ou melhor apos tuning)
- [ ] Walk animation cicla suavemente a ~8 FPS com 4 frames
- [ ] Run animation cicla suavemente a ~12 FPS com 4 frames
- [ ] Idle breathing loop suave a ~4 FPS
- [ ] Transicoes entre estados sao responsivas (sem delay perceptivel)
- [ ] Ataque se sente "snappy" (prep → hit rapido)
- [ ] Landing e rapido e nao "prende" o jogador

## Testing

Validacao subjetiva: jogar e avaliar se movimentacao sente fluida.

## Test Scenarios

- Happy path: andar pra esquerda e direita → ciclo fluido
- Happy path: correr → mais rapido que walk, frames legiveis
- Happy path: ficar parada → breathing sutil
- Edge case: mudar de walk → run rapidamente → transicao suave
- Edge case: pular e cair → landing nao trava o jogador
- Regressao: attack timing continua responsivo
