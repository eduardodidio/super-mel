# F62-T04: Fix Transparent/Invisible Items in Scene

**Wave:** 0
**Priority:** Medium
**Depends on:** none

## User Story

As a player, I want all items and entities in the game world to be clearly visible, so that I can interact with them and the world feels complete.

## Problem Analysis

The user reports that some items in the scene are rendering as transparent/invisible. This could be caused by:

1. **Failed texture loading**: If a sprite/texture fails to load, the material may render as fully transparent or invisible
2. **Depth sorting with transparent materials**: Three.js sorts transparent objects by distance; items behind glass/leaf/water blocks may not render correctly
3. **Material opacity not set correctly**: Some entities may have `transparent: true` without proper opacity
4. **Stale or disposed textures**: Texture cache may return disposed textures after scene transitions

### Entities to Audit

| Entity | Material Type | Transparency | Potential Issue |
|--------|--------------|-------------|----------------|
| Coin | Sprite texture + `transparent` | Yes | Texture load failure → invisible |
| Heart | Color meshes + emissive | No | Should be fine |
| Bone | Color mesh + emissive | No | Should be fine |
| Sign | Color meshes | No | Should be fine |
| DroppedCoin | Sprite texture + `transparent` | Yes | Texture load failure → invisible |
| Spring | Color meshes | No | Should be fine |
| MovingPlatform | Color mesh | No | Should be fine |
| Spikes | Color mesh | No | Should be fine |
| Goal | Color mesh + emissive | No | Should be fine |

| Block (glass) | `transparent: true, opacity: 0.35` | Yes | May appear invisible |
| Block (leaf) | `transparent: true, opacity: 0.9` | Yes | Nearly opaque, should be visible |
| Block (water) | `transparent: true, opacity: 0.5` | Yes | Semi-transparent, may look invisible |
| Projectile bark sprite | Dynamic texture assignment | Yes | Texture assigned in useFrame, not at init |

## Dev Notes

### Files to Audit and Fix

1. **`packages/frontend/src/game/entities/Coin.tsx`**
   - Check texture loading: if the coin sprite fails to load, the material has `transparent: true` but no fallback color
   - Fix: Add a fallback color (e.g., gold `#FFD700`) when texture map is null
   - Ensure `depthWrite: false` for proper transparent rendering with other transparent objects

2. **`packages/frontend/src/game/entities/DroppedCoin.tsx`**
   - Same texture loading concern as Coin
   - Add fallback color for failed texture loads

3. **`packages/frontend/src/game/entities/Projectile.tsx`** (bark sprite, lines ~247-256)
   - Material created WITHOUT initial texture map — texture assigned dynamically in useFrame
   - If texture never loads, material stays invisible
   - Fix: Set a fallback emissive color on the material at creation time

4. **`packages/frontend/src/game/systems/BlockTextures3D.ts`**
   - Glass blocks (opacity 0.35) may be nearly invisible in dark themes
   - Consider increasing minimum opacity or adding subtle emissive glow
   - Water blocks (opacity 0.5) — verify they're visible against dark backgrounds

5. **Depth sorting**: For scenes with many transparent objects (glass blocks + coins + water), Three.js default sorting may cause flickering or invisibility. Consider:
   - Setting `renderOrder` on critical transparent objects (coins, hearts)
   - Using `depthWrite: false` on transparent materials
   - Using `alphaTest` instead of `transparent` where possible (e.g., sprite sheets with hard edges)
