# F62-T02: Fix Mel Ground Stuck When Changing Direction

**Wave:** 0
**Priority:** HIGH
**Depends on:** none

## User Story

As a player, I want Mel to move smoothly when I change direction (walk left then right), without getting stuck or freezing on the ground, so that the gameplay feels responsive and fun.

## Problem Analysis

Mel gets "stuck" (travada) when walking on ground and reversing direction. The player must press the opposite direction again to unstick her. Two compounding root causes:

### Root Cause 1: Ghost Collisions at Block Seams

Mel's collider is a `CuboidCollider args={[0.3, 0.45, 0.25]}` — a rectangular box. The ground is made of adjacent 1x1x1 cuboid blocks. When the box collider slides across the boundary between two adjacent blocks, the vertical edge of the next block acts as a tiny wall that catches the bottom corner of Mel's collider.

This is a classic "ghost collision" problem in physics engines with tiled box terrain.

### Root Cause 2: Sluggish Direction Reversal

The movement acceleration formula at `Mel.tsx:164`:
```typescript
newVelX = THREE.MathUtils.lerp(vel.x, targetVelX, MOVE_ACCEL * delta / (Math.abs(vel.x) + 1));
```

When `vel.x = 6` (full speed right) and `targetVelX = -6` (pressing left):
- Lerp factor = `25 * 0.016 / (6 + 1)` = `0.057`
- This is extremely slow — it takes many frames to reverse direction
- Combined with ghost collisions, the character appears to freeze

## Dev Notes

### Files to Modify

1. **`packages/frontend/src/game/entities/Mel.tsx`**
   - **Collider**: Replace `CuboidCollider` with a compound shape that has rounded bottom:
     - Option A (preferred): Use `CapsuleCollider` — `@react-three/rapier` exports this
     - Option B: Compound of `CuboidCollider` (body) + `BallCollider` (feet)
     - The capsule's rounded bottom will slide over block seams instead of catching
   - **Movement formula**: Fix the acceleration to handle direction reversal better:
     ```typescript
     // When changing direction (vel.x and targetVelX have opposite signs),
     // use a higher acceleration factor for responsive feel
     const changingDirection = (vel.x > 0.1 && targetVelX < 0) || (vel.x < -0.1 && targetVelX > 0);
     const accelFactor = changingDirection ? MOVE_ACCEL * 2 : MOVE_ACCEL;
     newVelX = THREE.MathUtils.lerp(vel.x, targetVelX, accelFactor * delta);
     ```
     Remove the `/ (Math.abs(vel.x) + 1)` divisor — it makes acceleration inversely proportional to speed, which feels unresponsive.
   - **Ground detection**: The threshold `Math.abs(vel.y) < 1` at line 148 may falsely report airborne when catching on seams. Consider relaxing to `Math.abs(vel.y) < 2` or removing the velocity check entirely (the raycast hit alone is sufficient for ground detection).

### Collider Change Detail

Current:
```tsx
<CuboidCollider args={[0.3, 0.45, 0.25]} />
```

Proposed (CapsuleCollider):
```tsx
<CapsuleCollider args={[0.25, 0.25]} />
```
- `args=[halfHeight, radius]` — total height = 2 * (halfHeight + radius) = 2 * (0.25 + 0.25) = 1.0 (slightly taller but rounded)
- Adjust values to match current collider dimensions: halfHeight=0.2, radius=0.25 gives height=0.9 (close to current 0.9)

After changing collider shape:
- Verify the ground raycast origin (`pos.y - 0.55`) still works — may need adjustment for capsule shape
- Verify sprite foot anchoring offset (`meshOffsetY`) still aligns
- Verify collision with blocks, enemies, and other entities still works

### Movement Feel Tuning

After fixing the formula, test with these values and adjust:
- Normal acceleration: `MOVE_ACCEL * delta` with MOVE_ACCEL=25
- Direction change acceleration: `MOVE_ACCEL * 2 * delta` (50 * 0.016 = 0.8 lerp factor — near instant reversal)
- The key is that direction reversal should feel SNAPPY (like Mario), not floaty

## Testing

2. **Walk across block seams**: Walk right for 10+ blocks continuously — Mel should never stutter or catch on block edges

4. **Jump test**: Jump should still work correctly (grounded detection)

6. **Double jump test**: Jump → double jump should still work
7. **Stomp bounce**: Jump on enemy → Mel should bounce up
8. **Spring bounce**: Hit a spring → Mel should bounce with correct force
9. **Crouch test**: Hold down while grounded — Mel should crouch with reduced speed
10. **Mobile controls**: Touch controls should still move Mel correctly
11. **No collision regression**: Mel should still collide with walls, not fall through floors, not clip into ceilings
