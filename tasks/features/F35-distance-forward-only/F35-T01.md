# Task F35-T01 — Score conta apenas deslocamento forward (maxX)

**Feature:** F35
**Wave:** 0
**Type:** frontend (game logic)
**Depends on:** (none)
**Status:** planned

## User Story

As a player, I want the distance/score counter to only increase when I move forward so that my score reflects actual progress and cannot be exploited by walking back and forth.

## Objective

Alterar `handlePositionUpdate` em `GameScene3D.tsx` para usar um `maxX` ref que rastreia a posicao mais avancada. Score so incrementa quando o jogador ultrapassa seu recorde de posicao X.

## Dev Notes

- Arquivo: `packages/frontend/src/game/scenes/GameScene3D.tsx`
- Funcao: `handlePositionUpdate` (linhas 51-61)

### Alteracoes exatas

**1. Adicionar ref `maxX` (apos linha 40):**
```diff
  const lastX = useRef(0);
+ const maxX = useRef(0);
```

**2. Reescrever logica de score em handlePositionUpdate (linhas 55-60):**
```diff
  const dx = x - lastX.current;
- if (Math.abs(dx) > 0.01) {
-   addScore(Math.abs(dx));
-   facingRightRef.current = dx > 0;
- }
+ if (dx > 0.01) {
+   facingRightRef.current = true;
+ } else if (dx < -0.01) {
+   facingRightRef.current = false;
+ }
+ if (x > maxX.current) {
+   addScore(x - maxX.current);
+   maxX.current = x;
+ }
  lastX.current = x;
```

### Por que funciona

1. `maxX.current` comeca em 0 (posicao inicial da Mel e ~2, entao os primeiros metros ja contam)
2. Quando Mel anda pra frente alem do maxX, o delta `x - maxX.current` e adicionado ao score
3. Quando Mel volta e depois avanca novamente, so a parte NOVA (alem do maxX anterior) e contada
4. `lastX` continua servindo para calcular `dx` e determinar `facingRightRef`
5. Os refs sao reinicializados quando o componente remonta (novo jogo via resetGame muda scene, remontando GameScene3D)

### Risco: maxX initial value

O spawn default da Mel e `x=2` (vide `playerPosRef.current = { x: 2, y: 5 }`). Com `maxX = useRef(0)`, os primeiros 2 "metros" do spawn sao contados automaticamente no primeiro frame. Isso e aceitavel — o score inicia em ~2 que e desprezivel. Se necessario, pode-se inicializar `maxX` com o spawn X, mas isso adicionaria complexidade desnecessaria para uma feature de bug fix.
