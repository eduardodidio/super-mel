# Task F33-T02 — Mel.tsx: usar aspect ratio dinamico por frame

**Feature:** F33
**Wave:** 0
**Type:** frontend (entity)
**Depends on:** F33-T01 (assinatura: `getFrameAspectRatio(animName, elapsed): number`)
**Status:** planned

## User Story

As a player, I want Mel's sprite to appear with correct proportions in all
animation states, so that the character looks natural -- especially when idle,
where the current fixed ratio stretches the sprite horizontally by ~82%.

## Objective

Modificar `Mel.tsx` para remover o aspect ratio fixo e usar o ratio dinamico
por frame fornecido por `getFrameAspectRatio()` do SpriteAnimator.

### 3. Modificar o useFrame — calcular scale dinamico (apos linha 236)

Dentro do bloco `if (spritesLoaded.current)` (linhas 235-242), apos atualizar
a textura, calcular e aplicar o aspect ratio:

```ts
// --- Sprite texture update ---
if (spritesLoaded.current) {
  const texture = getFrame(animName, stateMachine.current.stateTime);
  const mat = (spriteRef.current as THREE.Mesh).material as THREE.MeshStandardMaterial;
  if (mat.map !== texture) {
    mat.map = texture;
    mat.needsUpdate = true;
  }

  // --- Dynamic aspect ratio per frame ---
  const ratio = getFrameAspectRatio(animName, stateMachine.current.stateTime);
  const frameWidth = SPRITE_HEIGHT * ratio;
  spriteRef.current.scale.set(
    facingRight.current ? frameWidth : -frameWidth,
    SPRITE_HEIGHT,
    1
  );
}
```

### 4. Remover a linha fixa de scale.x do flip (linha 247)

A linha que atualmente faz o flip usando `SPRITE_WIDTH` fixa:

```diff
- // --- Flip sprite based on facing ---
- const facing = stateMachine.current.facing;
- facingRight.current = facing === "right";
- spriteRef.current.scale.x = facingRight.current ? SPRITE_WIDTH : -SPRITE_WIDTH;
```

Deve ser substituida apenas pela atualizacao do facing (o scale ja e aplicado
no bloco acima):

```ts
// --- Update facing direction ---
const facing = stateMachine.current.facing;
facingRight.current = facing === "right";
```

**Nota:** Se `spritesLoaded.current` for false (primeiro frame antes do
carregamento), o scale do JSX sera usado. Nesse caso o sprite nao e visivel
mesmo, pois nao ha textura carregada.

### 5. Atualizar o scale inicial no JSX (linha 278)

```diff
- <mesh ref={spriteRef} position={[0, 0.3, 0]} scale={[SPRITE_WIDTH, SPRITE_HEIGHT, 1]}>
+ <mesh ref={spriteRef} position={[0, 0.3, 0]} scale={[SPRITE_HEIGHT, SPRITE_HEIGHT, 1]}>
```

Usar `SPRITE_HEIGHT` como scale.x inicial (ratio 1:1). No primeiro frame do
useFrame, o scale sera corrigido para o ratio real do idle sprite.

### Design Decisions

- **SPRITE_HEIGHT fixa, width dinamica**: Manter a altura constante garante que
  a Mel nao muda de tamanho vertical entre animacoes. Apenas a largura se
  ajusta ao conteudo real do sprite.
- **scale.set() em vez de scale.x separado**: Combinar o flip e o ratio
  dinamico numa unica chamada `scale.set()` evita o problema de ter dois
  pontos do codigo competindo para setar scale.x.
- **Sem smoothing/lerp**: Transicoes de ratio acontecem frame-a-frame. Na
  pratica, a diferenca de ratio entre frames adjacentes dentro de uma animacao
  e pequena (ex: walk_right 1.189 -> walk_right_b 1.058). Transicoes entre
  animacoes diferentes (ex: idle 0.732 -> walk 1.189) sao instantaneas, o que
  e esperado para sprite-based animation. Se causar jitter, adicionar lerp
  e trivial (mas provavelmente desnecessario).
- **Fallback antes do load**: O scale inicial de `[SPRITE_HEIGHT, SPRITE_HEIGHT, 1]`
  (quadrado) e usado apenas no frame antes do carregamento completar. Nenhum
  sprite e visivel nesse momento, entao nao importa.
