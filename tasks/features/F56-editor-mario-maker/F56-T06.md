# F56-T06: Editor State Preservation (sessionStorage)

**Wave:** 2
**Type:** frontend
**Depends on:** F56-T03, F56-T04, F56-T05
**Status:** planned

## User Story

As a level creator, I want my entire editor state to be preserved when I test
my level, so that when I return from testing, everything is exactly where I
left it -- blocks, tool selection, camera position, level dimensions, and all.

## Objective

Serialize the full editor state to sessionStorage before entering test mode.
On editor mount (return from test), detect and restore the saved state. Clear
the saved state after restoration.

## Dev Notes

### State shape to serialize

### SessionStorage key

```typescript
const EDITOR_STATE_KEY = "supermel_editor_state";
```

### Save before test

Modify `handleTest` and `handleTestFromCursor` in EditorWrapper to save state
before transitioning to test mode.

Extract a shared save function:

```typescript
const saveEditorState = useCallback(() => {
  const state: EditorSavedState = {
    blocks,
    entities,
    selectedTool,
    enemySubtype,
    currentZ,
    spawnPoint,
    levelName,
    customAssets,
    selectedCustomAssetId,
    itemBlockContent,
    signText,
    cameraPos,
    levelWidth,
    levelHeight,
    levelCleared,
    levelCode,
    savedLevelId,
    dataChangedSinceClear,
  };
  sessionStorage.setItem(EDITOR_STATE_KEY, JSON.stringify(state));
}, [
  blocks, entities, selectedTool, enemySubtype, currentZ, spawnPoint,
  levelName, customAssets, selectedCustomAssetId, itemBlockContent, signText,
  cameraPos, levelWidth, levelHeight, levelCleared, levelCode, savedLevelId,
  dataChangedSinceClear,
]);
```

Call `saveEditorState()` at the top of both `handleTest` and
`handleTestFromCursor` before calling `startLevel` or `setScene("playing")`.

### Restore on mount

Add a `useEffect` that runs once on mount (or when scene transitions to
"editor") to check for and restore saved state:

```typescript
useEffect(() => {
  if (scene !== "editor") return;

  const saved = sessionStorage.getItem(EDITOR_STATE_KEY);
  if (!saved) return;

  try {
    const state: EditorSavedState = JSON.parse(saved);
    setBlocks(state.blocks);
    setEntities(state.entities);
    setSelectedTool(state.selectedTool);
    setEnemySubtype(state.enemySubtype);
    setCurrentZ(state.currentZ);
    setSpawnPoint(state.spawnPoint);
    setLevelName(state.levelName);
    setCustomAssets(state.customAssets);
    setSelectedCustomAssetId(state.selectedCustomAssetId);
    setItemBlockContent(state.itemBlockContent);
    setSignText(state.signText);
    setCameraPos(state.cameraPos);
    setLevelWidth(state.levelWidth);
    setLevelHeight(state.levelHeight);
    // F46 state
    setLevelCleared(state.levelCleared);
    setLevelCode(state.levelCode);
    setSavedLevelId(state.savedLevelId);
    setDataChangedSinceClear(state.dataChangedSinceClear);
  } catch {
    // Corrupted state -- ignore
  }

  // Clear after restore
  sessionStorage.removeItem(EDITOR_STATE_KEY);
}, [scene]);
```

### Interaction with existing clear-check

The existing `supermel_editor_test_cleared` sessionStorage check (line 47-56)
runs in a separate `useEffect`. The restore effect should run BEFORE the
clear-check effect. Since both depend on `scene`, order matters.

Place the state restore effect ABOVE the clear-check effect in the component
body. React runs effects in declaration order, so the restore will execute first.

The clear-check sets `levelCleared = true`. The restore may set `levelCleared`
to whatever it was before test. These two effects need to compose correctly:

1. Restore runs first, setting all state from saved (including levelCleared).
2. Clear-check runs second. If the test was cleared, it sets `levelCleared = true`
   and `dataChangedSinceClear = false`, overriding the restored values.

This is the correct behavior: if the user clears the test, the cleared state
takes precedence over the pre-test state.

### State size consideration

Custom assets contain base64 data URIs that could be large. SessionStorage has
a ~5MB limit. Each custom asset is max 200KB (limited in ImageUploader), and
max 10 assets = ~2MB. Combined with block/entity data, this should stay within
limits. If it exceeds the limit, the `setItem` call will throw. Wrap it in
try/catch:

```typescript
try {
  sessionStorage.setItem(EDITOR_STATE_KEY, JSON.stringify(state));
} catch {
  console.warn("Editor state too large to save to sessionStorage");
}
```

### Clean up on non-test exits

When the user clicks "VOLTAR" (back to menu), do NOT save editor state. The
state preservation is only for the test cycle. Add cleanup:

```typescript
// In the onBack handler or at the start of EditorWrapper when scene changes away
useEffect(() => {
  return () => {
    // On unmount, don't leave stale state (only save is intentional before test)
  };
}, []);
```

Actually, the save is only called explicitly in handleTest/handleTestFromCursor,
so no cleanup is needed for the back button path. The sessionStorage entry will
only exist if the user entered test mode.

However, if the user refreshes the browser during test mode, the saved state
will persist in sessionStorage. On next editor open, it will be restored. This
is acceptable and even desirable (user doesn't lose work on browser refresh).

## Acceptance Criteria

- [ ] Editor state is serialized to sessionStorage before entering test mode
- [ ] On return from test, all editor state is restored (blocks, entities, tool, camera, dimensions)
- [ ] Selected tool and enemy subtype are restored
- [ ] Camera position is restored (user sees the same viewport they were editing)
- [ ] Level dimensions (width/height) are restored
- [ ] Custom assets are restored (base64 data preserved)
- [ ] Level name, sign text, item block content are restored
- [ ] F46 publish state (cleared, code, savedLevelId) is restored
- [ ] Clear-check override works: if test was cleared, levelCleared becomes true
- [ ] SessionStorage is cleaned up after successful restore
- [ ] Large state (many blocks + custom assets) does not crash (try/catch)
- [ ] "VOLTAR" does not save state (only test triggers save)
