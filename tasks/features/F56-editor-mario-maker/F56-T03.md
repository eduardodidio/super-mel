# F56-T03: Enemy Placement Logic in EditorWrapper + EditorScene3D

**Wave:** 1
**Type:** frontend
**Depends on:** F56-T01
**Status:** planned

## User Story

As a level creator, I want to click on the grid with an enemy tool selected and
have the enemy placed at that position, so that I can populate my level with
Aspirador, Pombo, and Abelha enemies that will appear during gameplay.

## Objective

Wire the enemy tool selection from T01 into the placement logic (EditorWrapper)
and the 3D visual rendering (EditorScene3D), so enemies are placed as entity
data, rendered as colored markers in the editor, and included in the exported
LevelDataV2.

### Handle enemy deduplication in EditorWrapper.handlePlaceEntity

File: `packages/frontend/src/game/scenes/EditorWrapper.tsx`

The `handlePlaceEntity` callback (line 116-155) has a generic dedup path at
line 148-152 that prevents duplicate entities of the same type at the same
position. Enemy entities at the same position should be REPLACED (not blocked),
since the user might want to change the subtype.

Add a case before the generic path:
```typescript
// For enemy entities, replace at same position (allows subtype change)
if (entity.type === "enemy") {
  const filtered = prev.filter(
    (e) => !(e.type === "enemy" && e.x === entity.x && e.y === entity.y)
  );
  return [...filtered, entity];
}
```

### Enemy visual markers in EditorScene3D

The `ENTITY_VISUALS` record (line 65-74) already has an `enemy` entry:
```typescript
enemy: { color: "#FF0000", emissive: "#FF0000", shape: "box", scale: 0.5 },
```

The `EntityMarker` component (line 81-122) already renders it as a red box.

To show the subtype letter on the marker, enhance `EntityMarker` for enemy
entities. Add a text sprite or a simple indicator:

```tsx
function EntityMarker({ entity, currentZ }: EntityMarkerProps) {
  const visual = ENTITY_VISUALS[entity.type] ?? { ... };
  const subtypeLabel = entity.type === "enemy"
    ? (entity.props?.subtype as string)?.[0]?.toUpperCase() ?? "?"
    : null;

  return (
    <group position={[entity.x, entity.y, currentZ]}>
      {/* existing shape mesh */}
      {subtypeLabel && (
        <sprite position={[0, 0.5, 0]} scale={[0.3, 0.3, 0.3]}>
          <spriteMaterial color="#FFFFFF" />
        </sprite>
      )}
    </group>
  );
}
```

However, since Three.js sprites cannot show text directly, a simpler approach
is to vary the enemy marker color by subtype:

```typescript
const ENEMY_SUBTYPE_COLORS: Record<string, string> = {
  vacuum: "#FF2222",  // red
  pigeon: "#8888FF",  // blue-ish
  bee: "#FFDD00",     // yellow
};
```

Override the visual color in `EntityMarker` when the entity is an enemy:
```typescript
if (entity.type === "enemy") {
  const subColor = ENEMY_SUBTYPE_COLORS[(entity.props?.subtype as string) ?? "vacuum"];
  visual = { ...visual, color: subColor, emissive: subColor };
}
```

This makes each enemy subtype visually distinguishable in the editor without
needing text rendering.
