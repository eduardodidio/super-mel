# F56-T05: Level Resize (Width/Height Controls)

**Wave:** 1
**Type:** frontend
**Depends on:** F56-T02
**Status:** planned

## User Story

As a level creator, I want to set the width and height of my level from the
editor toolbar, so that I can design levels of varying sizes -- from small
challenge rooms to sprawling platformer stages.

## Objective

Add width and height number inputs to the editor top bar. When the user changes
dimensions, the grid and click plane resize dynamically. If shrinking would
remove existing blocks, show a confirmation dialog.

### Resize handlers

File: `packages/frontend/src/game/scenes/EditorWrapper.tsx`

```typescript
const handleResizeLevel = useCallback((newWidth: number, newHeight: number) => {
  // Clamp values
  const w = Math.max(MIN_WIDTH, Math.min(MAX_WIDTH, newWidth));
  const h = Math.max(MIN_HEIGHT, Math.min(MAX_HEIGHT, newHeight));

  // Check if any blocks or entities would be removed
  const blocksOutside = blocks.filter((b) => b.x >= w || b.y >= h);
  const entitiesOutside = entities.filter((e) => e.x >= w || e.y >= h);

  if (blocksOutside.length > 0 || entitiesOutside.length > 0) {
    const msg = `Redimensionar para ${w}x${h} vai remover ${blocksOutside.length} bloco(s) e ${entitiesOutside.length} entidade(s) fora dos limites. Continuar?`;
    if (!window.confirm(msg)) return;

    // Remove out-of-bounds blocks and entities
    setBlocks((prev) => prev.filter((b) => b.x < w && b.y < h));
    setEntities((prev) => prev.filter((e) => e.x < w && e.y < h));
    markDataChanged();
  }

  setLevelWidth(w);
  setLevelHeight(h);
}, [blocks, entities, markDataChanged]);
```

### Update buildLevelDataV2 to use explicit dimensions

File: `packages/frontend/src/game/scenes/EditorWrapper.tsx` (line 196-233)

Replace the dynamic dimension calculation with the explicit state:
```typescript
const buildLevelDataV2 = useCallback((): LevelDataV2 => {
  const width = levelWidth;
  const height = levelHeight;

  const grid: BlockCell[][] = [];
  for (let y = 0; y < height; y++) {
    const row: BlockCell[] = [];
    for (let x = 0; x < width; x++) {
      row.push({ type: "empty" as BlockType, x, y });
    }
    grid.push(row);
  }

  for (const b of blocks) {
    if (b.z === 0 && b.y >= 0 && b.y < height && b.x >= 0 && b.x < width) {
      grid[b.y][b.x] = { type: b.type, x: b.x, y: b.y };
    }
  }

  return {
    version: 2,
    grid,
    width,
    height,
    entities,
    theme,
    customAssets: customAssets.length > 0 ? customAssets : undefined,
  };
}, [blocks, entities, theme, customAssets, levelWidth, levelHeight]);
```

<div style={styles.dimensionControls}>

## Acceptance Criteria

- [ ] Width (W) and Height (H) number inputs visible in the top bar
- [ ] Width clamps to [16, 200], Height clamps to [8, 40]
- [ ] Changing width/height resizes the grid and click plane in real-time
- [ ] Shrinking shows confirmation dialog if blocks/entities would be removed
- [ ] Confirming removal actually deletes out-of-bounds blocks and entities
- [ ] Canceling the confirmation leaves dimensions unchanged
- [ ] buildLevelDataV2() uses the explicit width/height state
- [ ] Expanding dimensions does not lose existing blocks
- [ ] Camera clamp bounds update when dimensions change

## Testing

Manual testing:

1. **Default size:** Open editor -- W shows 32, H shows 16
2. **Expand width:** Change W to 64 -- grid expands to the right
3. **Expand height:** Change H to 24 -- grid expands upward
4. **Shrink safe:** Place blocks at x=10, y=5. Change W to 50 -- no warning, blocks preserved
5. **Shrink with warning:** Place blocks at x=30, y=10. Change W to 20 -- confirmation dialog appears showing count of blocks to remove
6. **Confirm shrink:** Click OK on dialog -- blocks beyond x=20 are removed
7. **Cancel shrink:** Click Cancel -- dimensions and blocks unchanged
8. **Min/max clamp:** Try W=5 -- clamps to 16. Try W=300 -- clamps to 200
9. **Camera bounds:** Expand to 100x30, pan camera -- camera stops at new bounds
10. **Save and reload:** Set 64x24, save level -- LevelDataV2 has width=64, height=24
