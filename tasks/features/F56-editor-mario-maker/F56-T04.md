# F56-T04: Test-from-Cursor (TESTAR DAQUI)

**Wave:** 1
**Type:** frontend
**Depends on:** F56-T02
**Status:** planned

## User Story

As a level creator, I want to click "TESTAR DAQUI" to start testing from the
position my cursor is hovering over, so that I can quickly test a specific
section of my level without having to play through from the beginning every time.

## Objective

Add a "TESTAR DAQUI" button next to the existing "TESTAR" button. When clicked,
it records the current hover position and starts the level test with Mel spawning
at that position instead of the level's spawn point.

### handleTestFromCursor in EditorWrapper

File: `packages/frontend/src/game/scenes/EditorWrapper.tsx`

```typescript
const handleTestFromCursor = useCallback(() => {
  if (!hoverPos) return;
  // Build level data with spawn override
  const data = buildLevelDataV2();
  // Override spawn point with cursor position
  // Find and replace the spawn entity
  const overriddenEntities = data.entities.map((e) =>
    e.type === "spawn" ? { ...e, x: hoverPos.x, y: hoverPos.y } : e
  );
  const overriddenData: LevelDataV2 = { ...data, entities: overriddenEntities };

  const hasGoal = overriddenData.entities.some((e) => e.type === "goal");
  if (hasGoal) {
    startLevel(`editor-test-${Date.now()}`, overriddenData);
  } else {
    sessionStorage.setItem("supermel_test_level", JSON.stringify(overriddenData));
    setScene("playing");
  }
}, [hoverPos, buildLevelDataV2, startLevel, setScene]);
```

Key design: the spawn point in the editor state is NOT modified. Only the
data passed to the test runner has the overridden spawn position. When the
user returns from test, the original spawn entity remains at its designed
position.

### Pass to EditorUI

In EditorWrapper return JSX, pass to `<EditorUI>`:
```tsx
hoverPos={hoverPos}
onTestFromCursor={handleTestFromCursor}
```

### No changes to test return flow

The existing return-from-test flow (LevelClearOverlay setting
`supermel_editor_test_cleared` and calling `setScene("editor")`) remains
unchanged. The test-from-cursor is a one-shot override -- it does not
affect the return behavior.

## Testing

Manual testing:

1. **Button visibility:** Open editor -- "DAQUI" button appears next to "TESTAR"
2. **Disabled state:** Move mouse off the grid -- "DAQUI" is grayed out and unclickable
3. **Enabled state:** Hover over grid at (10, 5) -- button activates, tooltip shows "(10, 5)"
4. **Test from cursor:** Hover at (10, 5), click "DAQUI" -- Mel spawns at (10, 5) in gameplay
5. **Normal test preserved:** Click "TESTAR" -- Mel spawns at the regular spawn point
6. **Spawn preserved:** Return from DAQUI test -- spawn entity is still at its original position
7. **Goal level:** Place a goal entity, hover at mid-level, click "DAQUI" -- level starts from cursor
8. **No-goal level:** Remove goal entity, click "DAQUI" -- infinite mode starts from cursor position
